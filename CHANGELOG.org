#+TITLE: Changelog

This file records completed changes.

* Unreleased

- =FIXED= One unreadable or unparsable source file no longer fails the whole rebuild or stops the watcher (#34). A file with a read error, invalid UTF-8 (never decoded lossily), an unstable snapshot or a parse error is skipped with ~warning: <path>: skipped: <cause>~ on stderr. ~rebuild~ commits all other files and exits with ~0~. The watcher and incremental reconciliation apply all other files and keep the skipped file's last good rows; the skipped file is not recorded as indexed, so it is retried. Documented in ~docs/cli.org~ and ~docs/design/incremental-indexing.org~.
- =FIXED= The watcher keeps running after transient batch failures (#28). SQLite ~BUSY~/~LOCKED~, a file that vanished or was interrupted while indexed, and an unstable file snapshot requeue the batch with exponential backoff (1 s, doubling, at most 30 s, no retry limit) and print each retry with its cause to stderr. All other failures, including an unavailable watch root, still stop the watcher; ~docs/cli.org~ lists which.
- =CHANGED= Benchmark code is no longer part of the default build (#29). The benchmark modules, all five ~orgfdb-*benchmark~ and ~orgfdb-presentation-payload-analysis~ binaries, the query trace hooks and rusqlite's ~trace~ feature now sit behind the new ~bench~ Cargo feature, so ~cargo install~ and ~cargo build~ build only ~orgfdb~. Build benchmarks with ~--features bench~ (for example ~cargo build --release --features bench --bin orgfdb-benchmark~). The ~presentation-cache-benchmark~ feature is now part of ~bench~. ~make ci~ still compiles everything with ~--all-features~.
- =ADDED= The generation journal is pruned (#40). Each commit that advances the generation deletes journal rows older than the newest ~index.journal_retention_generations~ generations (default ~1000~, minimum ~1~) in the same transaction, using range deletes on the generation keys, so a long-running watcher no longer grows the database without bound. ~orgfdb changes --since-generation~ older than ~oldest_available_generation~ reports ~history-unavailable~ and asks for a rebuild. No schema change.
- =CHANGED= Headings may be nested to any depth, as in Emacs Org. Files with a heading deeper than 100 levels no longer fail to parse; the limit (~MAX_HEADING_LEVEL~) is removed because the own scanners never recurse per level. The parser contract version is ~10~, so existing indexes reparse once.
- =CHANGED= The ~orgize~ dependency is removed (#105, stage 3 of #41). An own inline scanner that follows ~org-element~ of Emacs Org 9.6 now reads timestamps, inline code, verbatim, inline source and export snippets, and the visible text of titles. Results that change for the same file, all checked against Emacs 29.3 on tens of thousands of generated files: timestamps with an unknown repeater unit (~<2024-04-01 Mon +1x>~), a ~/2m~ deadline part, a one-digit hour or ~10:00--11:00~ are found, as are timestamps in footnote definitions, in the tag of a description-list item and behind an inline source block; code and verbatim can end before ~-~, ~"~, ~\~ and ~[~ and can span more than one line break, so the timestamps and links inside them are no longer found (Orgize missed both), and nothing is read inside table.el tables; a range ~[2024-04-01 Mon]--[2024-04-02 Tue 10:00]~ starts at midnight of its first date instead of 10:00; titles drop the markers of ~-*d*-~ and ~"*c*"~. The heading depth limit of 100 stays. The parser contract version is ~9~, so existing indexes reparse once.
- =CHANGED= The parser now builds headings, the heading tree, planning, property drawers, keywords, body text and the ranges that link scanning skips from its own line scanner instead of from Orgize (#103, stage 2 of #41). Orgize only reads timestamps and inline code in text and normalizes title markup, and it is fed a copy of the source with all structure blanked out, so heading depth no longer recurses in it and an empty ~#+begin_quote~ / ~#+end_quote~ block no longer trips its debug assertion. The heading depth limit of 100 stays and now counts only ~^\*+ ~ lines (a ~*~ line inside a block counts, ~**<TAB>x~ does not). In-buffer ~#+TODO~ resolution uses the scanner's keywords. The parser contract version is now ~8~, so existing databases reparse automatically on the next incremental or watch run. On a generated file with 10,000 headings (planning, property drawer, links) a release-build rebuild drops from about 1.43 s to about 1.11 s, and with 20,000 headings from about 2.71 s to about 2.27 s (median of 3 runs).
- =FIXED= Parser results now match Emacs Org on more points (#103). A planning line without a timestamp (~SCHEDULED: garbage~, ~CLOSED:~) is an empty planning element, so a property drawer after it counts and the line is no body text; a planning line holds every keyword in it (~SCHEDULED: <a> x DEADLINE: <b>~), a timestamp must follow its keyword, and ~<a>--<b>~ is one range timestamp; links in a planning line are no links. A property drawer with a row that is no property (comment, keyword, ~:a b: c~, ~:ID:x~) is a generic drawer without properties, and ~:a:b: c~ has the key ~a:b~. Blocks end at the first matching end line and names match in any case; drawer names may hold hyphens and non-ASCII letters; ~#+BEGIN: name~ to ~#+END:~ is a dynamic block whose begin and end lines are no keywords; affiliated keywords (~#+NAME:~, ~#+CAPTION:~) before an element are no document keywords; text in verse blocks keeps its timestamps and links. A priority cookie counts only at the start of the title or right after the TODO keyword (~* foo [#A] x~ has no priority), ~* TODO [#10] x~ drops the cookie from the title, a TODO keyword outside the file's ~#+TODO~ set is title text, markup in a title no longer breaks when the title holds ~_~, ~#+TITLE: t <2024-01-01>~ is a title, and headline tags and TODO state of CRLF files are read.
- =FIXED= Two more parser results now match Emacs Org (#80). Planning keywords are matched case-insensitively (~scheduled: <...>~ and ~Deadline: <...>~ are planning lines, not body timestamps; each timestamp is stored under its own keyword, where Emacs itself files lowercase ~scheduled:~ and ~deadline:~ under ~:closed~). A tag block with empty segments (~* T ::a::~, ~* T :a::b:~) is stripped from the title and only its non-empty tags are stored. Unknown link types, numeric priorities, ~file+sys:~ and ~file+emacs:~, links in property values and a bare ~* TODO~ stay intentional differences, documented in ~docs/design/parser-risks.org~. The parser contract version is now ~7~, so existing databases reparse automatically on the next incremental or watch run.
- =FIXED= Priority cookies and title separators now match Emacs Org (#98). ~[#a]~, ~[#1]~, ~[#!]~ and any other single character are priorities, and no space is needed after the cookie (~* [#A]x~ has priority A and title ~x~). Only spaces and tabs separate the TODO keyword, priority cookie and ~COMMENT~: a non-breaking space is title text (~* COMMENT<NBSP>z~ is not commented), and a tab directly after a TODO keyword means no TODO state, as in Org. Multi-digit cookies such as ~[#10]~ stay priorities, and a multi-letter cookie such as ~[#AB]~ is no longer a priority. The parser contract version is now ~6~, so existing databases reparse automatically on the next incremental or watch run.
- =CHANGED= Link resolution is much faster (#35, #36). A full pass now compares each computed resolution with the stored row, writes only rows that changed with one prepared statement, and reads the source and state rows in one query. Incremental applies re-resolve only links owned by created, modified or metadata-updated files, links without a target file or never resolved, and file or id links that point at an affected file or name an id it defines; applies with index invalidations still take the full pass. The DB writer also prepares each insert statement once per batch. On a 500-file, 25,000-heading corpus with about 50,000 links (release build), applying a single-file watcher batch drops from about 1.9 s to about 0.12 s (link resolution from about 1.8 s to about 0.035 s), and a full rebuild of a 20,000-heading file drops from about 4.6 s to about 3.3 s (median of 3 runs). The resulting ~links~ table is identical to before.
- =CHANGED= Applying an incremental change plan now revalidates unchanged files by modification time and size instead of reading and hashing every one of them before the write transaction; files that are created, modified or metadata-only keep the full content check. On a 500-file, 25,000-heading corpus with links (release build), applying a single-file watcher batch drops from about 1.95 s to about 1.6 s (median of 7 runs).
- =FIXED= Effective property values now match Emacs Org for empty and appended components (#84). Components are joined with one space and empty ones are kept (empty base plus ~:F+: x~ gives ~" x"~, ~v~ plus an empty append gives ~"v "~). In ~#+PROPERTY~ lines a later plain definition replaces the earlier one together with the appends before it (~P+ c~ then ~P b~ gives ~b~, not ~c b~). The parser contract version is now ~5~, so existing databases reparse automatically on the next incremental or watch run.

- =FIXED= Parser results now match Emacs Org on six points found by the oracle comparison (#79). An indented ~:PROPERTIES:~ drawer directly after a heading or its planning line, or at the start of a file, now stores its properties. Property values are trimmed of leading and trailing spaces and tabs. With a repeated key in one drawer the first plain definition supplies the effective value (~effective_properties~), and ~properties~ keeps every row; repeated ~#+PROPERTY~ keys keep last-wins. ~[[test.org::Heading]]~ and ~[[test.org::#1]]~ are ~fuzzy~ links with the whole target as ~path~ instead of type ~test.org~ (~[[file:test.org::Heading]]~ and ~[[./test.org::Heading]]~ are unchanged). ~SCHEDULED: <%%(diary-float t 42)>~ (also with ~DEADLINE~ or ~CLOSED~ on the same line) is stored as the heading's ~scheduled_raw~ without a date instead of a body timestamp, and the line no longer appears in the body text. ~id:~ and ~#custom-id~ link targets are trimmed of spaces and tabs before matching the trimmed ID values. A priority cookie after ~COMMENT~ (~* COMMENT [#A] x~) is title text, not a priority. The parser contract version is now ~4~, so existing databases reparse automatically on the next incremental or watch run.

- =FIXED= TODO keyword specs now follow Org for every form: ~NAME(x/!)~, ~NAME(x@/!)~, ~NAME(x!/@)~, ~NAME(@/!)~, ~NAME(!)~, ~NAME(@)~ and ~NAME(/!)~ give the keyword ~NAME~ (with fast key ~x~ where present) in ~#+TODO~ lines instead of a literal name with parentheses, and ~todo.default_open_keywords~ and ~todo.default_closed_keywords~ accept them (for example ~WAIT(w@/!)~). The parser contract version is now ~3~, so existing databases reparse automatically on the next incremental or watch run.

- =FIXED= A ~:PROPERTIES:~ drawer after a blank line, or after a comment on a heading, no longer counts as a property drawer; at file level only comment lines (no blank lines) may precede it, and on a heading only a single planning line may, as in Org. The parser contract version is now ~3~, so existing databases reparse automatically.
- =FIXED= Files with headings nested deeper than 100 levels no longer abort the process with a stack overflow; they now fail to parse with an error naming the level and line, and ~collect_headlines~ no longer recurses per heading level.
- =FIXED= The watcher's presentation-view control socket now applies 5 s read/write timeouts and a 64 KiB request limit, so a silent client can no longer block other view commands or watcher shutdown; ~view read~ now fails after 60 s instead of waiting forever on a rebuild that stays pending.

- =CHANGED= Indexing skips the extra Orgize pre-parse for files without in-buffer TODO keyword lines and finds link-owning headings by binary search; rebuilding a file with 10,000 linked headings drops from about 3.1 s to about 2.2 s.

- =CHANGED= The parser contract version (~PARSER_INDEXER_CONTRACT_VERSION~) was bumped to ~2~, so existing databases reparse all files on the next incremental or watch run; a guard test (~tests/parser_contract_guard.rs~) now enforces bumps when parsed fixture output changes.

- =FIXED= ~:PROPERTIES:~ drawers that are not placed directly after the heading (or planning line), or after leading comments at file level, no longer create properties. Rebuild existing databases to refresh affected properties.

- =CHANGED= Library API: ~ValidatedQuery~, ~ValidatedPredicate~ and ~ValidatedOption~ fields are now crate-private with read-only accessors, so only the validator can build these types and the SQL compiler's invariants hold.

- =FIXED= Case-insensitive query predicates (~title~, ~has-text~, ~outline-contains~, ~outline-sequence~, ~keyword~, file and link text predicates) now use Unicode lowercase folding instead of ASCII-only folding, so ~"über"~ matches ~Über~.

- =FIXED= Planning fallback parsing no longer treats links like ~[[file:a/b.org]]~ as timestamps and keeps time ranges such as ~10:00-11:00~ when a repeater deadline like ~+1w/2d~ is present. Rebuild existing databases to refresh affected planning data.

- =FIXED= Headings with a trailing ~:foo/bar:~ block no longer lose that text from the title; only blocks whose tags consist of alphanumerics and ~_@#%~ are stripped as tags.

- =FIXED= ~search --title~ and ~--body~ now reject expressions with unbalanced parentheses outside double quotes, so user text can no longer close the scope wrapper and match the other column.

- =FIXED= ~file+sys:~ and ~file+emacs:~ links now resolve like ~file:~ links instead of always being ~unsupported~. Rebuild existing databases to refresh affected links.

- =FIXED= Config loading now rejects invalid ~todo.default_open_keywords~ and ~todo.default_closed_keywords~ entries (empty, whitespace, malformed shortcuts, duplicates across both lists) instead of storing them or silently dropping closed keywords.

- =CHANGED= Link resolution now builds ID, heading-title, ~CUSTOM_ID~ and root-heading lookups once per pass instead of querying per link; rebuilding a file with 10,000 linked headings drops from about 88 s to about 3 s.

- =FIXED= ~--help~ and ~--version~ now print to standard output and exit with code ~0~ instead of writing to standard error with exit code ~2~.

- =CHANGED= Parsing large Org files is now linear in file size: line numbers use a per-document line index, and link scanning no longer rescans ignored ranges or context spans per position.

- =FIXED= Parsing no longer panics when an in-buffer ~#+TODO:~ keyword contains a bracket link (e.g. ~#+TODO: [[b]] | DONE~).

- =FIXED= Discovery now skips dangling symlinks, such as Emacs lock files (~.#notes.org~), instead of aborting ~rebuild~ and ~watch~.

- =CHANGED= Direct-flat query result shaping now moves row-owned values and local metadata into final results instead of cloning them, reducing broad query latency.

- =CHANGED= Expensive heading queries now reuse one per-query TEMP matched relation while cheap matches stay query-derived.

- =CHANGED= Selective heading metadata filters now use predicate-driven SQLite matching with measured property and keyword indexes.

- =CHANGED= ~orgfdb status~ now reports the absolute canonical ~database_path~ so cached clients can install SQLite file-notification watches without duplicating config resolution.

- =ADDED= Added persistent database identities, transactional index generations, affected-file change journals, and read-only ~status~ and ~changes~ JSON commands for reliable cached-view refresh.

- =ADDED= Structural ~query~ execution can now be restricted safely to a machine-readable list of owning canonical file paths for selective saved-view patching.

** Changelog Entry Types

- =ADDED= :: Use for new features, new functionality, or newly introduced behavior.
- =CHANGED= :: Use for modifications to existing behavior.
- =FIXED= :: Use for bug fixes or incorrect behavior that now works correctly.
- =REMOVED= :: Use for removed functionality, deleted features, or deprecated behavior that no longer exists.

** Rules

- Use one bullet per change.
- Keep entries short and clear.
- Write for users, not developers.
- Do not include unfinished work.
- Do not include internal refactorings unless they affect users.
- Add newest entries at the top of the =Unreleased= section.
- Use uppercase entry types:
  - =ADDED=
  - =CHANGED=
  - =FIXED=
  - =REMOVED=
- Keep wording simple and direct.
- Prefer describing the visible result instead of implementation details.

** Releases

When creating a release:
- move entries from =Unreleased= into a version section
- keep the same bullet format
- use the following heading format:
  #+begin_src org
    ,* 0.1.0 - YYYY-MM-DD
  #+end_src

** Example Release

  ,* 0.1.0 - 2026-05-22

  - =CHANGED= Clarified AI workflow and commit rules.
  - =FIXED= Fixed incorrect WAIT status handling.
  - =REMOVED= Removed outdated setup instructions.
#+end_src
