#+TITLE: Project Structure & Module Descriptions

The source code is structured as follows:

├── src/
│   ├── *main.rs*       # Application Entry Point (Binary)
│   ├── *lib.rs*        # Project Library (Core Logic Export)
│   ├── *parser/*       # Module folder for all parsing components
│   │   ├── *mod.rs*    # Defines the 'parser' module
│   │   ├── *lexer.rs*  # Line and Inline Lexer
│   │   ├── *parser.rs* # Abstract Syntax Tree (AST) Parser
│   │   └── *ast.rs*    # AST Node and Object Definitions
│   ├── *db.rs*         # Database (DB) Logic Module
│   ├── *watcher.rs*    # File System Watcher Module
│   ├── *indexer.rs*    # Indexing and Sync Logic Module
│   ├── *config.rs*     # Configuration Handling Module
│   └── *utils.rs*      # General Utility Functions

* Modules

The following outlines the purpose and contents of the main files and modules within the =src/= directory.

** Application

- =main.rs= :: *Application Entry Point (The Binary)*
  This file contains the primary =fn main()= function. It is responsible for *loading the configuration* via the =config= module, *initializing the database* connection, and *starting the file system watcher* and the indexer loop. It acts as the glue code that orchestrates the execution flow of the application.

- =lib.rs= :: *Project Library (Core Logic Export)*
  This is the main library of the project. It *declares and exports all primary modules* (e.g., =parser=, =db=, =watcher=). Any function or struct intended to be shared across the application or used by external crates should be defined or re-exported here.

** Core

- =parser/= :: *Parsing Components Module*
  This module encapsulates all logic related to reading source files, tokenizing, and generating the Abstract Syntax Tree (AST).

  - =parser/mod.rs= :: *Parser Module Definition*
    Declares the sub-modules (=lexer=, =parser=, =ast=) and sets up the public API for the entire =parser= component, allowing other modules to easily import parsing functionality.
  - =parser/lexer.rs= :: *Lexical Analyzer*
    Contains the code for the *Line- and Inline-Lexer*. Its primary job is to take the raw input source code and convert it into a stream of meaningful tokens.
  - =parser/parser.rs= :: *AST Parser*
    Implements the logic that consumes the tokens generated by the lexer and constructs the hierarchical data structure, the *Abstract Syntax Tree (AST)*.
  - =parser/ast.rs= :: *AST Definitions*
    Defines the data structures for all *AST Nodes* and *Objects* (the intermediate representation) that the parser produces.

- =db.rs= :: *Database (DB) Logic Module*
  Handles all interactions with the persistent storage layer. This includes connection management, schema definition, and the implementation of CRUD (Create, Read, Update, Delete) operations for storing parsed data and indexes.

- =watcher.rs= :: *File System Watcher Module*
  Manages the *monitoring of the source file directory*. It uses system-specific APIs to detect changes (creation, modification, deletion) in files and triggers the indexer logic upon detecting an event.

- =indexer.rs= :: *Indexing and Sync Logic Module*
  Contains the core logic for *synchronizing parsed content with the database*. When triggered by the watcher, it reads the changed files, calls the =parser= module, and updates or inserts the results into the database using the =db= module.

** Auxiliary

- =config.rs= :: *Configuration Handling Module*
  Responsible for defining the application's settings structure, loading configuration from files (config.toml), and handling command-line arguments.

- =utils.rs= :: *Utility Functions*
  A collection of miscellaneous, non-domain-specific helper functions (e.g., logging setup, common error handling traits, simple string manipulation) used throughout the project.
