#+TITLE: Project Structure & Module Descriptions

[2026-05-27 Wed] Verifiziert

The source code is structured as follows:

├── src/
│   ├── main.rs          # App Entry Point (Glue-Code, Loop-Start)
│   ├── lib.rs           # Core Library Export (deklariert die Top-Level-Module)
│   ├── parser.rs        # Haupteinstieg parser-Modul & Haupt-Parser-Logik
│   ├── parser/          # Ordner NUR für die parser-Submodule
│   │   ├── block.rs     # Block-Scanner (Headings, Drawers, Blocks)
│   │   ├── inline.rs    # Inline-Lexer (Links, Textmarker)
│   │   └── ast.rs       # Reine Typdefinitionen (AST-Knoten / Structs)
│   ├── db.rs            # Datenbank-Interaktion (CRUD)
│   ├── watcher.rs       # Dateisystem-Überwachung
│   ├── indexer.rs       # Synchronisations-Logik (Watcher -> Parser -> DB)
│   ├── config.rs        # Konfigurations- & CLI-Parsing
│   └── error.rs         # Zentrales Fehler-Handling 

* Modules

The following outlines the purpose and contents of the main files and modules within the =src/= directory.

** Application

- =main.rs= :: *Application Entry Point (The Binary)*
  This file contains the primary =fn main()= function. It is responsible for *loading the configuration* via the =config= module, *initializing the database* connection, and *starting the file system watcher* and the indexer loop. It acts as the glue code that orchestrates the execution flow of the application.

- =lib.rs= :: *Project Library (Core Logic Export)*
  This is the main library of the project. It *declares and exports all primary modules* (e.g., =parser=, =db=, =watcher=, =error=). Any function or struct intended to be shared across the application or used by external crates should be defined or re-exported here.

** Core

- =parser.rs= :: *Parser Module Entry & Core Logic*
  Acts as the entry point for the =parser= module, declaring its sub-modules (=block=, =inline=, =ast=). It implements the main parser logic that coordinates the block scanning and inline lexing to build the final Abstract Syntax Tree (AST).

- =parser/= :: *Parsing Sub-modules Folder*
  This directory contains the specialized components used by the main parser.

  - =parser/block.rs= :: *Block Scanner*
    Scans the source file line by line to identify structural block-level elements such as headings, properties, drawers, and source blocks.
  - =parser/inline.rs= :: *Inline Lexer*
    Analyzes the content within blocks to detect inline elements, including links, text formatting, and timestamps.
  - =parser/ast.rs= :: *AST Definitions*
    Defines the data structures, enums, and nodes for the Abstract Syntax Tree (AST), representing the parsed document in a structured format.

- =db.rs= :: *Database (DB) Logic Module*
  Handles all interactions with the persistent storage layer. This includes connection management, schema definition, and the implementation of CRUD (Create, Read, Update, Delete) operations for storing parsed data and indexes.

- =watcher.rs= :: *File System Watcher Module*
  Manages the *monitoring of the source file directory*. It uses system-specific APIs to detect changes (creation, modification, deletion) in files and triggers the indexer logic upon detecting an event.

- =indexer.rs= :: *Indexing and Sync Logic Module*
  Contains the core logic for *synchronizing parsed content with the database*. When triggered by the watcher, it reads the changed files, calls the =parser= module, and updates or inserts the results into the database using the =db= module.

** Auxiliary

- =config.rs= :: *Configuration Handling Module*
  Responsible for defining the application's settings structure, loading configuration from files (config.toml), and handling command-line arguments.

- =error.rs= :: *Central Error Handling Module*
  Defines the application-wide error types and traits (e.g., using custom enums). Centralizes error management to ensure robust and idiomatic error propagation throughout all modules.
