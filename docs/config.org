#+TITLE: Configuration Reference
#+STARTUP: showall

~orgfdb~ reads TOML configuration. This page lists the configuration keys that the current implementation accepts.

Unknown keys are errors. This rule applies at the top level and inside every configuration section.

* Example

#+begin_src toml
db_path = "org-files-db.sqlite"
files = ["inbox.org", "projects.org"]
files_exclude = ["private.org", "**/*.private.org"]

[[dirs]]
path = "notes"
recursive = true
exclude = ["archive/**"]

[[dirs]]
path = "reference"

[links]
plain_protocols = ["http", "https", "file"]
custom_protocols = ["jira", "customlink"]

[todo]
default_open_keywords = ["TODO(t)", "NEXT(n)"]
default_closed_keywords = ["DONE(d)", "CANCEL(c)"]

[search]
fts5_enabled = true
index_body_text = false

[query]
timezone = "Europe/Zurich"
#+end_src

* Path rules

Relative paths use the configuration file directory as their base. This rule applies to ~db_path~, ~files~, and ~dirs[].path~.

A leading ~~/~ uses the current ~HOME~ directory. Named-user forms such as ~~alice/~ are not supported.

The loader converts configured paths to absolute syntactic paths. File discovery later canonicalizes indexed file identity.

* Top-level keys

The supported top-level keys are:

- ~db_path~
- ~files~
- ~files_exclude~
- ~dirs~
- ~links~
- ~todo~
- ~search~
- ~query~

The old top-level ~recursive~ key is not supported. Configure recursion in each ~[[dirs]]~ entry.

* ~db_path~

~db_path~ selects the SQLite database file.

- Type: string
- Default: ~org-files-db.sqlite~

Example:

#+begin_src toml
db_path = "./state/org-files-db.sqlite"
#+end_src

* ~files~

~files~ lists explicit source files.

- Type: array of strings
- Default: ~[]~

Example:

#+begin_src toml
files = ["inbox.org", "capture.txt"]
#+end_src

An explicit file does not need an ~.org~ extension. This is the documented extension override for individual files.

A missing explicit file remains part of the configured source set as an absent source. Incremental reconciliation can detect its later creation.

* ~files_exclude~

~files_exclude~ defines global file exclusion globs.

- Type: array of strings
- Default: ~[]~

Example:

#+begin_src toml
files_exclude = [
  "private.org",
  "**/*.private.org",
  "~/notes/generated/**"
]
#+end_src

Global exclusions apply across configured aliases and directory roots. Another root cannot make a globally excluded file eligible again.

An excluded explicit file is ignored before file metadata or canonical path access. An excluded missing explicit file therefore causes no missing-file error.

* ~dirs~

~dirs~ contains directory discovery roots. Configure each root with a ~[[dirs]]~ table.

- Type: array of tables
- Default: ~[]~

Each table supports:

- ~path~
- ~recursive~
- ~exclude~

Example:

#+begin_src toml
[[dirs]]
path = "notes"
recursive = true
exclude = ["archive/**", "generated/*.org"]
#+end_src

** ~dirs[].path~

~path~ selects the directory root.

- Type: string
- Required: yes

** ~dirs[].recursive~

~recursive~ controls subdirectory discovery for this root.

- Type: boolean
- Default: ~false~

If ~recursive = false~, discovery reads eligible files directly inside the configured directory only.

If ~recursive = true~, discovery also descends into eligible subdirectories.

** ~dirs[].exclude~

~exclude~ defines exclusion globs for one directory root.

- Type: array of strings
- Default: ~[]~

Relative local patterns use that root as their logical base. A local exclusion affects only its own ~[[dirs]]~ entry.

A local pattern can exclude a file or a directory tree. For example, ~archive/**~ excludes that tree from a recursive root.

* Discovery rules

Directory discovery includes regular files whose extension is ASCII case-insensitively equal to ~.org~. Explicit ~files~ entries can use another extension.

Hidden files and directories use the same discovery rules as other entries. A recursive root can descend into hidden directories.

File symlinks and directory symlinks are followed. Cycle detection prevents recursive loops inside each configured root.

Configured aliases and overlapping roots can find the same physical file. Canonical file identity deduplicates these matches before indexing.

A missing configured directory is an error. A missing explicit file is an absent configured source.

The rebuild safety guard prevents an accidental empty-source replacement of an existing index. Use ~--allow-empty~ only for an intentional empty rebuild.

* Exclusion glob rules

Exclusion globs are case-sensitive. A slash is a literal path separator.

Global relative patterns use the configuration directory as their base. Global absolute patterns match absolute logical paths.

A leading ~~/~ in a global pattern expands when the configuration loads. That expansion keeps the same home-directory basis during discovery.

Local relative patterns use their ~[[dirs]]~ root as the base. Local rules do not leak into another root.

Discovery keeps logical path provenance while it applies exclusions. Canonical paths remain the physical file identity and final deduplication key.

A rebuild that becomes empty only because exclusions matched is intentional. It can remove previously indexed rows without ~--allow-empty~.

* ~[links]~

The ~[links]~ section controls protocols that the parser recognizes as plain Org links.

Supported keys:

- ~plain_protocols~
- ~custom_protocols~

** ~links.plain_protocols~

~plain_protocols~ replaces the built-in base protocol list when present.

- Type: array of strings
- Default: built-in plain-link protocols

Example:

#+begin_src toml
[links]
plain_protocols = ["http", "https", "file"]
#+end_src

The loader normalizes protocol names to lowercase and removes duplicates.

** ~links.custom_protocols~

~custom_protocols~ adds project-specific protocols to the base list.

- Type: array of strings
- Default: ~[]~

Example:

#+begin_src toml
[links]
custom_protocols = ["jira", "customlink"]
#+end_src

The loader normalizes and deduplicates the combined protocol list.

* ~[todo]~

The ~[todo]~ section provides default TODO keywords for files without in-buffer TODO declarations.

Supported keys:

- ~default_open_keywords~
- ~default_closed_keywords~

In-buffer ~#+TODO~, ~#+SEQ_TODO~, and ~#+TYP_TODO~ declarations take precedence over these defaults.

** ~todo.default_open_keywords~

~default_open_keywords~ defines open TODO keywords.

- Type: array of strings
- Default: ~["TODO"]~

Entries can contain Org fast-selection keys such as ~TODO(t)~.

** ~todo.default_closed_keywords~

~default_closed_keywords~ defines closed TODO keywords.

- Type: array of strings
- Default: ~["DONE"]~

Entries can contain Org fast-selection keys such as ~DONE(d)~.

* ~[search]~

The ~[search]~ section controls the optional SQLite FTS5 index.

Supported keys:

- ~fts5_enabled~
- ~index_body_text~

** ~search.fts5_enabled~

~fts5_enabled~ controls FTS5 index creation during indexing.

- Type: boolean
- Default: ~true~

If this value is true, rebuild requires SQLite FTS5 support. Rebuild writes trust metadata for the derived search index.

If this value is false, rebuild does not create or refresh the FTS index. ~orgfdb search~ also rejects search while this configuration disables FTS.

A table that remains from an older rebuild is not sufficient. Search also requires current persisted FTS trust metadata.

** ~search.index_body_text~

~index_body_text~ controls persistence and search indexing of heading body text.

- Type: boolean
- Default: ~false~

If this value is true, indexing stores canonical heading body text. An FTS-enabled rebuild also indexes that body text.

If this value is false, the trusted FTS index is title-only. ~orgfdb search --body~ is then unavailable.

Changing this setting requires a rebuild before the database capability reflects the new value.

* ~[query]~

The ~[query]~ section controls structural query time handling.

Supported keys:

- ~timezone~

** ~query.timezone~

~timezone~ selects an IANA timezone for relative query dates such as ~today~, ~-1~, and ~7~.

- Type: string
- Default: local system timezone

Example:

#+begin_src toml
[query]
timezone = "Europe/Zurich"
#+end_src

The loader rejects an invalid timezone name.

The timezone selects the calendar date for relative values. Stored Org planning and generic timestamp values remain timezone-naive.
