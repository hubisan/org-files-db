#+TITLE: Config Reference
#+STARTUP: showall

This page lists the ~config.toml~ variables currently supported by ~orgfdb~.

* Example

#+begin_src toml
db_path = "org-files-db.sqlite"
files = ["inbox.org", "projects.org"]

[[dirs]]
path = "notes"
recursive = true

[[dirs]]
path = "archive"

[links]
plain_protocols = ["http", "https", "file"]
custom_protocols = ["jira", "customlink"]

[todo]
default_open_keywords = ["TODO(t)", "NEXT(n)"]
default_closed_keywords = ["DONE(d)", "CANCEL(c)"]

[search]
fts5_enabled = true
index_body_text = false

[query]
timezone = "Europe/Zurich"
#+end_src

* Top-level keys

- ~db_path~
- ~files~
- ~dirs~
- ~links~
- ~todo~
- ~search~
- ~query~

* ~db_path~

Path to the SQLite database file.

- Type: string
- Default: ~org-files-db.sqlite~

Relative paths are resolved against the config file location.

* ~files~

Explicit Org files to index.

- Type: array of strings
- Default: ~[]~

Each entry is a file path. Relative paths are resolved against the config file location.

Explicit files are regular-file overrides: they may use an extension other than ~.org~. A missing explicit file is recorded as an absent configured source for later incremental reconciliation; it does not make a configured directory root disappear.

* ~dirs~

Directories to search for Org files.

- Type: array of tables
- Default: ~[]~

Each ~[[dirs]]~ entry configures one discovery root. Relative paths are resolved against the config file location.

** ~dirs[].path~

Directory path to search for Org files.

- Type: string
- Required: yes

** ~dirs[].recursive~

Controls whether discovery for this directory descends into subdirectories.

- Type: boolean
- Required: no
- Default: ~false~

Example:

#+begin_src toml
[[dirs]]
path = "notes"
recursive = true

[[dirs]]
path = "inbox"
recursive = false
#+end_src

* Discovery and file identity

Discovery constructs one deterministic source set shared by rebuild and later incremental entry points.

- org-files-db supports Linux and Unix-like platforms, including macOS. Windows is unsupported.
- Directory roots include regular files whose extension is ASCII case-insensitively ~.org~. Explicit ~files~ entries are the documented extension override.
- Hidden entries follow the same rules as ordinary entries. Recursive roots descend into hidden directories.
- Configured aliases, overlapping roots, and file symlinks are canonicalized and deduplicated to one indexed file. A recursive directory symlink is followed even when its target is outside the configured root. Cycle detection is per configured root, so overlapping roots may traverse a physical directory separately while final files remain globally deduplicated.
- A missing configured directory root is a discovery error and prevents destructive reconciliation. A missing explicit file is an absent-source record; the existing empty-source rebuild guard still prevents an unintended wipe.
- Indexed file identity is a version-tagged byte-preserving canonical Unix path. The public path field remains unchanged for UTF-8 paths; non-UTF-8 paths use a reversible ~path-bytes:%XX...~ representation rather than lossy replacement text. Existing TEXT-only DB rows retain ~identity = NULL~ until a successful rebuild or later reconciliation rediscovers the canonical path.
- ~files_exclude~ contains global, file-only Unix globs. Relative patterns are evaluated from the config directory; absolute patterns are matched against absolute logical paths; leading ~~/~ patterns are expanded once while loading the config and retain that stable home-directory basis for discovery.
- Each ~[[dirs]]~ entry may contain ~exclude = ["..."]~. Relative local patterns are evaluated from that entry's logical root and may exclude files or whole directory trees. A matching recursive directory is pruned; use ~archive/**~ to exclude that directory and all descendants.
- Globs are case-sensitive, use ~/~ as a literal path separator, and match Unix path bytes without lossy conversion. Global rules win across aliases and are never undone by another root; local rules remain isolated to their configured root. Logical discovery provenance is retained for this decision while canonical paths remain the physical identity and final deduplication key.
- An explicit file matched by a global exclusion is ignored before any stat or canonicalization, so an excluded missing explicit file is not an error. A rebuild emptied by matching exclusions, including a pruned tree, is intentional and transactionally removes prior indexed rows. Missing roots and genuinely empty input retain the existing safety behavior.

* ~[links]~

Controls plain-link protocol handling for Phase 3 link scanning.

Supported keys:

- ~plain_protocols~
- ~custom_protocols~

** ~links.plain_protocols~

Protocols recognized as plain links.

- Type: array of strings
- Default: built-in plain-link protocol list

When this field is omitted, the built-in defaults are used. When it is present, it defines the base list before ~custom_protocols~ are appended and deduplicated case-insensitively.

** ~links.custom_protocols~

Additional project-specific protocols recognized as plain links.

- Type: array of strings
- Default: ~[]~

Values are lowercased and deduplicated together with ~plain_protocols~.

* ~[todo]~

Controls default TODO keyword handling when a file does not define its own in-buffer Org TODO keywords.

Supported keys:

- ~default_open_keywords~
- ~default_closed_keywords~

** ~todo.default_open_keywords~

Default open TODO keywords.

- Type: array of strings
- Default: ~["TODO"]~

Entries may include Org-style fast selection keys such as ~TODO(t)~.

** ~todo.default_closed_keywords~

Default closed TODO keywords.

- Type: array of strings
- Default: ~["DONE"]~

Entries may include Org-style fast selection keys such as ~DONE(d)~.

* ~[search]~

Controls search-related indexing behavior.

Supported keys:

- ~fts5_enabled~
- ~index_body_text~

** ~search.fts5_enabled~

Controls whether SQLite FTS5 indexing is enabled during rebuild.

- Type: boolean
- Default: ~true~
- When enabled and supported by the opened SQLite build, rebuild recreates a derived contentless ~heading_fts~ table from canonical relational facts.
- When enabled but unsupported by the opened SQLite build, rebuild fails with a clear backend-capability error.
- When disabled, rebuild does not create or refresh ~heading_fts~. A stale table may still exist on disk, but it is not trusted without a new FTS-enabled rebuild.
- The read-only ~orgfdb search~ command also requires the active config to leave ~search.fts5_enabled = true~. A trusted persisted FTS index on disk is not usable when the current config disables FTS.
- Current config does not prove that a trusted search index exists. ~orgfdb search~ additionally requires persisted FTS trust metadata written by a successful rebuild.

** ~search.index_body_text~

Controls whether heading body text is persisted as canonical database data during rebuild.

- When enabled, the indexer stores heading body text in ~heading_bodies~ and persists a database capability flag indicating that body text is available for query backends.
- When enabled together with ~search.fts5_enabled = true~, rebuild also records that the trusted FTS index contains body text so ~orgfdb search --body~ is allowed.
- When disabled, the indexer does not store heading body text and persists the capability flag as unavailable even though the ~heading_bodies~ table may still exist in the schema.
- When disabled, a trusted FTS rebuild remains title-only and ~orgfdb search --body~ fails clearly until a later rebuild enables both FTS and body persistence.
- Upgrading an older database schema creates the metadata storage, but body-text capability does not become available until a rebuild writes the current capability value for that database instance.

- Type: boolean
- Default: ~false~

* ~[query]~

Controls query-time behavior for relative date resolution.

Supported keys:

- ~timezone~

** ~query.timezone~

Optional IANA timezone name used when resolving relative query date values such as ~today~, ~-1~, and ~7~.

- Type: string
- Required: no
- Default: local system timezone

If this field is set, it overrides the local system timezone for query-time relative-date resolution. Relative dates are resolved before SQL execution into timezone-naive date strings so stored Org timestamps are not converted between timezones.
