* Angle links


** Basic angle links with spaces
- <https://example.com/some path with spaces>
- <https://example.org/ spaces >
- <info:org#External Link>
- <mailto:emacs-orgmode@gnu.org>

** File-like angle links with search options
- <file:~/code/main.c::255>
- <file:~/xx.org::*My Target>
- <file:~/xx.org::#my-custom-id>
- <file:~/xx.org::/regexp/>
- <file:::find me>
- <file:::*Current File Heading>

** File variant angle links with search options
- <file+sys:~/code/main.c::255>
- <file+sys:~/xx.org::*My Target>
- <file+emacs:~/code/main.c::255>
- <file+emacs:~/xx.org::#my-custom-id>

** Unknown and custom-looking angle links
- <unknown:foo>
- <jira:ABC-123>
- <customlink:test>
- <doi:10.1000/182>
- <irc:/irc.com/#emacs/bob>

** Action-like angle links

These must be stored as raw source facts only. They must not be executed.

- <shell:ls *.org>
- <elisp:(find-file "~/.emacs.d/init.el")>

** Non-file-like search-option-looking paths

These should keep the full path and should not split ~::~ in Phase 3.

- <id:16ccfc6a-11ba-499f-8bc6-41be30daa3c5::10>
- <attachment:projects.org::10>
- <docview:papers/last.pdf::12>
- <unknown:file.org::10>
- <customlink:file.org::10>

** Special
Results in an angled link as brackets are escaped:
[[<https://www.gnu.org>\][Test]]

Or with a new line
[[<https://www.gnu.org>]
[Test]]

But this should be a bracket link:
[[<https://www.gnu.org>][<https://www.gnu.org>]]

** Invalid angle candidates

These should not be stored as angle links.

- <https://example.com
- <unknown:unterminated
- <file:~/broken.org::10

This multiline candidate should also be ignored:

<https://example.org
  path with newline>

Garbage before a later valid angle link:
<broken
<https://example.org/later-valid>
<broken <https://example.org/later-valid>

** Plain links not stored by this task

These should remain out of scope until plain-link storage is implemented.

- https://example.org/plain
- file:~/code/main.c::255
- shell:ls *.org
- jira:ABC-123
