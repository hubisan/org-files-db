These should not be stored by default.

They may be stored only when explicitly enabled through ~plain_protocols~ or ~custom_protocols~.

** Boundary and end behavior

Representative cases checked against observed ~org-element-parse-buffer~ behavior.
The project keeps the configured protocol list project-owned, but plain-link boundary and end semantics should stay Org-like where feasible.

Org keeps balanced ~(...)~, ~[...]~, and ~<...>~ suffixes as part of the plain-link path.

*** Accepted plain-link left boundaries

These should store the URL without the prefix punctuation.

- !https://www.example.com/bang-prefix
- @https://www.example.com/at-prefix
- #https://www.example.com/hash-prefix
- ^https://www.example.com/caret-prefix
- &https://www.example.com/ampersand-prefix
- (https://www.example.com/open-paren-prefix
- )https://www.example.com/close-paren-prefix
- _https://www.example.com/underscore-prefix
- -https://www.example.com/dash-prefix
- =https://www.example.com/equal-prefix
- ~https://www.example.com/tilde-prefix
- +https://www.example.com/plus-prefix
- "https://www.example.com/double-quote-prefix
- Prefix:https://www.example.com/after-colon-prefix

*** Rejected plain-link left boundaries

These should not be stored as plain links.

- $https://www.example.com/dollar-prefix
- %https://www.example.com/percent-prefix
- 'https://www.example.com/single-quote-prefix
- xhttps://www.example.com/middle-of-word

*** Whitespace and balanced delimiter end behavior

Plain links should stop at whitespace.

- https://example.org/path with text after whitespace

Balanced delimiter groups should remain part of the plain-link path when complete.

- https://example.org/path<balanced-suffix>
- https://example.org/path(foo)
- https://example.org/path[foo]
- https://example.org/path<balanced-angle-suffix>

Unbalanced or leading closer delimiter cases should stop before the delimiter.

- https://example.org/path>not-part-of-plain-link
- https://example.org/path<not-part-of-plain-link
- https://example.org/path)not-part-of-plain-link
- https://example.org/path]not-part-of-plain-link

Curly braces are not Org plain-link balanced groups. The trailing ~}~ remains deterministic punctuation trimming, not balanced-group handling.

- https://example.org/path{not-a-balanced-plain-link-group}
- https://example.org/path}

*** Emphasis and markup interaction

Exact emphasis/markup interaction remains deferred to later ignored-region/source-context work.
Observed Org behavior extracts the plain link from this emphasis object:

- *https://example.org/emphasis-delimited*

The final scanner/storage expectation for this case should be pinned when ignored-region/source-context handling is implemented.

*** Final-character behavior

Deterministic trailing punctuation should be trimmed from the stored raw span.

- https://example.org/path.
- https://example.org/path,
- https://example.org/path;
- https://example.org/path:
- https://example.org/path!
- https://example.org/path?

A trailing slash or dash should remain part of the stored raw span.

- https://example.org/path/
- https://example.org/path-

** Search-option-looking paths

Search-option splitting for plain file-like links may be handled by the dedicated search-option task.
Until then, these are useful manual cases.

- file:./plain-links.org::10
- file:./plain-links.org::*Plain links
- file:./plain-links.org::#some-custom-id
- file:./plain-links.org::/regexp/
- file:::current file search
- file+sys:./plain-links.org::10
- file+emacs:./plain-links.org::10

Non-file-like plain links with ~::~ should not be split in Phase 3.

- id:abc123::10
- attachment:projects.org::10
- docview:papers/last.pdf::12
- jira:ABC-123::10
- customlink:file.org::10
