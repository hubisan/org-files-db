Define semantic presentation roles in Rust.

Initial roles include:

- ~heading~
- ~title~
- ~todo~
- ~done~
- ~priority~
- ~tag~
- ~date~
- ~file-name~
- ~file-path~
- ~keyword-name~
- ~keyword-value~
- ~property-name~
- ~property-value~

Use ~heading~ for ~outline-path~, ~source-outline-path~, and ~target-outline-path~.

Do not add heading-level roles, role ranges, outline-separator styling, Emacs face names, colors, text properties, or theme data.

* Planning

** Problem summary

The public presentation column registry stores semantic roles as string literals inside ~PresentationRoleRule~.

This does not give Rust one typed definition of the public role vocabulary. It also leaves the ~todo-keyword~ role unresolved between open and closed TODO states.

** Goals

- Add one typed ~PresentationRole~ enum.
- Give every role a stable kebab-case wire name.
- Replace string role literals in the column registry with typed roles.
- Keep ~todo-keyword~ dynamic so open TODO states use ~todo~ and closed states use ~done~.
- Keep columns without useful styling semantics on ~None~.
- Keep outline-path columns on the single ~heading~ role.
- Prepare the role type for the later cell wire model.

** Non-goals

- Do not define presentation rows or cells.
- Do not serialize complete presentation responses.
- Do not add link-specific roles without a concrete display distinction.
- Do not add heading levels, role ranges, or separator roles.
- Do not add Emacs face names or client styling data.
- Do not implement value extraction, sorting, widths, truncation, or row expansion.

** Architecture

Add ~PresentationRole~ as a typed public enum in ~src/presentation.rs~.

Use ~serde~ kebab-case names so the later wire model can serialize stable values without client-specific names.

Keep ~PresentationRoleRule~ as the registry rule type:

- ~None~ gives no role.
- ~Static(PresentationRole)~ gives one fixed role.
- ~TodoKeyword~ resolves from the stored TODO type.

The TODO type uses the existing database values ~open~ and ~closed~. Unknown or missing TODO types do not invent a role.

- ~file-title~ uses the existing ~title~ role.
- Aggregate ~tags~ and singular ~tag~ both use the ~tag~ role.
- Missing or invalid TODO type data produces no role instead of guessing an open or closed state.
