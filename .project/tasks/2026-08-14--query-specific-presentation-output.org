Goal: Add the infrastructure for an opt-in presentation output format to ~orgfdb query~ without changing the existing JSON output contract.

Keep:

#+begin_src sh
orgfdb query --format json ...
#+end_src

fully backwards compatible.

Add a query-specific presentation format conceptually named:

#+begin_example
presentation-json
#+end_example

Presentation must remain part of the existing ~query~ command rather than becoming a separate query subcommand.

Do not expose the presentation format accidentally on unrelated commands.

Do not implement presentation caching or streaming.

Acceptance criteria:

- Existing JSON query output remains unchanged.
- ~presentation-json~ is query-specific.
- The normal query parser and execution path remain shared.
- Invalid combinations produce clear CLI errors.

* Planning

** Problem summary

The CLI currently uses one shared output-format type for ~headings~, ~links~, ~status~, ~changes~, ~query~, and ~search~.

That type only supports ~json~. Adding ~presentation-json~ there would expose the new format on commands that must remain JSON-only.

The presentation data model does not exist yet. This task therefore adds query-specific format selection and routing only.

** Goals

- Keep the existing ~orgfdb query --format json~ path unchanged.
- Add ~presentation-json~ as a format value accepted only by ~orgfdb query~.
- Keep query parsing, validation, execution, includes, restrictions, and result shaping shared between query formats.
- Add one query-output routing boundary for later presentation serialization.
- Return a clear error for ~presentation-json~ until the presentation response model is implemented.

** Non-goals

- Do not define ~PresentationSpec~.
- Do not define presentation rows, cells, columns, roles, sorting, widths, or truncation.
- Do not add caching, JSONL, or streaming.
- Do not change the existing query JSON response.

** Architecture

Keep ~CliOutputArgs~ and ~CliOutputFormat~ for commands that support JSON only.

Add a query-specific format argument type with these values:

- ~json~
- ~presentation-json~

The query command executes its normal query path before output routing. A dedicated writer selects JSON output or the presentation placeholder error.

The existing query execution helpers remain shared. Only the final output routing differs by query format.

** Execution plan

1. Add query-specific format arguments and enum values.
2. Keep the existing ~--json~ compatibility flag for ~query~.
3. Route only ~query~ through the query-specific format type.
4. Keep the existing query execution path shared.
5. Add a clear placeholder error for ~presentation-json~ until its wire model exists.
6. Add parser, help, compatibility, and command-isolation tests.
7. Update CLI and presentation design documentation for the staged format support.
8. Run ~make ci~.

** Risks & assumptions

- ~presentation-json~ is intentionally not a usable presentation contract in this task. The later wire-model and connection tasks will replace the placeholder error.
- Executing a valid query before the placeholder output error proves that both query formats share query parsing and execution. This temporary cost exists only during the staged implementation.
