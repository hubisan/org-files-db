* Phase 3: Link extractor

Goal of this phase:
Extract Org links and represent them in SQLite. Link resolution comes later.

Reference:

- [[file:../../tests/data/org-test-links.org][Org Tests for Links]]

** TODO Define OrgLink and create DB table

Goal:
Define an internal link model.

Possible fields:

- ~file_id~
- ~heading_id~
- ~link_type~
- ~raw_link~
- ~target~
- ~target_absolute~
- ~description~
- ~format~
- ~search_option~
- ~relation~
- ~byte_start~
- ~byte_end~
- ~line_number~

Acceptance criteria:

- Link model is independent of Orgize.
- DB table is created.
- Links can be deleted and reinserted per file.
- Links outside regular headings are attached to the level 0 heading.
- Link source fields are separated from resolved target fields.
- Link target foreign keys use deliberate ~ON DELETE SET NULL~ behavior.

* Phase 4: Link resolution

Goal of this phase:
Resolve links to known files, headings, IDs, and CUSTOM_IDs.

** TODO Resolve ID and CUSTOM_ID links

Goal:
Resolve ~id:~ and custom-id links by matching them against properties in the DB.

Acceptance criteria:

- ~id:~ links are assigned ~resolved_heading_id~ where possible.
- ~CUSTOM_ID~ links are assigned ~resolved_heading_id~ where possible.
- Broken links are marked.
- Ambiguous IDs are reported as diagnostics.
- Properties indexes for ~ID~ and ~CUSTOM_ID~ are used or checked.

** TODO Resolve file and attachment links

Goal:
Map ~file:~ and ~attachment:~ links to known files.

Acceptance criteria:

- Relative paths are interpreted relative to the source file.
- Known files are linked through ~resolved_file_id~.
- Missing files are marked as broken.
- Link rows are not deleted when a target file disappears; target references are set to NULL or marked broken.

* Phase 5: Query engine and optional full-text search

Goal of this phase:
Build a simple, safe query layer that can later be extended toward org-ql-like behavior. It would actually be cool to make it exactly like org-ql, the query language. And extend if org-ql does not support it.

FTS5 is optional and must only be required when FTS-specific functionality is enabled.

** TODO Enable optional SQLite FTS5 for full-text search

Goal:
Create and maintain a virtual FTS5 table for heading title and optional body search when FTS5 is enabled in configuration.

Planned table if enabled:

#+begin_src sql
CREATE VIRTUAL TABLE heading_fts
USING fts5(
    title,
    body,
    tokenize = 'unicode61'
);
#+end_src

Acceptance criteria:

- FTS5 support is configurable through ~search.fts5_enabled~.
- If FTS5 is disabled, rebuild works without creating or writing ~heading_fts~, unless the project explicitly documents that the table is always created but unused.
- If FTS5 is enabled, ~heading_fts~ is created and maintained.
- ~heading_fts.rowid~ matches ~headings.id~.
- Heading titles are indexed when FTS5 is enabled.
- Heading body text is indexed only when both ~search.fts5_enabled~ and ~search.index_body_text~ are enabled.
- Search can match title-only, body-only, or both when enabled.
- Body indexing can be disabled even when FTS5 is enabled.
- Search/query commands handle disabled FTS5 clearly.

** TODO Define query model v0

Initially supported operators:

#+begin_src lisp
(todo "NEXT")
(todo-type "open")
(tags "tag")
(title-contains "search term")
(text-contains "search term")
(link-type "file")
(has-property "ID")
(property "KEY" "VALUE")
(deadline ...)
(scheduled ...)
(ancestor ...)
(descendant ...)
#+end_src

Acceptance criteria:

- Query AST is defined.
- Unsupported operators produce understandable errors.
- Query model is independent of CLI and SQL.
- Query model can use ~outline_path~ for hierarchy queries.
- Query model can use FTS5 for title/body search when FTS5 is enabled.
- Query model has documented fallback/error behavior for FTS-dependent operators when FTS5 is disabled.

** TODO Build query parser and SQL translator

Goal:
Parse query strings and translate them safely to SQL using bound parameters.

Acceptance criteria:

- No string concatenation with user input in SQL.
- Bound parameters are used.
- Invalid query syntax produces understandable error messages.
- Tests exist for all supported operators.
- FTS5 MATCH queries are handled safely and deliberately.
- FTS-dependent SQL is generated only when FTS5 is enabled.
- Hierarchy queries use ~outline_path~ where appropriate.

** TODO Implement CLI command `query`

Example:

#+begin_src shell

Acceptance criteria:

- Query outputs JSON.
- Query uses the DB layer, not the parser.
- Simple combinations can be added later.
- Query results include enough location data for editor jumps.
- If a query requires FTS5 while FTS5 is disabled, the CLI returns a clear error.

** TODO Provide CLI command `search`

Goal:
Provide a simple FTS-focused command before or alongside the full query language.

Example:

#+begin_src shell
orgfdb search --json sqlite
#+end_src

Acceptance criteria:

- Search uses ~heading_fts~ only when ~search.fts5_enabled~ is enabled.
- If FTS5 is disabled, the command returns a clear error or documented fallback.
- Results include heading id, file path, title, and byte_start.
- Search can optionally include body matches when ~search.index_body_text~ is enabled.
- Output is usable from Emacs.

* Phase 6: Robust initial indexer

Goal of this phase:
Turn the MVP rebuild into a robust indexer.

** TODO Recursive file discovery (`find_org_files`)

** TODO Add change detection

Goal:
Avoid reparsing unchanged files unnecessarily.

Signals:

- ~mtime_ns~
- ~size~
- ~content_hash~

Acceptance criteria:

- Unchanged files are skipped.
- Changed files are parsed again.
- ~mtime_ns~ and ~size~ are used as a fast check.
- ~content_hash~ is used when stronger verification is needed.
- Explicitly document what goes into ~content_hash~ (e.g., pure file content bytes, excluding metadata) to ensure stable deduplication. Tending to use file contents only.
- Deleted files are removed from the DB or marked as missing.

** TODO Optimize transaction batching

Goal:
Index multiple files efficiently without losing database consistency.

Acceptance criteria:

- Batch size is configurable or sensibly fixed.
- Error strategy is defined.
- DB remains consistent even on interruption.
- Derived/cache tables are kept consistent with core rows.
- Optional FTS rows are kept consistent only when FTS5 is enabled.

** TODO Evaluate parallelization with Rayon

Goal:
Parallelize parsing while keeping DB writes controlled, either serial or batched.

Note:
Define performance targets only after benchmarking. The earlier target "5,000 files in < 1 second" is too risky as a hard initial target and should only be made concrete after measurements.

Acceptance criteria:

- Benchmark baseline exists.
- Parsing and DB writing are cleanly separated.
- There are no race conditions while writing.
- DB writes remain transactional and deterministic.

** TODO Optimize SQLite indexes

Goal:
Speed up common queries.

Acceptance criteria:

- Important indexes are defined.
- ~EXPLAIN QUERY PLAN~ was checked for typical queries.
- Typical queries include TODO, tags, properties, links, planning, outline/subtree lookups, and FTS if enabled.
- Results are documented.

** TODO Evaluate SQLite query performance

Goal:
Check whether the current SQLite schema is fast enough for the intended query workload.

Note:
The project is query-oriented, but a separate data warehouse is probably unnecessary unless measurements show a real bottleneck.

Acceptance criteria:

- Benchmark data set is defined.
- Common queries are measured.
- FTS query performance is measured when FTS5 is enabled.
- Materialized path subtree queries are measured.
- Findings are documented.
- Schema changes are based on measurements, not assumptions.

** TODO Selective reparse

Goal:
When a file changes, reparse exactly the affected file through the parser adapter and replace it in the DB through a transaction.

Acceptance criteria:

- Only the affected file is reindexed.
- Old headings, TODO keywords, tags, keywords, properties, timestamps, links, bodies, outline rows, and FTS rows for the file are replaced where applicable.

- Level 0 heading is recreated consistently.
- Selective reparse works when FTS5 is disabled.
- Selective reparse updates FTS rows when FTS5 is enabled.
