* Planning

** Problem summary
The repository has a single local quality gate in ~make ci~, but GitHub does not currently run it automatically for pushes or pull requests.

** Goals
- Add a minimal GitHub Actions workflow for pushes and pull requests.
- Use the stable Rust toolchain with the components required by the existing ~make ci~ target.
- Keep ~make ci~ as the single definition of CI checks.

** Non-goals
- Do not duplicate Makefile checks in the workflow.
- Do not change the Makefile.
- Do not add caching, release, packaging, or deployment jobs.

** Architecture
Use one GitHub-hosted Ubuntu job that checks out the repository, installs stable Rust with Clippy and rustfmt, and runs ~make ci~.

** Execution plan
1. Add ~.github/workflows/ci.yml~.
2. Trigger it on ~push~ and ~pull_request~.
3. Give the workflow read-only repository contents permission.
4. Install stable Rust with ~clippy~ and ~rustfmt~.
5. Run only ~make ci~ as the repository quality gate.

** Risks & assumptions
- GitHub-hosted ~ubuntu-latest~ includes GNU Make and the system tools already required by the project.
- Rust CI itself is not executed in this environment, per user instruction.

** Open questions
None.
