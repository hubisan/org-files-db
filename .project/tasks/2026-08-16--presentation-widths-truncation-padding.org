* Planning

** Problem summary

The presentation pipeline extracts values and sorts rows. It does not prepare shared display widths or final cell text yet.

** Goals

- Calculate one shared width for each displayed column.
- Support ~auto~, ~max~, and ~fixed~ width modes.
- Support left, middle, and right truncation.
- Support custom and empty truncation markers.
- Pad final cell text to the shared column width.
- Preserve the complete logical value in ~search_text~.
- Keep Unicode text on valid character boundaries.

** Non-goals

- Do not add percentage widths.
- Do not add free-text search.
- Do not add row expansion.
- Do not emit the final ~presentation-json~ response.
- Do not add a new dependency for display width calculation.

** Architecture

Add a layout stage after row sorting.

The stage extracts displayed values for all rows first. It then calculates shared column widths from the complete row set.

Use Unicode scalar values for width calculations. This keeps slicing deterministic and avoids UTF-8 byte boundaries.

Use the default right truncation with ~…~ when a constrained width needs truncation and no custom truncation object exists.

Keep each complete extracted value in ~search_text~. Store only truncated and padded text in ~display_text~.

** Execution plan

1. Add a Rust layout error type.
2. Extract all displayed cell values before width calculation.
3. Calculate shared widths for ~auto~, ~max~, and ~fixed~.
4. Add left, middle, and right truncation helpers.
5. Count the marker inside the target width.

** Risks & assumptions

- Width counts Unicode scalar values, not UTF-8 bytes.
- The layout stage preserves row order.
- ~fixed~ always uses its configured width.
- ~max~ never exceeds its configured value.
- Missing values use an empty ~search_text~ and receive normal padding.
