Add the watcher CLI command and Unix process lifecycle over the completed watcher runtime.

* Planning

** Problem summary

The watcher runtime can register filesystem watches, run startup reconciliation, process bounded batches, and terminate on fatal recovery failures, but it has no user-facing command or Unix signal-driven lifecycle. The CLI must start the existing runtime, remain silent during routine activity, flush pending work on shutdown, and return stable non-zero status for fatal failures without changing existing JSON commands.

** Goals

- Add ~orgfdb watch --config PATH~ using the same configuration and database schema selection as Phase 6.
- Install safe ~SIGINT~ and ~SIGTERM~ handling on supported Unix platforms.
- Report readiness only after startup reconciliation succeeds.
- Stop accepting new events on shutdown and flush already pending work through the controller policy.
- Keep routine activity silent and send lifecycle messages to stderr only.
- Return exit code ~1~ for signal registration, startup, watch registration, runtime, and Phase 6 execution failures.
- Add deterministic lifecycle tests without sending real process signals.

** Non-goals

- No daemonization, service files, background process management, structured event stream, configurable debounce flag, automatic restart, Windows support, or end-to-end watcher scenario matrix.
- No changes to discovery, batching, parsing, DB mutation, FTS, link resolution, or retry semantics.

** Architecture

- Add a small internal ~watcher_cli~ module that owns signal registration and the production event loop.
- Poll the existing non-blocking watcher runtime with a bounded idle interval and sleep only until the earlier of the debounce deadline or signal-poll boundary.
- Add runtime wrappers for beginning shutdown and detecting completion; after shutdown starts, source intake is skipped and only already pending work is flushed.
- Keep the command stdout empty. Readiness, stopping, and stopped messages go to stderr.
- Use an injectable clock and shutdown request in tests so idle shutdown and pending flush are deterministic without sleeps.

** Execution plan

- Add the Unix signal dependency and module registration.
- Extend the watcher runtime with shutdown wrappers and no-new-input processing during shutdown.
- Add the ~watch~ Clap command and error mapping.
- Implement the production lifecycle loop and deterministic fake-source tests.
- Update CLI and incremental-indexing documentation.
- Set the task to ~REVIEW~ after static checks and available test execution.

** Risks & assumptions

- Signal flags are checked at a bounded interval, so idle shutdown latency is limited by the fixed poll interval rather than an unbounded backend wait.
- A signal received during synchronous startup reconciliation is retained and handled immediately after startup completes.
- Fatal runtime failures remain terminal and are not retried by the CLI.
