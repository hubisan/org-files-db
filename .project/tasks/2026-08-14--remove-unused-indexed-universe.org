Remove the obsolete ~indexed_universe~ value transported from change planning into application while preserving rediscovery, stale-plan checks, and link resolution behaviour.

* Planning

** Problem summary
~ChangePlan~ stores the discovery-time ~IndexedUniverse~ only so ~ActionableChangePlan~ can extract it. Application discards that value and resolves links with the fresh ~rediscovery.indexed_universe~, making the transported value obsolete.

** Goals
- Remove the obsolete ~indexed_universe~ field from the change plan/actionable-plan path.
- Simplify conversion to an actionable plan accordingly.
- Preserve fresh rediscovery, stale-plan validation, and link resolution using the rediscovered universe.
- Remove rejection logic that exists only because the obsolete field was optional.

** Non-goals
- Do not alter discovery or rediscovery behaviour.
- Do not weaken stale-plan checks.
- Do not change link resolution behaviour.
- Do not remove unrelated dead-code allowances.

** Architecture
Keep ~ActionableChangePlan~ as the single-use mutation-boundary wrapper, but make it contain only ~ChangePlan~. ~TryFrom<ChangePlan>~ continues to reject failed-source plans and no longer validates presence of an unused universe. Application continues to call ~discover_org_files~ and passes ~rediscovery.indexed_universe~ to ~LinkResolver::resolve_all~.

** Execution plan
1. Remove ~indexed_universe~ from ~ChangePlan~ construction and storage.
2. Remove it from ~ActionableChangePlan~ and simplify ~TryFrom<ChangePlan>~.
3. Remove the now-obsolete ~InvalidPlan~ rejection variant and watcher display arm.
4. Verify rediscovery and link resolution still use the fresh universe and review the diff for scope.

** Risks & assumptions
- ~InvalidPlan~ is only reachable when the optional transported universe is missing; repository search confirms it has no other producer.
- Existing indexer tests cover actionable-plan application, stale-plan rejection, and link resolution behaviour.

None.
