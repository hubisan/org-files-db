Implement the plan for resolving effective property values for query matching.

* Planning

** Problem summary

Property rows are stored losslessly, but query matching still needs one resolved effective value per key that follows Org overwrite, append, and inheritance behavior.

** Goals

- Keep raw property storage unchanged.
- Resolve effective property values consistently for heading and file/root property matching.
- Expose resolved values separately from raw stored property rows.
- Update the CLI and reference docs for the new output contract.

** Non-goals

- No schema changes.
- No precomputed effective-property table.
- No change to the existing raw ~properties~ include.

** Architecture

- Add one shared Rust resolver for local overwrite/append semantics plus optional inheritance.
- Use the same semantics in SQLite property predicates and result shaping.
- Add a distinct ~effective_properties~ include so raw and resolved facts stay separate.

** Execution plan

- Implement the shared property resolver and unit tests.
- Switch SQLite property matching to resolved effective values.
- Extend shaped query results with ~effective_properties~.
- Update CLI/docs/tests and run the preferred checks.

** Risks & assumptions

- Inherited append-only local values must extend the inherited base when ~:inherit t~.
- Descendants inherit resolved parent values unless a later local non-append definition overrides them.
