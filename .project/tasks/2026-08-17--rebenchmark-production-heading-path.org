* Planning

** Problem summary

The production direct-flat heading path loader now uses the Rust-driven bulk ancestor strategy.

The isolated path benchmark shows that this strategy is faster than the recursive query-derived loader.

The production workload still needs an end-to-end measurement after the switch.

** Goals

- Measure production ~headings.path~ at 100, 1'000, 10'000, and 50'000 results.
- Compare the new run with the pre-switch benchmark from the same machine and SQLite environment.
- Record total latency, SQL statements, row transfer, SQL execution, row decoding, Rust processing, and final shaping.
- Confirm that the isolated path improvement reduces complete production latency.
- Update ~docs/query-sql-performance.org~ with the measured result.

** Non-goals

- Do not change production query behavior in this task.
- Do not change the benchmark protocol unless the existing output is insufficient.
- Do not add another path strategy.
- Do not change public query output.
- Do not add dependencies.

** Architecture

Use the existing schema version ~4~ SQL benchmark without code changes.

The normal ~headings.path~ workload calls the production query path and records complete query latency.

Its direct phase profile already records SQL execution, row decoding, Rust processing, and final shaping.

Use ~total_query_time~ for the latency comparison because phase instrumentation runs in a separate sample.

Use the schema version ~3~ pre-switch run as the A/B baseline.
