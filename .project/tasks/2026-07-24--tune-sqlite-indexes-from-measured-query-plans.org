* Original Task (User only)

Tune SQLite indexes from measured query plans.

* Planning

** Problem summary

- Compare each index candidate against the unchanged version-8 schema, then compare a combined candidate profile before changing persistent schema.

** Goals

- Preserve production query semantics and record reproducible planner, read, storage, rebuild, and incremental-write evidence.

** Non-goals

- FTS virtual-table tuning and query compiler changes.

** Architecture

- The benchmark runner creates fresh profile databases using the production schema/rebuild path and rejects incomparable results.

** Execution plan

- Add profile, inventory, statistics, incremental-sequence, and comparison evidence to the benchmark runner.
- Run individual and combined candidates; change the persistent schema only for accepted evidence.

** Risks & assumptions

- A candidate remains rejected unless repeatable evidence supports it; raw machine results stay untracked.

** Proposed checks

- ~make ci~ and a release benchmark smoke run.

* Results

** Approach

- Added isolated fresh source copies per FTS/profile run, detailed SQLite index inventories, per-index dbstat evidence when available, and one deterministic incremental sequence using the production change planner and transactional application path.
- Read workloads run on the unchanged rebuilt database before the incremental sequence. Every operation validates its planned classifications before becoming actionable and records exact counts, separate planning/application timings, and DB/WAL sizes.
- The final incremental database is compared with a clean rebuild of the final corpus using the same FTS mode and profile. The snapshot excludes operational IDs and ~indexed_at~ while preserving canonical tables and trust metadata; FTS shadow tables are not canonical facts.
