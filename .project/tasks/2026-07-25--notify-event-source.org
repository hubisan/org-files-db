Integrate ~notify~ as the thin filesystem event source for the completed Phase 7 watcher event model and execution controller.

* Planning

** Problem summary

Phase 7 has a backend-independent event model and deterministic execution controller but no operating-system event source. The adapter must register the configured Phase 6 inputs, preserve all available path hints, report backend failures, and request reconciliation under uncertainty without duplicating discovery or indexing semantics.

** Goals

- Add a compatible ~notify~ dependency.
- Watch configured directory roots with their declared recursion mode.
- Watch explicit-file parents non-recursively so atomic replacement remains observable.
- Translate ~notify~ events into existing backend-independent ~WatcherInput~ values.
- Preserve complete rename path order and pass incomplete renames through for conservative reconciliation.
- Convert rescan indications and runtime backend errors into reconciliation recovery signals.
- Report watcher creation, inaccessible target, registration, and channel failures with path context.
- Add synthetic translation and target-planning tests plus one real supported-backend integration test.

** Non-goals

- No startup reconciliation, retry policy, long-running event loop, CLI command, signal handling, or daemonization.
- No watcher-owned discovery, exclusions, canonicalization, parsing, DB classification, or mutation.
- No Windows-specific code or compatibility layer.
- No use of a separate debounce crate; the existing controller remains authoritative.

** Architecture

- Add an internal ~notify_source~ module beside the backend-independent ~watcher~ module.
- Build a deterministic set of watch targets from configured roots and explicit-file parents.
- Collapse duplicate or covered targets before registering them with ~RecommendedWatcher~.
- Keep the watcher alive inside ~NotifyWatcherSource~ and receive raw ~notify::Result<Event>~ values through a standard channel.
- Translate events at the receive boundary and leave source-universe filtering to ~WatcherBatchNormalizer~.
- Represent runtime backend failures separately so callers can report them and submit their dropped-events recovery input.

** Execution plan

- Add ~notify~ 8.2 to the dependency set.
- Implement watch-target planning, validation, deduplication, and registration.
- Implement event and backend-error translation.
- Add non-blocking and timeout receive operations for later lifecycle integration.
- Add deterministic unit tests and a bounded real-backend integration test.
- Document the adapter contract and update active task state.

** Risks & assumptions

- Backend event counts, ordering, and precise kinds differ across supported platforms; the integration test asserts eventual normalized path observation only.
- Runtime backend errors may not identify a platform-specific overflow kind uniformly, so every stream error is reported and conservatively treated as possible event loss.
- The existing Phase 6 normalizer remains responsible for exclusions, source-universe membership, deleted identities, symlinks, and unrelated paths.
