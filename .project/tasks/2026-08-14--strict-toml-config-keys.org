* Planning

** Problem summary
The raw TOML configuration structs currently ignore unknown fields, so misspelled keys can silently leave defaults in effect.

** Goals
- Reject unknown top-level configuration keys.
- Reject unknown keys in nested config tables and directory entries.
- Add focused tests for a top-level typo and a nested ~[search]~ typo.
- Document that unknown configuration keys are rejected.

** Non-goals
- Do not rename keys or change defaults.
- Do not change configuration semantics beyond rejecting unknown keys.
- Do not introduce a new configuration format.

** Architecture
Use Serde's existing ~deny_unknown_fields~ support on every user-facing raw configuration struct. Keep the existing ~ConfigError::ParseToml~ path so callers receive normal TOML/config parsing errors.

** Execution plan
1. Add ~#[serde(deny_unknown_fields)]~ to all raw config structs.
2. Add regression tests for unknown top-level and nested ~[search]~ keys.
3. Update the config reference with strict unknown-key behavior.

** Risks & assumptions
- Existing valid TOML remains unchanged.
- Previously ignored unknown keys will intentionally become parse errors.
- Rust CI is run by the user rather than in this environment.

** Open questions
None.
