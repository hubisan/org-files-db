* Planning

** Problem summary
File links currently stop at ~target_file_id~ when they resolve to a known file without a search option, which leaves document-level links without a synthetic-root ~target_heading_id~.

** Goals
- Add a resolver fallback for file-only links that points ~target_heading_id~ at the target file's synthetic root heading.
- Preserve current precedence so heading-title, CUSTOM_ID, ID, broken, unresolved, and unsupported outcomes do not regress.
- Cover both direct resolver behavior and rebuild-level supported file-link forms with tests.

** Non-goals
- Creating synthetic root headings.
- Changing parser semantics or search-option resolution rules.
- Changing non-file link resolution behavior.

** Architecture
Extend the file-link resolution path in ~src/link_resolver.rs~ so the fallback runs only for already-resolved file links with no ~search_option~. Load synthetic root candidates from persisted headings using the existing root contract (~level = 0~, ~parent_id IS NULL~) and keep more specific heading-target resolution unchanged.

** Execution plan
- Add synthetic-root lookup and root-target assignment in the file-link resolver path.
- Add deterministic handling for missing or duplicate synthetic root rows.
- Add unit tests in ~src/link_resolver.rs~ and a rebuild integration test in ~src/indexer.rs~.
- Update repository docs if resolver behavior descriptions changed.
- Run ~make ci~ and record results.

** Risks & assumptions
- Assumption: persisted synthetic root rows always use the documented contract of ~level = 0~ and ~parent_id IS NULL~.
- Risk: rebuild-level assertions need to account for the synthetic root title coming from the indexed root-heading title contract rather than always mirroring a fixture helper path string.
