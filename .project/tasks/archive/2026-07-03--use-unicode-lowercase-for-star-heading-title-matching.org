* Planning

** Problem summary
- The current resolver relies on SQLite =COLLATE NOCASE= for star heading-title matching.
- That keeps ASCII behavior but misses Unicode pairs such as =Ärger= versus =ärger=.

** Goals
- Keep the existing star target normalization unchanged.
- Load headings in deterministic document order and compare in Rust using Unicode lowercase.
- Preserve current first-match duplicate behavior and raw link fields.

** Non-goals
- No full Unicode casefolding.
- No =ß= versus =ss= equivalence.
- No changes to =CUSTOM_ID=, =ID=, parser extraction, or schema.

** Architecture
- Replace the SQL exact-match query with ordered candidate loading scoped to one file.
- Filter those candidates in Rust with =to_lowercase()= on both the normalized target and stored heading title.

** Execution plan
- Update the resolver helper/query path.
- Add unit coverage for Unicode case-insensitive matching in both file and same-file star resolution.
- Extend rebuild tests with =Ärger= / =ärger= fixtures.
- Run formatter, focused tests, and =make ci=.
