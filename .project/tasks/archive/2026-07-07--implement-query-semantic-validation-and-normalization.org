* Planning

** Problem summary
The repository now has a structural query parser and canonical ~tags-all~ parser normalization, but it still lacks a semantic validation layer that checks Query Model v0 target compatibility, arity, options, canonical predicate behavior, and pre-execution capability failures.

** Goals
- Add a validator that consumes parsed ~QueryAst~ and returns a dedicated validated representation.
- Reject semantically invalid v0 queries clearly.
- Keep validated queries implementation-independent and SQL-free.
- Add coverage for successful and failing validation paths.

** Non-goals
- SQL translation
- DB access or execution
- CLI behavior
- JSON shaping
- FTS implementation or body indexing changes

** Architecture
- Add ~src/query/validate.rs~ with validated query types, validation options, and validation error types.
- Re-export validation types and ~validate_query~ from ~src/query.rs~.
- Keep parser syntax tests separate from validator tests.

** Execution plan
- Add validated query/error/options types.
- Implement recursive semantic validation for all v0 predicate families.
- Add success and error integration tests, including parse+validate canonical ~tags-all~ coverage.
- Run focused query tests and full CI.

** Risks & assumptions
- The validator should treat parser-normalized ~tags-all~ as canonical ~tags ... :match :all~.
- Optional ~source :any~ and ~target :any~ are supported because the parser already exposes them.
- Capability checks are limited to explicit v0 needs in this task.

** Open questions
- None at implementation start.

* Results

** Approach
- Added ~src/query/validate.rs~ as the semantic validation layer that runs on parsed ~QueryAst~ before any later SQL work.
- Introduced dedicated validated query types:
  - ~ValidatedQuery~
  - ~ValidatedExpr~
  - ~ValidatedPredicate~
  - ~ValidatedArg~
  - ~ValidatedOption~
- Added explicit validation inputs via ~QueryValidationOptions~ with only the approved capability flags:
  - ~body_text_available~
  - ~regexp_body_matching_supported~
- Kept parser and validator failure domains separate by introducing:
  - ~QueryValidationErrorKind~
  - ~QueryValidationError~
- Implemented recursive semantic validation for the current Query Model v0 predicate families in this phase:
  - heading predicates
  - link predicates
  - file predicates
  - hierarchy predicates
  - relation predicates
- Made option validation predicate-aware and target-aware, especially for:
  - ~tags~
  - ~property~
  - ~keyword~
  - inheritance-related options on headings vs files
- Treated parser-normalized ~tags-all~ as canonical ~tags ... :match :all~ and added parse+validate coverage for that path.
- Added explicit semantic checks for:
  - unsupported predicates such as ~tags-regexp~
  - target/predicate compatibility
  - predicate arity
  - unknown options
  - invalid option combinations such as ~:regexp t~ with ~:exact t~
  - invalid ~:match~ values
  - recursive nested relation query validation
  - ~has-text~ capability failures for missing body text and missing regexp body support
