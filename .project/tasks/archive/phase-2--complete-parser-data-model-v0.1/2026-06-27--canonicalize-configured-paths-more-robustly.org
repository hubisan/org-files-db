* Planning

** Problem summary
Config loading currently validates source paths too early, while rebuild discovery still relies on syntactic path forms that miss =..= and symlink-equivalent duplicates.

** Goals
- Keep config loading permissive for missing sources.
- Make rebuild/indexing validate and canonicalize source paths before discovery.
- Preserve read-only DB queries as non-mutating and source-path agnostic.

** Non-goals
- Do not change parser semantics.
- Do not change DB schema or JSON contracts.
- Do not redesign configuration fields.

** Architecture
- Config loading resolves paths syntactically against the config file location.
- Rebuild discovery canonicalizes configured files and directories before scanning.
- Discovery deduplicates on canonical paths so equivalent configured inputs collapse to one file row.

** Execution plan
1. Remove source existence validation from config loading.
2. Canonicalize configured files and directories during rebuild discovery.
3. Update path-related tests to cover missing-source permissiveness and rebuild-time validation.
4. Document the path policy in README.

** Risks & assumptions
- Canonicalization may change stored file paths to filesystem-canonical absolute paths; that is acceptable and preferred for deduplication.
- Read-only commands should continue to work as long as the DB exists, even if configured source paths do not.
