** DONE [2026-06-23 Tue 21:53] Parse direct heading tags and FILETAGS as normalized tag facts

Goal:
Define and implement the tag storage contract for direct Org heading tags and file-level ~#+FILETAGS~.

This task should store direct tag facts in the normalized ~tags~ table and keep inherited/effective tag computation in ~headings.all_tags_json~.

Context:
~headings.all_tags_json~ already computes effective visible tags for headings, including inherited parent tags, duplicate removal, and deterministic ordering. This existing logic must be preserved.

~#+FILETAGS~ are also raw Org keyword lines. Raw keyword storage must remain unchanged: ~#+FILETAGS~ must continue to be stored as raw rows in the ~keywords~ table on the synthetic level 0 heading.

Preferred design:
- ~tags~ stores direct tag facts only.
- Direct heading tags are stored on their actual heading.
- File-level tags from ~#+FILETAGS~ are stored as direct tag facts on the synthetic level 0 heading.
- ~headings.all_tags_json~ stores effective/visible tags for each heading.
- Do not materialize inherited tag rows into ~tags~ unless planning finds a strong reason to keep that design.
