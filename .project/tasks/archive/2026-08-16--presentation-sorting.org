* Planning

** Problem summary

The presentation model can extract typed logical values, but presentation rows do not have a Rust sorting stage yet.

The sort specification already uses the shared column registry. The implementation now needs deterministic row ordering from these definitions.

** Goals

- Sort rows by one or more declared sort keys.
- Support ascending and descending direction for each key.
- Support sort columns that are not displayed.
- Use typed logical values for comparison.
- Put missing values in a deterministic position.
- Keep equal rows in deterministic input order.
- Support future expanded rows that share one result.

** Non-goals

- Do not implement free-text search.
- Do not implement row expansion.
- Do not calculate widths.
- Do not truncate or pad cells.
- Do not emit the final ~presentation-json~ response.
- Do not add a second sort-column registry.

** Architecture

Extract all sort keys once for each row before sorting.

Use ~PresentationSpec::extract_value~ so displayed and hidden sort columns share the same registry and value extraction.

Compare integers numerically. Compare text, lists, and outline components with deterministic lexicographic order.

Put missing values after present values for both sort directions.

Use the incoming row position as the final tie key. This keeps equal values deterministic without changing result identity.

** Execution plan

1. Add a row sorting stage to ~PresentationSpec~.
2. Extract typed sort keys once for each row.
3. Add deterministic comparison rules for each logical value type.
4. Apply sort rules in declared order.
5. Preserve incoming row order for complete ties.
6. Add tests for hidden keys, multiple keys, missing values, and row contexts.
7. Update the presentation design documentation.
8. Archive the previous completed task file.

** Risks & assumptions

- Missing values sort after present values in both directions.
- Text sorting is case-sensitive.
- Outline sorting compares components. The display separator does not affect order.
- Query results and row construction provide deterministic incoming row order.
