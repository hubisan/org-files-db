Goal:

- Implement the already accepted and documented ~:regexp t~ mode for the remaining SQLite metadata predicates:
  - ~has-text~
  - ~tags~
  - ~property~
  - ~keyword~
- Make parser, validation, documentation, and SQLite execution agree.
- Preserve existing non-regexp behavior.
- Reuse one consistent regexp implementation instead of adding predicate-specific matching engines.

Current behavior:

- The query parser accepts ~:regexp t~ for these predicates.
- Validation accepts the option.
- Public documentation describes the regexp mode.
- The SQLite metadata backend rejects the query during execution.

Affected forms:

#+begin_src lisp
(has-text "PATTERN" :regexp t)

(tags "PATTERN" :regexp t)

(property "KEY" "PATTERN" :regexp t)

(keyword "KEY" "PATTERN" :regexp t)
#+end_src

Typical current error:

#+begin_src text
predicate property with :regexp t is not supported by the SQLite metadata backend
#+end_src

Scope:

- Implement regexp matching for:
  - heading body text through ~has-text~
  - tag values through ~tags~
  - property values through ~property~
  - keyword values through ~keyword~
- Preserve existing key matching semantics for ~property~ and ~keyword~.
- Do not silently apply regexp matching to property or keyword keys unless the public contract explicitly says so.
- Do not change inheritance semantics.
- Do not change root/file participation.
- Do not change raw indexing or database schema.

Shared regexp semantics:

- Use the same regexp engine and options for all affected predicates.
- Define one public regexp dialect.
- Document unsupported syntax and flags.
- Matching must be deterministic.
- Invalid patterns must fail with a clear query error.
- Invalid patterns must not produce a SQLite error or panic.
- User patterns must remain bound data and must not be interpolated unsafely into SQL.

Case sensitivity:

- Preserve the existing Query Model v0 regexp case-sensitivity contract.
- If it is not yet explicitly defined, decide and document it before implementation.
- Do not inherit SQLite ~LIKE~ case behavior accidentally.
- Add tests using both uppercase and lowercase input.

Recommended contract unless existing documentation differs:

- Non-regexp matching retains the existing case-insensitive text semantics.
- Regexp matching follows the selected regexp engine's documented case behavior.
- If regexp matching is intended to remain case-insensitive, apply that explicitly rather than depending on backend defaults.

Backend design:

- Investigate whether the current SQLite connection already registers a regexp function.
- If no regexp function exists, add one shared SQLite scalar function, for example:

#+begin_src text
regexp(pattern, value) -> boolean
#+end_src

- Compile and validate patterns safely.
- Consider caching compiled patterns if the SQLite callback would otherwise compile the same expression for every row.
- Avoid unbounded cache growth.
- Convert invalid regexp patterns into a clear application-level error.
- Ensure ~NULL~ values evaluate as non-matches rather than errors.

Alternative implementation:

- A post-query in-memory matcher is acceptable only if it preserves:
  - boolean composition
  - negation
  - hierarchy relation predicates
  - root/file matching
  - pagination
  - result limits
  - deterministic ordering

- Do not fetch a broad result set and filter after applying ~limit~, because that changes query semantics.
- Prefer execution inside the SQLite predicate compiler unless a shared two-phase execution model already exists.

Predicate semantics:

*** ~has-text~

Syntax:

#+begin_src lisp
(has-text "PATTERN" :regexp t)
#+end_src

Required behavior:

- Apply the regexp to the indexed body text belonging directly to the candidate heading or root according to the existing ~has-text~ contract.
- Do not search title, properties, keywords, child text, or the complete file unless those are already part of the documented body-text field.
- A candidate matches when its indexed text contains a regexp match.
- Missing body text evaluates false.

Examples:

#+begin_src lisp
(headings
  (has-text "database.*resolver" :regexp t))

(headings
  (and
    (level > 0)
    (has-text "\\bTODO\\b" :regexp t)))
#+end_src

*** ~tags~

Syntax:

#+begin_src lisp
(tags "PATTERN"... :match :any|:all :inherit t|nil :regexp t)
#+end_src

Required behavior:

- Apply the regexp independently to complete tag values.
- Do not join all tags into one string and run the regexp across delimiters.
- Preserve ~:match :any~ and ~:match :all~ semantics.
- Preserve ~:inherit t|nil~ semantics.
- Root FILETAGS participation follows the existing heading-domain contract.

For ~:match :any~:

- At least one requested pattern must match at least one effective tag.

For ~:match :all~:

- Every requested pattern must match at least one effective tag.
- Different patterns may match different tags.

Example effective tags:

#+begin_src text
project
database
property-test
#+end_src

This matches:

#+begin_src lisp
(tags "^proj" "test$" :match :all :regexp t)
#+end_src

This does not match:

#+begin_src lisp
(tags "^missing" :regexp t)
#+end_src

*** ~property~

Syntax:

#+begin_src lisp
(property "KEY" "PATTERN" :inherit t|nil :regexp t)
#+end_src

Required behavior:

- Match the property key according to the existing normalized key semantics.
- Apply the regexp to the resolved effective property value.
- Do not apply the regexp independently to raw duplicate or append components.
- Preserve:
  - duplicate-definition resolution
  - append resolution
  - ~:inherit t|nil~
  - root/file property behavior
- A replaced raw value must not independently match.
- An individual append component must not independently match unless the complete resolved value also matches the regexp.

Example effective value:

#+begin_src text
VALUE = second appended another value
#+end_src

This matches:

#+begin_src lisp
(property "VALUE" "^second.*another value$" :regexp t :inherit nil)
#+end_src

This also matches:

#+begin_src lisp
(property "VALUE" "appended" :regexp t :inherit nil)
#+end_src

because the pattern occurs in the complete resolved value.

This does not match:

#+begin_src lisp
(property "VALUE" "^first" :regexp t :inherit nil)
#+end_src

if ~first~ was replaced by a later non-append definition.

Property existence form:

- If the predicate supports querying only for key existence without a value, keep that form unchanged.
- ~:regexp t~ must require a value pattern unless the public grammar explicitly defines regexp key matching.

*** ~keyword~

Syntax:

#+begin_src lisp
(keyword "KEY" "PATTERN" :regexp t)
#+end_src

Required behavior:

- Match the keyword key according to existing normalized key semantics.
- Apply the regexp to the effective or documented keyword value.
- Preserve duplicate-keyword and root/file behavior.
- Do not unexpectedly search keyword names with the value regexp.
- Missing keyword values evaluate false unless empty-value matching is explicitly supported.

Example:

#+begin_src lisp
(keyword "TITLE" "^Org Property.*Test$" :regexp t)
#+end_src

Example for an empty value:

#+begin_src lisp
(keyword "KEYWORD_EMPTY" "^$" :regexp t)
#+end_src

- Verify and document whether empty indexed keyword values match ~^$~.

* Planning

** Problem summary

- The query language and docs already accepted ~:regexp t~ for several metadata predicates, but the SQLite backend still rejected many of them during compilation or execution.
- The remaining gap covered not only ~has-text~, ~tags~, ~property~, and ~keyword~, but also other open SQLite regexp cases the user explicitly asked to finish in one pass.

** Goals

- Implement SQLite regexp matching for the remaining metadata predicates with one shared backend mechanism.
- Preserve existing non-regexp semantics, root/file participation rules, inheritance behavior, and SQL parameter binding.
- Keep validation, compiler behavior, execution tests, and documentation aligned.

** Non-goals

- No query-language syntax changes.
- No schema migration.
- No changes to FTS-specific behavior.

** Architecture

- Register one SQLite scalar function backed by Rust ~regex~ compilation and a small per-connection cache.
- Reuse existing text predicate compilation paths where possible instead of adding predicate-specific regexp engines.
- Validate regexp patterns before SQL execution so invalid patterns fail clearly and deterministically.

- Finish SQLite regexp support for inherited tag matching and remaining metadata/text predicate compilers.

- Update public docs for the supported regexp behavior and SQLite regexp semantics.

- SQLite regexp support must stay parameterized so injection-like patterns cannot affect SQL structure.
- Regexp matching should stay case-sensitive, matching Rust regex defaults, while non-regexp matching remains case-insensitive where previously documented.
