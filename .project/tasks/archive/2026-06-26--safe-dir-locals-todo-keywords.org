* Planning

** Problem summary
The project already resolves effective per-file TODO keywords before parsing, but it has no safe external resolver for ~.dir-locals.el~ defaults.

** Goals
- Add config-gated, data-only ~.dir-locals.el~ TODO keyword support outside the parser.
- Keep Org in-buffer TODO declarations as highest precedence.
- Store effective provenance with ~source_kind = dir_locals~ when directory locals provide the defaults.

** Non-goals
- No Emacs file-local variables.
- No ~.dir-locals-2.el~.
- No full Emacs Lisp reader or evaluator.
- No parser-side filesystem access.
- No separate ~todo_keyword_sources~ table.

** Architecture
- Add a dedicated resolver module outside the parser.
- Extend config with typed ~parse.dir_locals~ settings.
- Extend TODO keyword resolution to accept a default source kind.
- Integrate resolver use in the indexer before parsing each file.

** Execution plan
1. Add typed parse config for directory locals and tests for parsing/defaults.
2. Add a strict, data-only ~.dir-locals.el~ parser/resolver plus focused unit tests.
3. Wire the resolver into the indexer with bounded root lookup and effective provenance.
4. Extend schema constraints for ~source_kind = dir_locals~.
5. Add end-to-end indexer tests for enabled, disabled, inheritance, precedence, and provenance.

** Risks & assumptions
- The safest minimal reader is a tiny parser for the supported literal subset, not a general Lisp parser.
- For explicitly configured files, ancestor search should stop at the file's parent directory unless the file also falls under a configured directory root.
- Unsupported forms should produce warnings or hard errors only when directory-local parsing is enabled.
