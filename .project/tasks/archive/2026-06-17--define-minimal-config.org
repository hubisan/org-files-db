** BUILD Define minimal config

Implement the task **Define minimal config**.

Scope:
Create the minimal project configuration model and config loading behavior needed for the Phase 1 end-to-end slice.

Implement only what is needed for this task. Do not implement the indexer, DB schema, CLI commands, parser adapter changes, or file discovery beyond what is necessary to validate config paths.

Required config fields:

* `db_path`
* `files: Vec<PathBuf>`
* `dirs: Vec<PathBuf>`
* `recursive: bool`
* `todo.default_open_keywords: Vec<String>` with default `["TODO"]`
* `todo.default_closed_keywords: Vec<String>` with default `["DONE"]`
* `search.fts5_enabled: bool` with initial default `true`
* `search.index_body_text: bool` with initial default `false`

Requirements:

1. Add a parser-backend-independent config module/type.
2. Config must be loadable from a file.
3. Use clear defaults for omitted optional fields.
4. Handle relative and absolute paths deliberately.

   * Relative paths in the config should be resolved relative to the config file location, unless the repository already has a different established convention.
   * Document the chosen behavior in code comments or docs.
5. Missing files or directories must produce understandable errors.
6. Org-mode TODO defaults must be available:

   * open: `TODO`
   * closed: `DONE`
7. Custom project-level TODO defaults must be configurable.
8. Add a minimal model for configured TODO defaults, but do not implement the full TODO keyword model task yet.
9. Config must include FTS5 enable/disable and body text indexing settings.
10. `search.index_body_text` must be independent from `search.fts5_enabled`, but validation should reject or clearly report impossible/unsupported combinations if the implementation chooses that behavior.
11. Config must not expose Orgize-specific or parser-backend-specific details.
12. Add tests for:

    * loading a minimal config
    * default TODO keywords
    * custom TODO keywords
    * relative path resolution
    * missing file or directory errors
    * FTS5/body-indexing config values

Keep the implementation small and focused. Prefer simple, explicit types over premature abstraction.

After implementation:
