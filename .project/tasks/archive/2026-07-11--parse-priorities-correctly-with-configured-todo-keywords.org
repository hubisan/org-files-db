* Planning

** Problem summary
Orgize currently parses headings with its default TODO keyword set unless the adapter passes the effective configured TODO keywords into the parser. For configured keywords like ~PLAN~, ~NEXT~, or ~REVIEW~, Orgize can miss the priority cookie, causing ~priority~ to stay empty even though fallback TODO inference later recognizes the keyword.

** Goals
- Make priority parsing work for headings that use effective configured TODO keywords.
- Keep the fix scoped to parser behavior for TODO keyword recognition and priority extraction.
- Preserve the current contracts for ~priority~, ~title_raw~, and TODO type output.

** Non-goals
- separate statistics-cookie normalization work
- unrelated parser refactors
- query, DB schema, or CLI behavior changes

** Architecture
- Update the Orgize adapter to build the parser with the effective TODO keyword lists from ~ParseOptions.todo_keywords~.
- Keep ~parse_document()~ as the resolver of file-local and configured TODO keywords, and let ~parse_document_core()~ consume that resolved configuration.
- Use regression tests in the adapter layer to prove the failure before the parser change and the fix after it.

** Execution plan
- Add regression tests for configured project TODO keywords and file-local TODO sequences that include priority cookies.
- Run focused tests to confirm the new regressions fail before changing parser construction.
- Change the adapter parser construction to pass the effective open and closed TODO keyword lists into Orgize.
- Re-run focused tests and then ~make ci~.

** Risks & assumptions
- Orgize provides a configurable parser entrypoint for TODO keyword lists in the currently pinned crate version.
- Title output may change only as a direct consequence of Orgize now recognizing configured TODO keywords and valid priority cookies, which is within scope.
