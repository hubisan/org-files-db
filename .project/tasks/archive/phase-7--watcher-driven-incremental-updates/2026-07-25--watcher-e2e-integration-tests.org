Add end-to-end integration tests for real watcher-backed filesystem updates.

* Planning

** Problem summary

The watcher layers have deterministic unit coverage for event normalization, batching, startup, recovery, CLI lifecycle, and failure handling, but the complete path from a real ~notify~ backend event through Phase 6 to committed SQLite state is not yet covered. The missing suite must validate eventual state without depending on one backend-specific event sequence.

** Goals

- Exercise the real supported-platform ~notify~ backend against temporary filesystem roots.
- Assert eventual committed DB state with bounded polling and useful timeout diagnostics.
- Cover startup, create, modify, metadata-only, delete, rename, atomic replacement, rapid writes, explicit files, recursive and non-recursive roots, exclusions, unrelated paths, DB sidecar activity, invalid input, restart recovery, and temporary root disruption.
- Compare watcher-produced canonical, FTS, and link-resolution state with a fresh Phase 6 reconciliation.
- Keep deterministic batching and recovery policy in the existing unit tests.

** Non-goals

- No production behavior changes, new CLI surface, dependency changes, daemonization, platform-specific event assertions, exact event-count assertions, or Phase 8 parallelism.
- No timing assumptions about a specific create/modify/rename event sequence.

** Architecture

- Add a crate-internal ~#[cfg(test)]~ module so the tests can drive the crate-private watcher runtime without exposing test-only public APIs.
- Use a reusable real-backend harness with one real SQLite connection, the production Phase 6 executor, and a production ~NotifyWatcherSource~.
- Poll the runtime until a DB predicate becomes true or a bounded deadline expires.
- Include file paths, headings, and links in timeout diagnostics.
- Use a quiet-period helper only to detect completion of ignored and DB-sidecar event bursts, not as the primary correctness assertion.

** Execution plan

- Add the real-backend harness and DB observation helpers.
- Add focused tests for no-change startup and normal recursive change sequences.
- Add scope, exclusion, non-recursive, unrelated-file, and watched-DB activity coverage.
- Add explicit-file replacement and offline restart recovery coverage.
- Add invalid-input rollback and temporary-root safety coverage.
- Add semantic comparison against a fresh Phase 6 reconciliation, including FTS where available and link resolution.
- Set the task to ~REVIEW~ after static review and available checks.

** Risks & assumptions

- Local filesystem notifications may be bursty or reordered, so tests assert only eventual state.
- The default 250 ms debounce interval makes the real-backend tests slower than unit tests; the suite uses bounded polling rather than changing production timing.
- FTS assertions are enabled only when the linked SQLite library reports FTS5 support.
- Temporary root disruption is made deterministic by first queuing a normal real event, then removing the root before the pending batch executes.
