Implement the approved task from ~todo.org~ that persists and validates configured source-root identity so automatic reconciliation cannot treat a replaced directory root as the continuation of the previously indexed root.

* Planning

** Problem summary

Phase 6 currently validates configured directory roots only within one watcher process. After restart, a reachable replacement directory at the same configured path can be interpreted as authoritative and can cause existing indexed state to be removed. Root identity also needs to remain stable from discovery through the transaction commit.

** Goals

- Persist deterministic evidence for configured directory roots in ~db_metadata~.
- Reject automatic full reconciliation when a previously committed root changes identity.
- Revalidate root evidence after discovery, before mutation, and immediately before commit.
- Add an explicit manual rebuild option for intentional root replacement.
- Keep zero-input safety independent from root-identity acceptance.
- Reuse the Phase 6 contract from the watcher without adding watcher-owned persistence.

** Non-goals

- Persist identities for individual files or discovered subdirectories.
- Change explicit-file input semantics.
- Implement mount management or Phase 8 parallelism.
- Add watcher-specific root-evidence storage.

** Architecture

- Add one internal source-root evidence module using native Unix path bytes plus device and inode identity.
- Store a versioned deterministic JSON representation in existing ~db_metadata~ entries.
- Capture and compare evidence only for full configured-source reconciliation and full rebuild.
- Carry the captured evidence in a full Phase 6 change plan and persist it in the same transaction as indexed state.
- Keep bounded candidate reconciliation unchanged.

** Execution plan

1. Add the evidence model, persistence, loading, comparison, and errors.
2. Integrate evidence into full change planning, stale validation, rebuild, and commit.
3. Add the manual ~--accept-source-root-changes~ rebuild option.
4. Add deterministic tests for replacement, missing legacy evidence, acceptance, stale races, rollback, and watcher startup failure.
5. Update CLI and incremental-indexing documentation.
6. Run all available checks and record any environment limitation.

** Risks & assumptions

- The existing Unix-only platform contract permits use of device and inode metadata.
- Configuration changes that add or remove logical roots are intentional; identity continuity is checked for logical roots present in both committed and current evidence.
- Recursive-mode changes do not by themselves represent root replacement.
