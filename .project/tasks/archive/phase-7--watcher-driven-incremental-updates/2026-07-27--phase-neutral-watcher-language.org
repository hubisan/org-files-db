Remove phase-number terminology from watcher production code, tests, and user-facing documentation where it no longer carries durable architectural meaning. Keep phase references in historical planning and roadmap material where they remain useful. Improve the missing configured-root startup error.

* Planning

** Problem summary

The watcher implementation and public documentation still expose the temporary project label "Phase 6" in type names, test names, comments, help text, and runtime errors. One startup error also describes internal source-universe derivation instead of explaining that a configured directory is missing.

** Goals

- Replace phase-number terminology in production Rust code with domain-oriented indexing and reconciliation language.
- Rename watcher executor and test helpers so their names describe their roles rather than the implementation phase that introduced them.
- Make missing configured directory errors actionable and user-facing.
- Update public README, CLI, and design documentation to use stable terminology.
- Retain phase references in task history and roadmap documents where they describe project sequencing.

** Non-goals

- Change watcher behavior, indexing semantics, error variants outside the known missing-root mapping, or public CLI options.
- Rewrite archived task history or roadmap phase descriptions.
- Add debug logging or new watcher features.

** Architecture

- Rename the watcher adapter around ~Indexer~ to ~IndexerWatcherExecutor~.
- Map an initial source-universe discovery ~NotFound~ error to a dedicated notify-source error for a missing configured directory.
- Keep all other source-universe errors wrapped with phase-neutral watcher-registration context.
- Replace remaining phase language in production comments, tests, help text, README, and maintained design documentation.

** Execution plan

1. Rename production identifiers and all direct test helpers.
2. Add the missing configured-directory error variant and focused assertions.
3. Replace phase-specific runtime messages, comments, test names, fixtures, and expectations.
4. Update maintained public documentation.
5. Run formatting, focused tests, full CI, and a final source scan.

- Historical task and roadmap references remain untouched because phase numbers are meaningful there.
