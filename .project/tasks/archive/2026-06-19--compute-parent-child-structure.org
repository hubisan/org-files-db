* Planning

** Problem summary
The DB already stores `parent_id`, but hierarchy is still only implied by parsed heading order and `parent_index`. The missing work is to make indexer normalization authoritative so that `parent_index` is recomputed from heading levels before DB insertion.

** Goals
- Compute parent-child structure from heading levels during indexer normalization.
- Ensure exactly one synthetic level 0 heading at index 0.
- Keep `parent_id` DB-only and derived during insert.
- Prepare the hierarchy model for the later `outline_path` task.

** Non-goals
- No Orgize adapter hierarchy redesign.
- No DB schema redesign unless a failing test proves it necessary.
- No CLI, parser API, tag feature, or outline-path feature expansion.

** Architecture
Hierarchy should be computed in `src/indexer.rs` during document normalization.

Reasons:
- The parser adapter already provides stable document order and heading levels.
- The DB layer already requires `parent_id` but does not have parsed ordering context.
- Downstream features such as inherited tags and `outline_path` already depend on normalized hierarchy, so one normalization step should define the structure for all later consumers.

Normalization behavior:
- Guarantee a single level 0 heading at index 0.
- Level 0 heading:
  - `level = 0`
  - `parent_index = None`
  - `is_root = true`
  - normalized file path, title, and full-file byte range kept as today
- Regular headings:
  - `is_root = false`
  - `parent_index = nearest earlier heading with lower level`
  - top-level Org headings parent to level 0

Algorithm:
- After level 0 is guaranteed at index 0, iterate headings from index 1.
- Maintain a stack of heading indexes, initialized with `0`.
- For each regular heading:
  - pop while the stack top has `level >= current.level`
  - use the remaining top index as parent
  - if the stack is empty unexpectedly, fall back to `0`
  - assign `parent_index = Some(parent)`
  - push the current index

DB mapping:
- Keep `index_document` responsible for translating normalized `parent_index` into inserted row ids and storing those as `parent_id`.
- Keep `HeadingRecord.parent_id` and SQLite `headings.parent_id` unchanged.

Preparation for `outline_path`:
- `outline_path`, inherited tags, and later hierarchy-derived data should continue to consume normalized `parent_index` so all hierarchy-dependent behavior shares one source of truth.
