** BUILD Store materialized outline path

Goal:
Build the ~outline_path~ derived/cache table for fast hierarchy queries.

The table stores:

- ~heading_id~
- ~file_id~
- ~parent_id~
- ~depth~
- ~materialized_path~
- ~breadcrumbs_json~

Example materialized paths:

#+begin_src text
0000
0000.0001
0000.0001.0002
0000.0001.0001.0001
#+end_src

Acceptance criteria:

- One ~outline_path~ row exists per heading.
- Level 0 heading has depth 0.
- Top-level Org headings have depth 1.
- ~materialized_path~ is stable for one rebuild.
- Zero-padding is explicitly defined and enforced, e.g. exactly 4 digits per level.
- ~breadcrumbs_json~ contains titles from level 0 to the current heading.
- Subtree queries can use ~file_id~ and ~materialized_path~.
- A test verifies expected paths for nested headings.

* Planning

** Problem summary
`outline_path` already exists as a derived table and is populated during rebuild, but the current path construction uses the global heading index instead of a sibling ordinal. That makes the path shape depend on document position rather than structural sibling order.

** Goals
- Derive `outline_path` after headings are inserted and `parent_id` is known.
- Use sibling ordinal among siblings, not heading id.
- Keep exactly 4 digits per path segment.
- Keep level 0 path as `0000`.
- Store hierarchy depth as `depth`, with level 0 = 0.
- Store breadcrumb titles from level 0 through the current heading.

** Non-goals
- No parser changes.
- No query engine implementation.
- No schema redesign unless a failing test proves it is necessary.

** Architecture
The indexer should continue to insert headings first, then derive `outline_path` rows from the inserted hierarchy. The sibling ordinal should be tracked per parent heading index during the same document pass that produces heading ids.

** Execution plan
- Update the outline-path derivation in `src/indexer.rs` to use sibling ordinals per parent instead of the global heading index.
- Keep `depth` and `breadcrumbs_json` derived from the parent outline row.
- Add a focused indexer test that exercises nested headings with siblings and asserts exact `materialized_path` and `breadcrumbs_json`.
- Keep repeated rebuild coverage to prove stability and non-duplication.
- Run targeted tests, then `make ci`.

** Risks & assumptions
- Assumption: document order is stable and can be used to assign sibling ordinals deterministically.
- Assumption: the current `outline_path` schema is sufficient and does not need changes.
- Risk: changing path derivation may require updating existing outline-path tests that currently rely on the old global-index behavior.
