Implement the task: "Expand `~` in config paths".

Context:
The config loader currently supports absolute paths and paths relative to the config file location. Paths starting with `~` are currently treated as normal relative paths. This task should add home-directory expansion for config path fields only.

Scope:

- Update config path resolution so a leading `~` expands to the current user's home directory.
- Apply this to:
  - `db_path`
  - entries in `files`
  - entries in `dirs`
- Keep the change focused in the config/path resolution layer.

Required behavior:

- `~/org-files-db.sqlite` resolves under the current user's home directory.
- `~/notes/test.org` resolves under the current user's home directory.
- Existing absolute path behavior remains unchanged.
- Existing config-relative path behavior remains unchanged.
- A `~` that is not at the start of the path is not expanded.
- Do not implement general shell expansion.
- Do not expand environment variables such as `$HOME`.
- If the home directory cannot be determined, return an understandable config error.

Non-goals:

- Do not change CLI behavior.
- Do not change parser, DB, indexer, or schema behavior.
- Do not add `--config` support to other commands.
- Do not perform unrelated refactors.

Tests:

- Add focused config tests for leading `~` expansion in `db_path`.
- Add focused config tests for leading `~` expansion in `files`.
- Add focused config tests for leading `~` expansion in `dirs`.
- Test that non-leading `~` is not expanded.
- Keep existing config-relative and absolute path behavior passing.
- Run the repository’s relevant checks, preferring commands from `repository.org` if present.

Completion report:

- State tests/checks run.
