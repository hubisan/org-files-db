** Support simplified file-local TODO keyword lines

Goal:
Support the Org file-local TODO keyword line forms needed for keyword
recognition, without modeling full Org TODO semantics.

This is a follow up of: [[file:archive/2026-06-18--respect-file-local-todo-keyword-config-in-parser-indexer-pipeline.org]]

Checkout the org semantics: [[file:../notes/org-semantics/file-local-todo-keywords.org][File-local TODO Keywords]]

Context:
Org allows file-local TODO keyword definitions using `#+TODO:`,
`#+SEQ_TODO:`, and `#+TYP_TODO:`. These lines may appear anywhere in the file
and apply file-wide.

For now, org-files-db does not model fast-selection keys and does not
distinguish `SEQ_TODO` from `TYP_TODO` semantically. All supported local TODO
keyword lines are treated as equivalent keyword definition lines for heading
TODO detection.

Design decisions:

- Treat `#+TODO:`, `#+SEQ_TODO:`, and `#+TYP_TODO:` as equivalent.
- Collect all supported local TODO keyword lines from anywhere in the file.
- Apply the collected local keyword set globally to the whole file.
- If at least one local TODO keyword line exists, override project/default TODO
  keywords for that file.
- Do not implement position-dependent TODO keyword semantics.
- Do not model fast-selection metadata.
- Strip fast-selection suffixes such as `(t)`, `(w@)`, or `(c)` for keyword
  matching and otherwise ignore them.
- Do not distinguish sequence and type TODO semantics.
- Do not change the DB schema.
- Do not change CLI JSON field names.

Required behavior:

- Keywords before `|` are open TODO keywords.
- Keywords after `|` are closed TODO keywords.
- If no `|` exists, treat the last keyword on that line as closed and preceding
  keywords as open.
- If the left side before `|` is empty, all keywords after `|` are closed.
- If the right side after `|` is empty, all keywords before `|` are open.
- Recognized TODO keywords are removed from normalized/display title fields
  according to the existing title semantics.
- Unrecognized keywords remain part of the title.

Example:

#+begin_src org
,#+TODO: this

,* this sdfdsf

,#+TODO: | that

,* that sdfdsf
#+end_src

Expected behavior:

- `this` is recognized as an open TODO keyword.
- `that` is recognized as a closed TODO keyword.
- Both apply globally to the whole file.

Larger fixture:

#+begin_src org
,#+TITLE: Testing local keywords
,#+TODO: one(t) two(n) | three(d) four(w@)
,#+TODO: FIVE SIX |
,#+TYP_TODO: seven | eight
,#+SEQ_TODO: nine | ten
,#+TODO: | eleven(c)
,#+STARTUP: showall

,* TODO invalid keyword, even though it is a default it is overwritten
,* DONE invalid keyword, even though it is a default it is overwritten

,* one valid, type open
,* two valid, type open
,* three valid, type closed
,* four valid, type closed
,* FIVE valid, type open
,* SIX valid, type open
,* seven valid, type open
,* eight valid, type closed
,* nine valid, type open
,* ten valid, type closed
,* eleven valid, type closed
#+end_src

Expected behavior for the larger fixture:

- `one`, `two`, `FIVE`, `SIX`, `seven`, and `nine` are recognized as open TODO
  keywords.
- `three`, `four`, `eight`, `ten`, and `eleven` are recognized as closed TODO
  keywords.
- `TODO` and `DONE` are not recognized because file-local keywords override
  defaults and they are not listed locally.
- Recognized TODO keywords are removed from normalized/display title fields.
- Unrecognized default keywords remain part of the title.

Acceptance criteria:

- Multiple file-local TODO keyword lines are accumulated.
- `#+TODO:`, `#+SEQ_TODO:`, and `#+TYP_TODO:` are supported.
- Local TODO keyword lines appearing after headings still apply globally.
- Empty left side before `|` is supported.
- Empty right side after `|` is supported.
- Fast-selection suffixes are stripped for matching.
- Fast-selection metadata is otherwise ignored.
- Defaults are overridden when local TODO lines exist.
- Existing default/project TODO keyword behavior still works when no local TODO
  lines exist.
- Existing title normalization behavior is preserved.
- Focused tests cover the behavior above.

* Planning

** Problem summary

The current file-local TODO parsing only reads the first ~#+TODO:~ line and
requires an explicit ~|~, so it misses the supported Org variants and the
simplified fallback semantics needed by this task.

** Goals

- Support ~TODO~, ~SEQ_TODO~, and ~TYP_TODO~ lines equivalently.
- Accumulate multiple local lines from anywhere in the file.
- Override defaults only when at least one local line exists.
- Preserve existing heading title normalization behavior.

** Non-goals

- Full Org TODO semantics.
- Position-dependent TODO scope.
- Multiple ~#+TITLE:~ handling.
- Path normalization or schema/JSON changes.

** Architecture

Keep the change in the shared parser TODO-keyword model so both the Orgize
adapter and the indexer inherit the behavior without new pipeline branches.

** Execution plan

- Extend file-local TODO keyword parsing in ~src/parser/model.rs~.
- Add focused parser fixture and adapter assertions for override/global scope.
- Add an indexer regression covering stored TODO rows and heading recognition.

** Risks & assumptions

- Orgize keyword collection is assumed to include supported keyword lines
  anywhere in the file.
- Existing storage of the first fast-selection character remains acceptable
  because this task only requires stripping suffixes for keyword matching.
