Store absolute normalized config paths and make rebuild replace configured-scope
indexed data from disk.

Apply to:

- `db_path`
- `files`
- `dirs`

Requirements:

- Keep config-relative paths relative to config file directory.
- Keep existing `~` expansion behavior.
- Do not canonicalize through filesystem.
- Do not resolve symlinks.
- Do not require `db_path` to exist.
- Keep existing validation behavior for `files` and `dirs`.
- Rebuild must remove stale indexed data for the configured scope before
  inserting rebuilt data.
- After rebuild, `files` must contain one row per currently indexed configured
  Org file.
- Old relative/noisy rows for those files must not remain.
- Headings must only reference current rebuilt files rows.
- Do not change parser, DB schema, indexer behavior, or CLI JSON field names.

Tests:

- `db_path = "./org-files-db.sqlite"`
- `files = ["./test.org"]`
- `dirs = ["./notes"]`
- rebuilding the same file with equivalent config paths does not create two
  `files` rows
- seeding old relative/noisy `files` rows and headings is cleaned by rebuild
- absolute paths containing `.` components
- `~` expansion together with `.` normalization

* Planning

** Problem summary
Config path resolution and rebuild semantics currently allow stale relative file
identity to survive in the DB.

** Goals
- Resolve configured paths to absolute syntactically normalized paths.
- Make rebuild replace configured-scope indexed data instead of incrementally
  preserving stale file identity.

** Non-goals
- No filesystem canonicalization.
- No symlink resolution.
- No parser, DB, indexer, or CLI schema changes.

** Architecture
Keep path normalization in config resolution and rebuild cleanup in the indexer
and DB writer transaction path.

** Execution plan
- Make resolved config paths absolute and syntactically normalized.
- Replace configured-scope indexed rows transactionally during rebuild.
- Add focused config and indexer tests for stale-row cleanup and dedupe.
- Run repo checks.

** Risks & assumptions
- `Path::components()` is sufficient for removing only `.` segments without
  changing filesystem identity.
- Parsing before the rebuild transaction is acceptable and avoids clearing the
  DB on parse failure.
