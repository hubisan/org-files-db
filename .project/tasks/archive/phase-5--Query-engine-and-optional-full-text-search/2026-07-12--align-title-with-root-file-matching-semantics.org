Goal:

- Make ~title~ root/file behaviour explicit and consistent with Query Model v0.
- Implement root/file title matching as the default behaviour unless it is explicitly disabled through the existing ~:with-root~ option.

Problem:

- Query Model v0 says the root can act as a synthetic heading context for selected heading predicates.
- For root/file context, ~title~ should match the effective file/root title.
- Query Model v0 defines root inclusion as enabled by default where root participation is meaningful.
- The current ~title~ predicate contract only documents ~:regexp~ and ~:exact~.
- The current validator and backend likely treat ~title~ as a real-heading-only predicate.
- Root/file matches must be returned as file objects rather than fake headings.

Required semantics:

- ~title~ on real headings matches heading titles.
- ~title :with-root t~ matches real heading titles and also allows the file/root node to match by its effective file/root title.
- ~title :with-root nil~ excludes file/root title matching and matches real headings only.
- ~title~ without an explicit ~:with-root~ option behaves as ~:with-root t~.
- A matching file/root title returns the file/root object itself.
- ~title :with-root t~ must not behave like ~file-title~.
- ~file-title~ continues to filter headings or other supported objects by the title of their containing file.
- File/root matches must be represented as ~kind = "file"~, not as fake headings.

Specification update:

- Update the documented ~title~ predicate signature to include ~with-root~.

#+begin_src lisp
(title &rest strings &key regexp exact with-root)
#+end_src

- Document the default explicitly.

#+begin_src lisp
(title "Projects")
#+end_src

is equivalent to:

#+begin_src lisp
(title "Projects" :with-root t)
#+end_src

- Document how to disable root/file matching.

#+begin_src lisp
(title "Projects" :with-root nil)
#+end_src

matches real headings only.

- Document the distinction from ~file-title~.

#+begin_src lisp
(title "Projects" :with-root t)
#+end_src

may return the matching file/root object itself.

#+begin_src lisp
(file-title "Projects")
#+end_src

filters supported objects by the title of their containing file and does not turn the file title into a heading match.

Rules:

- Do not change ~file-title~ semantics.
- Do not make ~title :with-root t~ match every heading in a file merely because the file title matches.
- Do not represent root/file matches as fake heading rows.
- Omitted ~:with-root~ must behave exactly like ~:with-root t~.
- Explicit ~:with-root nil~ must suppress file/root matches.
- Explicit ~:with-root t~ must include file/root title matching.
- Output mode must not change which objects match.
- Include options must not change which objects match.
- SQL must continue to use bound parameters for user-provided title values.
- Query execution must remain read-only and DB-backed.
- Root/file title matching must use the effective file/root ~title~, including a file-stem fallback where no source title exists.
- ~title_raw~ must not participate in normal ~title~ matching.
- This task must not introduce or reference any replacement option for ~:with-root~.
- Any future option rename must be handled in a separate follow-up task after this behaviour is implemented and tested.

Examples:

Given a file with the effective title ~Projects~ and a heading titled ~Projects overview~:

#+begin_src lisp
(title "Projects")
#+end_src

may return the file/root object because root inclusion is enabled by default.

#+begin_src lisp
(title "Projects" :with-root t)
#+end_src

has the same root-including behaviour explicitly.

#+begin_src lisp
(title "Projects" :with-root nil)
#+end_src

must not return the file/root object.

#+begin_src lisp
(title "Projects overview")
#+end_src

matches the real heading.

#+begin_src lisp
(file-title "Projects")
#+end_src

filters supported objects by their containing file title and must remain semantically distinct from ~title :with-root t~.

Implementation notes:

- Keep the public syntax based on the existing ~:with-root~ option.
- Add ~with-root~ to the allowed options for the ~title~ predicate.
- Normalize omitted ~:with-root~ to root inclusion.
- Prefer a positive internal representation such as ~include_root~.
- Compile real-heading title matching and file/root title matching as distinct branches.
- Combine both branches only when root inclusion is enabled.
- Do not implement root matching by propagating a matching file title to all headings in that file.
- Reuse the effective file/root ~title~ already exposed by the persisted model.
- Ensure result shaping can return a direct file/root match in both flat and outline output.
