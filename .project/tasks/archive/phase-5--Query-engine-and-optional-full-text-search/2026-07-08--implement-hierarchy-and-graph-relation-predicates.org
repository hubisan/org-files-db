* Planning

** Problem summary

- The SQLite backend already supports metadata predicates and direct link ~source~ / ~target~ filtering on top-level ~links~ queries.
- Hierarchy predicates and graph relation predicates are already parsed and validated, but the backend still rejects them as unsupported.

** Goals

- Add hierarchy predicates for heading queries.
- Add heading/file link relation predicates using persisted link and resolver facts only.
- Extend nested target-query compilation safely for correlated hierarchy and graph subqueries.

** Non-goals

- CLI integration, JSON/result shaping, outline output, include options
- FTS/body search
- Org scanning, rebuilds, repair commands, or DB mutation
- query-time link resolution or resolver semantic changes

** Architecture

- Keep the implementation in ~src/query/sqlite.rs~.
- Keep ~compile_sqlite_query(&ValidatedQuery)~ and ~execute_sqlite_query(&Connection, &ValidatedQuery)~ separate.
- Introduce scope-aware SQL compilation with unique aliases per nested query scope to avoid alias collisions.
- Restrict ~headings~ query matches to real headings with ~level > 0~, while still allowing root/file context on the related side where the specification defines it.
- Implement hierarchy relations from persisted ~headings.parent_id~ and ~outline_path~.
- Implement graph relations from persisted ~links~ source/target columns and stored resolver statuses only.

** Execution plan

- Refactor predicate compilation to work against explicit query scopes and alias-qualified columns.
- Add hierarchy predicate compilation for ~parent~, ~ancestors~, ~children~, and ~descendants~.
- Add heading/file relation predicate compilation for ~has-link~, ~links-to~, and ~linked-from~.
- Extend link ~source~ / ~target~ compilation to the new scoped nested-query helpers.
- Expand the SQLite seed data and module tests for hierarchy, graph relations, resolver status behavior, SQL safety, and non-mutation.
- Run ~cargo fmt --all~, ~cargo test query::sqlite --lib~, and ~make ci~.

** Risks & assumptions

- Nested alias scoping must stay unique across recursive nested queries to avoid self-shadowing bugs.
- ~outline_path.materialized_path~ must be used with delimiter-safe predicates and same-file constraints.
- File backlink semantics rely on persisted ~target_file_id~ also being set for heading-resolved links.

* Results

** Approach

- Refactored the SQLite query compiler to use explicit query scopes with unique aliases per nested query scope.
- Restricted ~headings~ query matches to real headings with ~level > 0~ while keeping root/file facts available through the existing root-context predicates and file-side relations.
- Implemented hierarchy predicates over persisted ~headings.parent_id~ and ~outline_path~ using delimiter-safe materialized-path checks for ancestor/descendant matching.
- Implemented heading/file graph relation predicates and link ~source~ / ~target~ predicates from persisted ~links~ rows and stored resolver-owned target IDs only.
- Enforced resolved-target semantics for every structured target-side predicate so ambiguous, broken, unresolved, external, and unsupported links do not match based on stored candidate target IDs alone.
- Extended the SQLite seed data with an ambiguous link that stores candidate target IDs and added regressions for ~target~, ~links-to~, and ~linked-from~ behavior.
