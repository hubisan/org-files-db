Goal:

- Fix heading title normalisation so ~title~ contains only the semantic heading title.
- Always remove priority cookies from ~title~.
- Always remove statistics cookies from ~title~.
- Ensure title queries match against the cleaned ~headings.title~ value.
- Preserve the source-oriented representation in ~title_raw~.

Example:

#+begin_src org
,* REVIEW [#B] Statistic Cookies [0/1]
#+end_src

Expected parsed and persisted values:

#+begin_src json
{
  "todo_keyword": "REVIEW",
  "priority": "B",
  "title": "Statistic Cookies",
  "title_raw": "[#B] Statistic Cookies [0/1]"
}
#+end_src

Current incorrect result:

#+begin_src json
{
  "todo_keyword": "REVIEW",
  "priority": "B",
  "title": "[#B] Statistic Cookies [0/1]",
  "title_raw": "[#B] Statistic Cookies [0/1]"
}
#+end_src

Rules:

- ~title~ must not contain the TODO keyword.
- ~title~ must not contain a priority cookie such as ~[#A]~, ~[#B]~, or ~[#C]~.
- ~title~ must not contain a statistics cookie such as ~[0/1]~, ~[2/5]~, or ~[50%]~.
- ~title_raw~ keeps priority and statistics cookies according to the existing raw-title contract.
- The separately parsed ~priority~ field remains unchanged.
- Statistics cookies should be removed using Org syntax information where available.
- Arbitrary bracketed text such as ~[Linux]~ or ~[RFC]~ must remain part of ~title~.
- Removing cookies must not leave leading, trailing, or duplicate whitespace in ~title~.
- Built-in and configured TODO keywords must behave identically.
- The normal ~title~ query predicate uses ~headings.title~.
- Priority and statistics cookies must not participate in normal title matching.
- ~title_raw~ is source-oriented output and must not be used by the normal ~title~ predicate.
- Existing indexed data must be rebuilt after this parser change.

Examples:

#+begin_src org
,* TODO [#A] Prepare release
,* REVIEW [#B] Statistic Cookies [0/1]
,* NEXT Progress [50%]
,* TODO Support [Linux]
#+end_src

Expected normalised titles:

#+begin_src text

Support [Linux]
#+end_src

Expected query behaviour:

#+begin_src lisp
(title "Prepare release")
(title "Statistic Cookies")
(title "Progress")
(title "Support [Linux]")
#+end_src

These queries must match the corresponding headings.

These queries must not match through the normal ~title~ predicate:

#+begin_src lisp
(title "[#A] Prepare release")
(title "[#B] Statistic Cookies [0/1]")
(title "Progress [50%]")
#+end_src

* Planning

** Problem summary
The parser currently derives normalised heading titles by reparsing raw heading text, which leaves priority and statistics cookies in ~title~ for some configured TODO cases. Query title matching must use the cleaned persisted ~headings.title~ value rather than any raw-title form.

** Goals
- Remove priority and statistics cookies from parsed heading ~title~.
- Preserve ~title_raw~ as-is.
- Ensure title query predicates match the cleaned persisted title values.

** Non-goals
- changing ~title_raw~ semantics
- further priority parsing changes
- TODO keyword configuration changes
- unrelated query semantics changes

** Architecture
- Adjust title normalization in the Orgize adapter using headline/title syntax information and parsed priority metadata.
- Keep persistence and query behavior aligned by continuing to read the normal ~headings.title~ column in title predicates.
- Add parser and DB-backed query regressions for combined priority/statistics and normal bracket text preservation.

** Execution plan
- Add parser regression tests that currently fail for combined priority/statistics and statistics-only titles.
- Add query regression coverage that proves title matching uses cleaned persisted ~headings.title~ and does not match raw cookie text.
- Implement the title normalization change in the parser adapter.
- Run focused tests and ~make ci~.

** Risks & assumptions
- Orgize ~COOKIE~ syntax nodes can distinguish real statistics cookies from ordinary bracketed text well enough for this task.
- The query backend already targets ~headings.title~; the main need is regression coverage to lock that contract down.

* Results

** Approach
- Added a parser regression for headings that combine TODO keywords, priority cookies, statistics cookies, and ordinary bracketed text, plus a DB-backed query regression that distinguishes ~title~ from ~title_raw~.
- Changed heading-title normalization in ~src/parser/orgize_adapter.rs~ so Orgize ~COOKIE~ nodes are skipped during title rendering and fallback raw-title normalization strips only a leading parsed priority cookie before reusing Orgize for markup-aware normalization.
- Kept ~title_raw~ unchanged in this task and left priority parsing / TODO keyword configuration behavior untouched apart from consuming the already parsed priority value.
- Updated the query-model reference docs to state that ~title~ matching uses normalized stored heading titles and excludes TODO, priority, and statistics cookies.
- Adjusted the native TODO-recognition path so ~title_raw~ is derived from the source heading line with only the leading TODO keyword removed, which preserves priority and statistics cookies consistently across native and fallback TODO detection.
