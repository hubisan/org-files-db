Goal:

- Evaluate every predicate used with the ~headings~ target against one consistent domain:
  - file/root objects at level 0
  - real Org headings at levels 1 and above
- Include matching file/root objects by default.
- Audit every implemented heading predicate instead of fixing root handling only for individual predicates such as ~title~ or ~property~.
- Expose ~level = 0~ on file/root results so the public result representation agrees with the semantics of the ~level~ predicate.
- Remove the predicate option ~:without-root~ from Query Model v0.

Current problem:

- Bare:

#+begin_src lisp
(headings)
#+end_src

already returns file/root objects and real headings.

- Some filtered heading queries return matching file/root objects, while others evaluate only real headings.

- For example:

#+begin_src lisp
(headings
  (property "WHATEVER" "level 0 drawer property"))
#+end_src

currently returns real headings that inherit the root property, but omits the file/root object on which the property is directly stored.

- With:

#+begin_src lisp
(headings
  (property "WHATEVER" "level 0 drawer property" :inherit nil))
#+end_src

the current implementation may return no result, although the property is directly present on the file/root object.

- Root support is therefore implemented inconsistently and appears to depend on the individual predicate or SQL path.

Core domain rule:

- The ~headings~ target domain consists of:
  - one file/root object for every indexed file
  - every real Org heading in those files

- The file/root object represents the internal synthetic level-0 heading.
- Real headings have levels 1 and above.
- A predicate filters this existing domain; it must not silently replace it with a real-headings-only domain.
- Matching file/root objects are returned with ~kind = "file"~.
- Matching real headings are returned with ~kind = "heading"~.
- The internal level-0 database row must not additionally be returned as a duplicate ~kind = "heading"~ object.

File/root result representation:

- Add ~level = 0~ to file/root results returned through the ~headings~ target.

Example:

#+begin_src json
{
  "kind": "file",
  "matched": true,
  "id": 1,
  "root_heading_id": 1,
  "level": 0,
  "title": "Org Property and Keyword Test",
  "title_raw": "Org Property and Keyword Test"
}
#+end_src

- Real heading results continue to contain:

#+begin_src json
{
  "kind": "heading",
  "level": 1
}
#+end_src

or a greater level.

- ~level = 0~ is required on file/root results because the root participates in:

#+begin_src lisp
(level 0)
#+end_src

- The result object must expose the level used during predicate evaluation.
- Consumers must not need to infer level 0 only from ~kind = "file"~.
- File results returned by the standalone ~files~ target should use the same field where practical.
- If result shapes intentionally differ between targets, document and test that difference explicitly.

Required default behavior:

- Root participation is always enabled for the ~headings~ target.
- A file/root object is returned whenever the complete heading predicate expression evaluates to true for that root.
- A real heading is returned whenever the complete expression evaluates to true for that heading.
- Root participation must not depend on whether the query uses:
  - no predicate
  - an atomic predicate
  - ~and~
  - ~or~
  - ~not~
  - a nested relation predicate

Replacement semantics:

- To exclude file/root objects from the result set, combine the query with:

#+begin_src lisp
(level > 0)
#+end_src

Example:

#+begin_src lisp
(headings
  (and
    (level > 0)

#+end_src

- To use only directly stored properties, use:

#+begin_src lisp
(property "CATEGORY" "work" :inherit nil)
#+end_src

- To use effective properties, including values inherited from the file/root level, use:

#+begin_src lisp
(property "CATEGORY" "work" :inherit t)
#+end_src

- To use only local tags, use:

#+begin_src lisp
(tags "project" :inherit nil)
#+end_src

- To use effective tags, including FILETAGS, use:

#+begin_src lisp
(tags "project" :inherit t)
#+end_src

- Query Model v0 does not support the special case:
  - inherit from real ancestor headings
  - but exclude inheritance from the file/root level

- Do not add this distinction without a demonstrated use case.
- A later version may introduce a more precise option such as ~:inherit-root nil~ if required.

Property semantics:

For:

#+begin_src lisp
(headings
  (property "WHATEVER" "level 0 drawer property"))
#+end_src

with default ~:inherit t~, return:

- the file/root object where the property is directly stored
- real headings whose effective property value is inherited from the root

For:

#+begin_src lisp
(headings
  (property "WHATEVER" "level 0 drawer property" :inherit nil))
#+end_src

return:

- the file/root object because the property is directly stored there
- only real headings that directly define the same property
- no real heading that merely inherits it

To exclude the root result while retaining normal effective inheritance:

#+begin_src lisp
(headings
  (and
    (level > 0)
    (property "WHATEVER" "level 0 drawer property" :inherit t)))
#+end_src

return:

- no file/root object
- real headings whose effective property includes the root value

This distinction is intentional:

- ~(level > 0)~ controls which candidate objects are returned.
- ~:inherit t|nil~ controls how effective heading values are resolved.

Tag semantics:

- A file/root object directly matches its FILETAGS.
- With ~:inherit t~, real headings may match local tags, ancestor tags, and FILETAGS according to the accepted effective tag semantics.
- With ~:inherit nil~, only tags directly present on the candidate object match:
  - FILETAGS for the root object
  - local heading tags for a real heading

Example:

#+begin_src lisp
(headings
  (tags "project" :inherit t))
#+end_src

returns:

- the file/root object when its FILETAGS contain ~project~
- real headings whose effective tags contain ~project~

Example excluding root results:

#+begin_src lisp
(headings
  (and
    (level > 0)
    (tags "project" :inherit t)))
#+end_src

returns only real headings, while FILETAGS may still participate in their effective tags.

Title semantics:

- The root title always participates in ~title~ matching.
- The effective root title is:
  - the source ~#+TITLE~ value when present
  - otherwise the file name without its extension

Example:

#+begin_src lisp
(headings
  (title "Projects" :exact t))
#+end_src

may return:

- a matching file/root object
- matching real headings

To return only real heading matches:

#+begin_src lisp

#+end_src

Level semantics:

- File/root objects have semantic level 0.
- Real headings begin at level 1.

Therefore:

#+begin_src lisp
(headings
  (level 0))
#+end_src

returns every file/root object and no real heading.

#+begin_src lisp
(headings
  (level 1))
#+end_src

returns top-level real headings and no file/root object.

#+begin_src lisp
(headings

#+end_src

returns:

- file/root objects
- top-level real headings

#+begin_src lisp
(headings
  (level <= 1))
#+end_src

returns:

- file/root objects
- top-level real headings

* Planning

** Problem summary

- Filtered ~headings~ queries used a predicate allowlist to decide whether matching file/root results could be returned.
- Root participation was inconsistent across implemented heading predicates, and the public query contract still exposed ~:without-root~.
- File results returned from ~headings~ queries did not expose ~level = 0~, which made output inconsistent with the ~level~ predicate semantics.

** Goals

- Evaluate heading predicates against one consistent domain containing real headings and synthetic file/root rows.
- Remove public ~:without-root~ support and align validation, execution, tests, and docs with that model.
- Return ~level = 0~ on file results emitted by ~headings~ queries.

** Non-goals

- No schema changes.
- No expansion of unsupported outline predicates.
- No unrelated query-language cleanup outside root/file participation.

** Architecture

- Keep the existing split execution model: one SQL branch for real heading rows and one SQL branch for synthetic file/root rows.
- Remove the separate root-result allowlist and let the root branch run for every heading query.
- Preserve predicate-specific root-false behavior only where the contract requires it, such as ~parent~, ~ancestors~, and ~has-text~.

** Execution plan

- Remove ~:without-root~ from validator support and obsolete guidance.
- Update SQLite heading predicate compilation so root rows participate consistently.
- Adjust hierarchy/root special cases and result shaping.
- Update tests and public docs.
- Run repository-preferred checks.

** Risks & assumptions

- This is an intentional API-contract change within the active Query Model v0 workstream.
- Existing test fixtures already contain enough root facts and preamble links to validate the behavior without new schema data.
