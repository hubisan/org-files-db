* Planning

** Problem summary

- The SQLite backend currently supports only direct heading ~tags~ and ~property~ matching when ~:inherit nil~ is used.
- Query Model v0 requires effective heading tag/property semantics by default and root/file keyword semantics for heading and file queries.

** Goals

- Extend the SQLite metadata backend with effective heading ~tags~, row-based effective heading ~property~, and root/file ~keyword~ support according to Query Model v0.
- Keep all SQL generated from validated query structures and use bound params for all user values.
- Cover root inclusion/exclusion, inheritance defaults, and backend safety with focused module tests.

** Non-goals

- CLI integration, JSON/result shaping, outline output, include options
- graph relations, hierarchy predicates, FTS, body text search
- parser/indexer fact changes, DB mutation, schema migrations

** Architecture

- Keep the implementation in ~src/query/sqlite.rs~.
- Preserve ~compile_sqlite_query(&ValidatedQuery)~ and ~execute_sqlite_query(&Connection, &ValidatedQuery)~ as separate APIs.
- Implement effective heading semantics with correlated SQL:
  - local-only direct row checks for ~:inherit nil~
  - inherited/effective tag matching via correlated lineage SQL over persisted ~tags~ rows
  - level-0/root tags included or excluded according to ~:with-root~
  - recursive ancestor/root traversal for heading properties when inheritance is enabled
  - root/file keywords through direct ~keywords~ rows on the containing file's level-0 heading

** Execution plan

- Update heading tag compilation to honor exact Query Model defaults and ~:with-root~ behavior.
- Update heading property compilation to use row-based inherited matching over local, ancestor, and optional root rows.
- Keep file tag/property/keyword semantics direct to the level-0 heading.
- Expand the SQLite backend tests to cover inherited/root behavior, regexp rejection, injection safety, persisted-only execution, and non-mutation.
- Run ~cargo fmt --all~, ~cargo test query::sqlite --lib~, and ~make ci~.

** Risks & assumptions

- Recursive SQL must be correlated to each candidate heading to avoid global false positives.
