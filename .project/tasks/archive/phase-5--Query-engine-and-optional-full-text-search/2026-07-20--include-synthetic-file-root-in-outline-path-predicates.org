Task file: [[file:archive/2026-07-20--include-synthetic-file-root-in-outline-path-predicates.org][Include the synthetic file root in outline path predicates]]

Goal:

- Make ~outline-contains~ and ~outline-sequence~ operate on the complete outline path.
- Include the synthetic file/root title as the first path component.
- Keep root handling consistent with the rest of the heading query model.

Current behaviour:

- ~outline-contains~ and ~outline-sequence~ currently exclude the synthetic file/root title from the match path.
- Only real Org headings participate in the outline path.

Current documented semantics:

#+begin_src text
The synthetic file/root title is not part of this match path.
#+end_src

Required semantics:

- The complete outline path starts with the synthetic file/root title.
- Every candidate heading is matched against this complete path.
- The synthetic level-0 heading has a path consisting only of its own title.

Example source:

#+begin_src org
,#+TITLE: Projects

,* Org database

*,* Query model
#+end_src

Expected paths:

#+begin_src text
Level 0:
Projects

Level 1:
Projects
Org database

Level 2:
Projects
Org database
Query model
#+end_src

Required ~outline-contains~ behaviour:

#+begin_src lisp
(outline-contains "Projects")
#+end_src

matches:

- the synthetic file/root heading
- ~Org database~
- ~Query model~

#+begin_src lisp
(outline-contains "Projects" "Query model")
#+end_src

matches ~Query model~ because both components occur somewhere in its complete outline path.

#+begin_src lisp
(outline-contains "Projects" "Org database")
#+end_src

matches both ~Org database~ and ~Query model~.

Required ~outline-sequence~ behaviour:

#+begin_src lisp
(outline-sequence "Projects" "Org database" :exact t)
#+end_src

matches:

- ~Org database~
- ~Query model~

because the sequence occurs contiguously at the beginning of both complete paths.

#+begin_src lisp
(outline-sequence
  "Projects"
  "Org database"
  "Query model"
  :exact t)
#+end_src

matches only ~Query model~.

#+begin_src lisp
(outline-sequence "Org database" "Query model" :exact t)
#+end_src

also matches ~Query model~, because the requested sequence may begin at any component of the complete path.

Root-heading behaviour:

- The synthetic file/root heading participates like any other heading result.
- Its outline path contains exactly one component: the root title.

Therefore:

#+begin_src lisp
(and
  (level 0)
  (outline-contains "Projects"))
#+end_src

matches the synthetic file/root heading.

And:

#+begin_src lisp
(and
  (level 0)
  (outline-sequence "Projects" :exact t))
#+end_src

also matches it.

Option semantics:

- Do not add a ~:with-root~ or ~:inherit~ option.
- Root inclusion is unconditional and part of the predicate definition.
- Existing options remain unchanged:
  - ~outline-contains~ supports ~:regexp t|nil~
  - ~outline-sequence~ supports ~:regexp t|nil~ and ~:exact t|nil~
- ~outline-contains~ continues to have no ~:exact~ option.

Matching details:

- Without ~:regexp t~, each supplied string is matched using the existing component-matching semantics.
- With ~:regexp t~, each pattern is matched against individual outline components, including the root component.
- For ~outline-sequence~, ~:exact t~ applies equally to the synthetic root component and ordinary heading components.
- Root inclusion must not flatten the path into one string before matching.
- Component boundaries must remain significant.

- Do not change storage or duplicate path data unless required by the existing implementation.

* Planning

** Problem summary

The SQLite predicate compiler deliberately skips breadcrumb index zero even though ~outline_path.breadcrumbs_json~ already stores the synthetic root title there.

** Goals

- Include the root component for root and real-heading candidates.
- Preserve substring, regexp, and per-component exact matching semantics.
- Document the complete-path contract and cover root, descendant, and ordinary-heading matches.

** Non-goals

- No schema migration, breadcrumb storage change, or root-inclusion option.

** Architecture

Use the persisted JSON breadcrumb path. Removing the index-zero filters includes the root exactly once while preserving the existing JSON component boundaries and root-to-candidate order.

** Execution plan

1. Remove the index-zero exclusions from both SQLite outline predicate compilers.
2. Extend execution tests for root, parent, child, regexp, exact sequence, and boolean behavior.
3. Update the CLI and Query Model reference contract.
4. Run focused tests and ~make ci~.

** Risks & assumptions

The indexed breadcrumb arrays consistently contain the synthetic root at index zero; this is already guaranteed by indexing and schema repair paths.

- ~make ci~
