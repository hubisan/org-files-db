#+end_src

- Valid only for ~headings~.
- Match when every supplied string matches at least one component somewhere in the heading's outline path.
- Components do not need to be contiguous.

Required semantics for ~outline-sequence~:

(outline-sequence STRING... :regexp t|nil :exact t|nil)

- Valid only for ~headings~.

- The matching sequence may begin at any position in the outline path.
- With ~:exact nil~, apply the existing non-exact text matching rule to each component.

- Root/file objects have an empty real-heading breadcrumb path and therefore evaluate false for a non-empty sequence.

* Planning

** Problem summary

The parser, validator, and public docs already exposed ~outline-contains~ and ~outline-sequence~, but the SQLite heading compiler still rejected both as unsupported predicates.

** Goals

- Compile both outline predicates into executable SQLite filters for ~headings~ queries.
- Keep matching limited to real heading path components rather than the synthetic file/root title stored in ~breadcrumbs_json~.
- Add regression coverage for direct use, boolean composition, and hierarchy nesting.

** Non-goals

- No schema migration.
- No change to parser syntax or core validator shape.
- No generic SQLite regexp support for text predicates.

** Architecture

- Use correlated ~EXISTS~ subqueries against ~outline_path~ and ~json_each(outline_path.breadcrumbs_json)~.
- Skip breadcrumb index ~0~ so outline matching uses only real heading components.
- Keep ~:regexp t~ unsupported in the SQLite backend and document that backend-specific limitation explicitly.

** Execution plan

- Replace the unsupported branches in ~src/query/sqlite.rs~ with dedicated outline predicate compilers.
- Add compile- and execution-level regressions for outline matching, root exclusion, hierarchy integration, and placeholder safety.
- Update the CLI and Query Model docs to reflect real-heading path semantics and SQLite regexp limitations.

** Risks & assumptions

- ~breadcrumbs_json~ currently stores the synthetic file/root title as its first element for headings, so SQL must ignore that element deliberately.
- SQLite JSON row order is not relied on implicitly; sequence matching uses explicit key offsets.
