Core distinction:

- Query matching operates on resolved effective values.

Resolution stages:

1. Resolve all rows stored directly at one location.
2. Apply hierarchy inheritance to those locally resolved values.
3. Match property predicates against the resulting direct or inherited value according to ~:inherit~.

Source order:

- Resolve local property rows in source order.
- Use ~line_number~ as the primary ordering field.
- Use property row ~id~ as a stable secondary ordering field.
- Do not rely on incidental SQLite row order.
- Match keys using their normalized property key.

Local resolution algorithm:

- Start without an effective value for the key.
- Process every local row in source order.
- For a row with ~append = 0~:
  - replace the current local effective value with the row value
- For a row with ~append = 1~:
  - append the row value to the current local effective value
  - separate non-empty components with one space
- If an append row has no preceding local value:
  - initialize the local effective value with the append row value
- Preserve the contents of each stored component.
- Do not split or reinterpret values such as ~foo=1~.

Rule 1: Append rows extend the current local value

- Use the same semantics in SQLite property predicates and result shaping.
- Add a distinct ~effective_properties~ include so raw and resolved facts stay separate.
