Include matching file/root objects for file predicates in heading queries.

* Planning

** Problem summary
- Bare ~(headings)~ already returns the full heading-target domain, including one file/root object per indexed file.
- Filtered heading queries using file predicates currently narrow that domain by omitting matching file/root objects.
- The SQLite backend also still rejects ~file-name~ and ~file-dir~ at execution time even though validation and docs already treat them as valid file predicates.

** Goals
- Make file predicates in heading queries evaluate over both real headings and file/root objects.
- Return matching file/root objects as ~kind = "file"~ without exposing internal level-0 rows as heading results.
- Keep bare ~(headings)~, deterministic ordering, and include behavior intact.
- Close the backend gap for ~file-name~ and ~file-dir~ where needed for this task.

** Non-goals
- No parser or query-model syntax changes.
- No schema change.
- No broader rewrite of root/file participation for unrelated predicate families.

** Architecture
- Reuse the existing root-file hydration path by broadening the gate that decides when heading queries need the extra root/file query.
- Treat ~title~ and heading-valid file predicates as root-capable for that gate.
- Add SQLite SQL-expression helpers for file-name and file-dir matching so heading queries can evaluate the full affected file-predicate set.
- Cover both raw execution and shaped flat/outline output with focused regression tests.

** Execution plan
- Add this task file and link it from ~todo.org~.
- Broaden the heading root/file inclusion gate.
- Implement the missing SQLite support needed for ~file-name~ and ~file-dir~.
- Add focused regression tests for file predicates, boolean combinations, includes, and result shaping.
- Update ~docs/cli.org~ and ~docs/reference/query-model-v0.org~.
- Run ~cargo fmt --all~, focused tests, and ~make ci~.

** Risks & assumptions
- The SQL helpers for file-name and file-dir should stay side-effect free and operate only on persisted file paths.
- This task stays focused on file predicates rather than generalizing root/file participation for every possible boolean form.
