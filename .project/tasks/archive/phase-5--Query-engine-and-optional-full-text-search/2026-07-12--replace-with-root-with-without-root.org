Goal:

- Replace the positive ~:with-root~ query option with the clearer negative ~:without-root~ option.
- Make the query syntax communicate that root participation is enabled by default.
- Apply the rename consistently across the Query Model v0 specification, parser, validation, normalization, execution, tests, and examples.

Problem:

Root/file facts participate by default in predicates where root inclusion is meaningful.

The existing option:

#+begin_src lisp
(title "Projects" :with-root nil)
#+end_src

requires users to know that root matching is enabled by default and then disable it by passing a false value.

The proposed syntax expresses the exception directly:

#+begin_src lisp
(title "Projects" :without-root t)
#+end_src

Required semantics:

- Omitting ~:without-root~ includes root/file participation where supported.
- ~:without-root nil~ behaves like the default and includes root/file participation.
- ~:without-root t~ excludes root/file participation.
- ~:with-root~ is removed from Query Model v0.
- ~:with-root~ and ~:without-root~ must not both remain as supported aliases.
- Predicates that do not support root participation must reject ~:without-root~.
- The rename must not otherwise change match semantics.

Examples:

Default root inclusion:

#+begin_src lisp
(title "Projects")
#+end_src

Equivalent explicit form:

#+begin_src lisp
(title "Projects" :without-root nil)
#+end_src

Exclude root/file matching:

#+begin_src lisp
(title "Projects" :without-root t)
#+end_src

For tags, properties, or other predicates where root participation is supported, apply the same option semantics:

#+begin_src lisp
(tags "project" :without-root t)
#+end_src

Scope:

- Find every use of ~with-root~ in:

  - result-shaping tests

  - error messages
- Replace supported ~:with-root~ syntax with ~:without-root~.
- Invert the Boolean interpretation at the semantic boundary.
- Prefer normalizing the option to one internal value such as ~include_root~ so backend code does not need to reason about negative naming.
- Remove obsolete ~with-root~ branches and tests.

Parser and validation rules:

- Accept ~:without-root t~ and ~:without-root nil~ only on predicates where root participation is meaningful.
- Reject non-Boolean values.
- Reject the obsolete ~:with-root~ keyword with a clear semantic error.
- Reject duplicate ~:without-root~ options according to the existing duplicate-option rules.
- Preserve the distinction between omitted and explicit values only where required for diagnostics or normalized output.
- Normal execution semantics are:
  - omitted: include root
  - nil: include root
  - t: exclude root

Internal representation:

- The public query syntax uses ~without-root~.
- Internal code should preferably use positive terminology such as ~include_root~.
- Normalize values as follows:

#+begin_src text

without-root nil     -> include_root = true
without-root t       -> include_root = false

- Do not propagate negatively named Boolean logic unnecessarily into SQL translation and result shaping.
