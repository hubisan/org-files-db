* Planning

** Problem summary
The query backend currently returns raw target-specific rows only. This task must turn those matched rows into a stable JSON-facing result model for later CLI/editor use without changing matching semantics or coupling the query AST to output concerns.

** Goals
- Add a result shaping layer above raw SQLite execution.
- Support stable ~flat~ and ~outline~ query output modes.
- Support include-based enrichment for ~path~, ~properties~, ~keywords~, ~links~, ~backlinks~, ~source~, and ~target~.
- Keep shaping read-only and based only on stored DB facts.
- Document behavior with focused tests.

** Non-goals
- CLI command integration
- parser, validator, or SQL predicate semantic changes
- link resolution at shaping time
- Org file scanning
- DB mutation or repair
- FTS/body search work

** Architecture
- Add a dedicated query result module re-exported from ~src/query.rs~.
- Keep output mode/include options in a separate execution-options struct.
- Execute raw matching first, then run read-only enrichment queries by matched IDs and relevant file IDs.
- Use distinct JSON names for stored link target paths and include-generated node paths.

** Execution plan
- Add public result/output option types and shaping entrypoints.
- Implement read-only enrichment loaders for files, headings, paths, properties, keywords, outgoing links, backlinks, and resolved target metadata.
- Shape heading, file, and link results for flat and outline modes with deterministic ordering.
- Add focused result-shaping tests and run the requested checks.

** Risks & assumptions
- The stable query JSON model for this task may differ from earlier raw CLI JSON row shapes.
- File/root locations use explicit nullable location fields instead of exposing the internal level-0 byte sentinel.
- File ~links~ and ~backlinks~ includes operate file-wide, not root-only.

* Results

** Approach
- Added ~src/query/result.rs~ as a result-shaping layer above raw SQLite execution and re-exported its public API from ~src/query.rs~.
- Kept query parsing, validation, and SQL matching unchanged. Output mode and include handling live in ~QueryExecutionOptions~.
- Loaded enrichment data only after raw matches were known, using read-only DB queries keyed by matched file IDs and heading IDs.
- Renamed stored link target path output to ~link_path~ and include-generated ordered node paths to ~node_path~ to avoid JSON field collisions.
- Represented file/root editor-jump locations without leaking the internal level-0 ~byte_start = -1~ sentinel: file/root JSON locations use nullable byte offsets.
- Implemented file-wide ~links~ and ~backlinks~ includes for file result nodes via stored ~links.file_id~ and ~links.target_file_id~ facts.
