** DONE [#B] Expand leading ~~ in ~file-path~ query values

- Task file: [[file:archive/2026-07-19--expand-leading-tilde-in-file-path-query-values.org]]

Goal:

- Allow ~file-path~ query values beginning with ~~ to refer to the current user's home directory.
- Expand ~~ from the process environment before compiling the predicate for the SQLite backend.
- Keep stored file paths unchanged.

Current behaviour:

- ~file-path~ is validated and compiled as a generic text predicate.
- Query values are passed to SQLite without path-specific processing.
- The compiler currently performs only:
  - substring matching
  - exact text matching
  - regular-expression matching
- Consequently, the following value remains literal:

#+begin_src text
~/projects/coding/org-files-db/.project/manual-tests/query-model/org/headings/ancestors.org
#+end_src

- It therefore does not match a stored absolute path such as:

#+begin_src text
/home/hubisan/projects/coding/org-files-db/.project/manual-tests/query-model/org/headings/ancestors.org
#+end_src

Required semantics:

- Expand a query value consisting only of ~~ to the value of the process environment variable ~HOME~.
- Expand a query value beginning with ~~/~ by replacing the leading ~~ with ~HOME~.

Example:

#+begin_src text
HOME=/home/hubisan
~/projects/example.org
-> /home/hubisan/projects/example.org
#+end_src

- Perform the expansion only on a leading path component.
- Do not replace ~~ occurring elsewhere in a string.

Examples that must remain unchanged:

#+begin_src text
projects/~/notes.org
file~backup.org
#+end_src

- Do not implement named-user expansion such as:

#+begin_src text
~alice/notes.org
#+end_src

- Named-user expansion is outside Query Model v0.
- Do not invoke a shell to perform expansion.
- Do not modify the path stored in the database.
- Do not canonicalise the expanded path, resolve symlinks, or require the referenced file to exist.

Supported targets:

- Apply the same expansion whenever ~file-path~ is used for:
  - ~headings~
  - ~files~
  - nested file relations from ~links~
- The result must not depend on which query target owns the predicate.

Matching modes:

- Apply home-directory expansion before evaluating the selected matching mode.
- Support expansion consistently for:
  - default substring matching
  - ~:exact t~
  - ~:regexp t~
- Expand each supplied ~file-path~ argument independently.

Example exact query:

#+begin_src lisp
(headings
  (file-path
    "~/projects/coding/org-files-db/.project/manual-tests/query-model/org/headings/ancestors.org"
    :exact t))
#+end_src

With:

#+begin_src text
HOME=/home/hubisan
#+end_src

this must behave like:

#+begin_src lisp
(headings
  (file-path
    "/home/hubisan/projects/coding/org-files-db/.project/manual-tests/query-model/org/headings/ancestors.org"
    :exact t))
#+end_src

Implementation tasks:

- Add a shared helper for expanding leading home-directory syntax in ~file-path~ query arguments.
- Read the home directory from the process environment variable ~HOME~.
- Handle:
  - ~~
  - ~~/...~
- Leave all other strings unchanged.
- Apply the helper before values are converted to SQLite query parameters.
- Keep generic text predicate compilation free of global path expansion.
- Ensure expansion is specific to ~file-path~ rather than all text predicates.
- Reuse the same implementation for heading, file, and nested relation queries.
- Do not use shell execution or shell-word expansion.
- Do not alter indexed paths or query result paths.

Missing ~HOME~:

- When a query contains ~~ or ~~/...~ and ~HOME~ is unavailable, return a clear query execution error.
- The error should identify:
  - the ~file-path~ predicate
  - the unavailable ~HOME~ environment variable
- Queries without a leading ~~ must continue to work when ~HOME~ is unavailable.

- Absolute-path queries retain their existing behaviour.
- Expansion works consistently for all targets supporting ~file-path~.
- Values without a leading ~~ remain unchanged.
- Named-user expansion is not introduced.
- Stored and returned paths remain absolute source paths.
