Goal:

- Make effective property resolution match Org when append rows occur before, between, or after ordinary property definitions at the same location.
- Use the last non-append definition as the base value.
- Append all append definitions for the same normalized key in source order.
- Preserve every raw property row unchanged.
- Apply the same semantics to:
  - file/root properties
  - heading property drawers
  - direct property queries
  - inherited property queries
  - effective property hydration

Problem:

- A sequential reset algorithm is not Org-compatible.
- A later non-append definition replaces earlier base definitions, but it does not discard append rows that appeared earlier.
- Append rows are collected independently of their position relative to the winning base definition.

Required local resolution rule:

For one normalized property key at one file/root or heading location:

1. Collect all rows for the key.
2. Sort them deterministically by:
   - ~line_number~
   - property row ~id~ as a stable tie-breaker
3. Select the last row with ~append = 0~ as the base value.
4. Collect every row with ~append = 1~ in source order.
5. Combine:
   - the winning base value, when present
   - followed by all append values
6. Separate non-empty components with one space.
7. If no non-append row exists, combine only the append values.
8. Do not discard append rows because they occur before the winning base row.

Inheritance semantics:

With ~:inherit t~:

- Resolve all local rows according to the same last-base-plus-all-appends rule.
- If a local non-append base exists:
  - use it instead of an inherited base
  - append all local append rows
- If no local non-append base exists:
  - use the nearest inherited effective value as the base when available
  - append all local append rows
- If no inherited value exists:
  - append-only local rows form the complete value

* Planning

** Problem summary

Effective property resolution still drops append rows when a later non-append row appears at the same location, which does not match Org ~org-entry-get~ behavior.

** Goals

- Make local property resolution use the last non-append value as the base and keep all append rows in source order.
- Apply the same semantics to in-memory resolution, SQLite query matching, and ~effective_properties~ output.
- Keep raw property storage and raw ~properties~ output unchanged.

** Non-goals

- No schema changes.
- No parser/storage changes for property rows.
- No change to unsupported ~:regexp t~ behavior for ~property~.

** Architecture

- Replace sequential-reset local property resolution with a shared last-base-plus-all-appends model.
- Mirror that model in the SQLite property predicate local-summary CTE.
- Cover the behavior with focused resolver, query, and result-shaping regressions.

** Execution plan

- Update ~src/query/property.rs~ local resolution logic and unit tests.
- Update SQLite property matching in ~src/query/sqlite.rs~ and extend the seeded query fixture.
- Add a result-shaping regression for ~effective_properties~ append ordering.
- Update query documentation and run ~make ci~.

** Risks & assumptions

- Deterministic ordering remains ~line_number~, then property row ~id~.
- Empty components should not create extra spaces in resolved values.
