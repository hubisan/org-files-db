* Planning

** Problem summary
~EnrichmentContext::load~ currently loads every stored heading for every relevant file, even when flat output without includes only needs the matched node data required to shape the result.

** Goals
- Add a narrow loading path for ~QueryOutputMode::Flat~ with no includes.
- Load only matched heading rows for real heading results.
- Load synthetic root headings only when a file result node needs them.
- Avoid loading heading rows for plain flat link results.
- Preserve all existing output, ordering, outline, and include behaviour.

** Non-goals
- Do not optimise outline output.
- Do not optimise any query using ~--include~.
- Do not redesign ~EnrichmentContext~ or query SQL.
- Do not add caching.

** Architecture
Keep the existing ~EnrichmentContext::load~ path unchanged for outline output and any query with includes. Add a dedicated flat/no-include constructor that loads matched files first, derives only the required heading IDs, and uses a targeted heading-by-ID loader.

** Execution plan
1. Route only flat output with an empty normalised include list through the dedicated loader.
2. Add a heading-by-ID loader while sharing the existing stored-heading loading implementation.
3. Add focused regression tests proving unrelated headings are not required for plain flat heading and link shaping.
4. Review the diff for output and scope changes.

** Risks & assumptions
- File result nodes still require their synthetic root heading because file tags are read from it.
- Real heading result nodes require only their own stored heading row when no includes are requested.
- Plain link result nodes require file metadata but no stored heading rows when no includes are requested.
- Rust CI is run by the user rather than in this environment.
