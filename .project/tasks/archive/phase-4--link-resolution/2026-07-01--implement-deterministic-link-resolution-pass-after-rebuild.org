* Planning

** Problem summary
- Raw Phase 3 links are already stored, and the DB contract for resolver-owned fields is in place, but rebuild currently stops after indexing and never runs a deterministic resolution pass.
- Later resolution tasks need a stable post-indexing orchestration point that sees the full rebuild universe inside the same transaction.

** Goals
- Add a dedicated resolver pass after all rebuild writes have completed.
- Reset stale resolver-owned fields before assigning unsupported fallback state.
- Keep resolver behavior deterministic and intentionally minimal in this task.

** Non-goals
- No concrete target resolution by file path, CUSTOM_ID, Org ID, attachment, or search options.
- No change to raw link extraction/storage semantics.
- No new public JSON surface for resolution fields.

** Architecture
- Add a small =src/link_resolver.rs= module with a transaction-scoped =LinkResolver::resolve_all= entry point.
- Invoke the resolver exactly once near the end of rebuild orchestration, after all file rows have been inserted for the current rebuild and before commit.
- Keep the initial implementation SQL-centric and deterministic: reset resolver-owned fields, load links in stable order, and mark each as unsupported with a stable diagnostic.

** Execution plan
- Create the active task file and link it from =todo.org=.
- Inspect rebuild orchestration and existing link/indexer tests.
- Implement the resolver module and wire it into rebuild.
- Add focused indexer/DB tests for ordering, reset behavior, repeat rebuild stability, and raw-field immutability.
- Run formatter, focused tests, and =make ci=, then record results.
