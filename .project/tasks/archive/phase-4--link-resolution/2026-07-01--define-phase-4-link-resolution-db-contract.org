Depends on:

- [[#phase3-link-contract][Phase 3 link extraction contract]]

Goal:

- Finalize how link resolution state is represented in the DB before implementing resolvers.
- Keep raw source columns as immutable source facts.
- Extend the current target fields with explicit resolution state.

Current schema already has:

- ~path_absolute~
- ~target_file_id~
- ~target_heading_id~
- ~target_custom_id~
- ~target_id~

Problem:

- Nullable target references alone cannot distinguish:
  - not attempted
  - resolved
  - broken
  - ambiguous
  - unsupported
  - unresolved because the complete target universe is unknown
- A NULL target alone is not enough because target deletion may also set target FKs to NULL.

Add fields:

- ~resolution_status~
- ~resolution_diagnostic~

Allowed ~resolution_status~ values:

- ~unresolved~
- ~resolved~
- ~broken~
- ~ambiguous~
- ~unsupported~

Rules:

- Raw fields remain unchanged:
  - ~raw~
  - ~raw_target~
  - ~raw_description~
  - ~link_type~
  - ~path~
  - ~search_option~
  - ~byte_start~
  - ~byte_end~
  - ~line~
  - ~source_context~
- Target fields may be updated by the resolver:
  - ~path_absolute~
  - ~target_file_id~
  - ~target_heading_id~
  - ~target_custom_id~
  - ~target_id~
  - ~resolution_status~
  - ~resolution_diagnostic~
- Broken links keep their raw source facts.
- Ambiguous links keep their raw source facts and must not pick an arbitrary target.
- Unsupported links keep their raw source facts.
- Unresolved links keep their raw source facts and represent incomplete target-universe knowledge.
- Target FK deletion uses ~ON DELETE SET NULL~ and must not delete source link rows.
- If a target FK is set to NULL by deletion, resolution state must become consistent on the next resolution pass.

Acceptance criteria:

- Schema migration adds explicit resolution state.
- Existing Phase 3 link source-fact tests still pass.
- Legacy migration tests cover the new columns.
- DB tests cover target heading deletion setting ~target_heading_id~ to NULL.
- DB tests cover target file deletion setting ~target_file_id~ to NULL.
- Tests prove source link rows survive target deletion.
- Tests cover all allowed ~resolution_status~ values.
- Naming is consistent with the existing schema; do not mix ~target_*~ and ~resolved_*~ for the same concept.

* Planning

** Problem summary
- The =links= table currently relies on nullable target columns alone, which cannot distinguish resolver outcomes from untouched rows or FK nulling caused by target deletion.
- Phase 4 needs a stable DB contract before any resolver implementation can safely update link rows.

** Goals
- Add explicit link resolution state columns to the persisted schema.
- Preserve Phase 3 raw link source facts and keep them immutable.
- Keep the existing =target_*= naming and align migrations/tests with the new contract.

** Non-goals
- No resolver implementation in this task.
- No change to stored raw link extraction semantics.
- No new CLI surface for resolution state in this task.

** Architecture
- Extend the authoritative SQLite schema and schema-version contract.
- Teach legacy links migration to populate the new columns deterministically.
- Expand DB tests to cover allowed statuses and FK nulling behavior after target deletion.

** Execution plan
- Create the active task file and link it from =todo.org=.
- Update =links= schema comments, columns, and migration detection for explicit resolution state.
- Refresh DB and writer tests to cover the new contract and keep Phase 3 expectations intact.
