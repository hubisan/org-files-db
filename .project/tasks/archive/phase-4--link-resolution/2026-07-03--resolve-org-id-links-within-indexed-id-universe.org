* Planning

** Problem summary
- The parser and storage already preserve Org ID links as =link_type = id= source facts, but the resolver currently treats them as unsupported.

** Goals
- Resolve Org ID links against =ID= properties across the indexed non-root heading universe.
- Normalize targets by trimming whitespace and compare case-insensitively.
- Surface missing IDs as =unresolved= and duplicates as =ambiguous= while preserving raw link fields.

** Non-goals
- No file-context ID search-option support.
- No parser classification changes unless a resolver test reveals a missing fixture expectation.
- No schema changes.

** Architecture
- Add a dedicated =id= branch in =LinkResolver::resolve_link=.
- Reuse the existing property lookup pattern with a global-scope helper ordered by document order.
- Add explicit marker helpers for resolved, unresolved, and ambiguous Org ID outcomes that populate =target_id= and clear =target_custom_id=.
