* Planning

** Problem summary
- =orgfdb links --json= currently exposes only the stored Phase 3 source-fact fields even though the DB contract already persists nullable Phase 4 resolution columns.

** Goals
- Expose the stored resolution columns in the public links JSON rows.
- Preserve deterministic ordering and read-only DB access semantics.
- Keep root links visible and surface resolved, broken, ambiguous, unresolved, and unsupported rows without filtering.

** Non-goals
- No rebuild behavior changes.
- No resolver changes.
- No schema changes or migrations.

** Architecture
- Extend =DbReader::list_links= to select the existing resolution columns from =links=.
- Extend =LinkJsonRow= to serialize the new nullable fields directly from stored DB rows.
- Update CLI contract tests and documentation to reflect the expanded public JSON shape.

** Execution plan
- Add the active task file and link it from =todo.org=.

- Add test coverage for the public JSON keys and mixed resolution-state rows.

- Run formatter, focused tests, and =make ci= if available.

** Risks & assumptions
- Assumption: the current on-disk schema for supported databases already contains the Phase 4 columns, so exposing them in the read path is an API change but not a schema change.
