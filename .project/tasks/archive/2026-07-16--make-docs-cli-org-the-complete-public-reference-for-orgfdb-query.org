Goal:

- Make ~docs/cli.org~ the complete user-facing reference for the implemented ~orgfdb query~ command.
- Document every supported query target, predicate, option, include value, output mode, result shape, default, and important semantic rule in one place.
- Keep ~docs/reference/query-model-v0.org~ as the normative Query Model v0 contract and design reference, but do not require users to read it merely to discover or use CLI functionality.

Current problem:

- ~docs/cli.org~ documents only a small part of the implemented query surface.
- Many supported predicates, predicate options, relation forms, timestamp semantics, root/file semantics, includes, and output details are currently documented only in ~docs/reference/query-model-v0.org~.
- Users cannot determine the complete CLI functionality from ~docs/cli.org~ alone.
- This creates documentation drift and makes the public CLI appear less capable than the implementation.

Documentation policy:

- ~docs/cli.org~ is the complete public usage reference.
- ~docs/reference/query-model-v0.org~ remains the normative contract for:
  - grammar decisions
  - validation rules
  - precise semantic definitions
  - implementation-oriented notes
  - compatibility and versioning decisions
- It is acceptable for both documents to contain the same predicate names and core semantics.
- Avoid contradictory wording by deriving both documents from the accepted Query Model v0 contract.
- Document only functionality that is currently implemented and publicly supported.
- Mark specified but unimplemented functionality clearly and do not mix it into the supported predicate inventory.
