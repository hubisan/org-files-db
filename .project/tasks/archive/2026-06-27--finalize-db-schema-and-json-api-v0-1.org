* Planning

** Problem summary
The current contract is close to freeze-ready, but ~headings --json~ still uses a write-capable DB open path and still exposes ~all_tags_json~ as a double-encoded string.

** Goals
- Freeze the intended populated ~v0.1~ SQLite schema contract.
- Freeze the ~headings --json~ API contract with a read-only open path and array-shaped tags.
- Add concise README contract documentation and focused regression tests.

** Non-goals
- Do not implement link indexing.
- Do not redesign field names beyond replacing public ~all_tags_json~ exposure with ~all_tags~.
- Do not perform unrelated DB, parser, indexer, or CLI refactors.

** Architecture
- Separate public CLI JSON output from internal DB row shape with a small CLI-facing JSON type if needed.
- Keep the internal DB schema unchanged unless a persistent-schema bug is discovered.
- Add an explicit read-only DB open helper in ~src/db.rs~ and route ~headings~ to it.

** Execution plan
1. Add a read-only DB open path for ~headings~ that does not initialize or migrate schema.
2. Add a CLI-facing JSON row type with ~all_tags~ as an array and preserve current root filtering semantics.
3. Tighten README contract documentation for schema population, deferred tables, and CLI JSON shape.
4. Update existing CLI/DB tests and run ~make ci~.

** Risks & assumptions
- Since this task should not change the persistent schema, ~CURRENT_SCHEMA_VERSION~ should not be bumped.
- Deferred ~links~ can be documented explicitly without blocking the ~v0.1~ freeze.
