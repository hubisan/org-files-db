Notes discovered during review:

- The multi-line planning example
  #+begin_src org
  * Each on one Line
  SCHEDULED: <2023-11-10>
  DEADLINE: <2023-11-12>
  CLOSED: [2023-11-10 Fri 14:00]
  #+end_src
  should currently be treated as matching Emacs ~org-element-parse-buffer~ behavior: only ~SCHEDULED~ lands in the planning node, while ~DEADLINE~ and ~CLOSED~ are parsed afterwards as paragraph content.
- The single-line planning form
  #+begin_src org
  * Test
  DEADLINE: <2024-12-01 Sun> SCHEDULED: <2024-11-20 Wed> CLOSED: <2024-11-20 Wed>
  #+end_src
  is explicitly allowed and should become a positive adapter regression test.
- Plain links such as ~https://www.example.com~ need explicit regression coverage because Orgize currently appears not to expose them like bracket/file links.
