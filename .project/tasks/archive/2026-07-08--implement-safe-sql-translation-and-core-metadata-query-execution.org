* Planning

** Problem summary
The repository has a parsed and semantically validated query model, but no SQL translation or DB-backed execution layer yet. This task adds a safe SQLite backend for core metadata predicates only, without moving into later hierarchy or graph-relation semantics.

** Goals
- Add a SQLite query backend that compiles only ~ValidatedQuery~ into parameterized SQL.
- Execute heading, link, and file metadata queries against persisted DB facts only.
- Return raw backend rows for later shaping work.
- Reject unsupported predicates and backend requirements clearly.

** Non-goals
- CLI query integration
- JSON or outline result shaping
- FTS or body text execution
- Org file scanning, rebuilds, repairs, or any DB mutation
- Hierarchy predicates
- Broad graph relation predicates such as ~has-link~, ~links-to~, and ~linked-from~
- Effective/inherited tag, property, keyword, or root semantics

** Architecture
- Add ~src/query/sqlite.rs~ and re-export its public surface from ~src/query.rs~.
- Keep ~compile_sqlite_query~ and ~execute_sqlite_query~ separate.
- Use a small internal SQL fragment representation for safe boolean composition and constrained joins.
- Add raw query row structs and backend error types in the query module.

** Execution plan
- Add backend types, compile/execute APIs, and narrow predicate support.
- Implement parameterized SQL generation for supported heading, link, and file metadata predicates.
- Add execution code that binds values safely and maps rows into raw backend row structs.
- Add focused compile and execution tests for supported and unsupported behavior.

** Risks & assumptions
- ~file-name~ and ~file-dir~ stay unsupported because the current schema does not store them directly and this task should not add SQL-specific path parsing behavior.
- ~source~ and ~target~ support on link queries stays limited to direct stored ID checks or trivial constrained subqueries.
- Any ~:regexp t~ usage fails explicitly because the current SQLite backend does not register a regexp function.

** Open questions
- None at implementation start.

* Results

- Implemented metadata execution for headings, links, and files plus boolean composition.
- Limited link ~source~ / ~target~ to direct stored IDs and small nested ~EXISTS~ checks over persisted rows.
- Rejected hierarchy, deferred graph relations, regexp matching, and effective/inherited semantics explicitly through backend errors.
- Added backend tests for SQL placeholder safety, injection-like payloads, representative metadata queries, persisted-DB-only reads, and no-mutation execution.
