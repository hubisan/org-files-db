Acceptance criteria:

- Rebuild processes at least one file completely.
- Diagnostics are visible in the CLI or can be retrieved later.
- A faulty file either stops cleanly or is skipped with documented behavior.

- Rebuild is idempotent for the same file.
- Outline cache rows are consistent after rebuild.
- Rebuild works with FTS5 disabled.
- FTS rows are consistent after rebuild when FTS5 is enabled.

* Planning

** Problem summary

Implement a narrow Phase 1 indexer that loads config, discovers Org files, parses them through the existing adapter, normalizes the result, and rebuilds per-file DB rows using the existing schema and writer APIs.

** Goals

- Add a project-owned indexer API for full rebuild from config.
- Keep rebuild idempotent per file.
- Preserve current layering: config -> parser adapter -> internal model -> DB writer.
- Collect diagnostics in an indexer-owned result type.

** Non-goals

- No CLI wiring yet.
- No new query APIs.
- No broad parser expansion beyond what the current model already exposes.
- No schema redesign unless required for this slice.

** Architecture

- Use the existing config loader and parse options.
- Discover files from explicit paths and configured directories with a small stdlib walker.
- Parse each file with the injected parser.
- Normalize documents into DB rows, including a synthetic level 0 heading when missing or malformed.
- Rebuild each file through ~DbWriter::rebuild_file~.
- Stop cleanly on the first faulty file. This matches the existing ~Result~-based error style and keeps Phase 1 behavior explicit.

** Execution plan

- Create the task record and link it from ~todo.org~.
- Expand ~src/indexer.rs~ into a full rebuild layer and add focused supporting types.
- Add or extend DB writer helpers only where the indexer needs an existing schema row type that is currently missing.
- Add focused indexer tests for rebuild, replacement, outline consistency, FTS behavior, and fault handling.
- Run relevant tests, then ~make ci~ if available.

** Risks & assumptions

- The parser model currently does not expose body text or links, so those inserts remain intentionally deferred.
- FTS tests must stay portable when the local SQLite build lacks FTS5.
