Goal:

- Extract supported Org bracket links and store them as raw source facts.

Contract copied from Phase 3 SPEC:

- Bracket links are syntax-driven.
- If bracket syntax is valid, extract the link.
- Supported:
  - ~[[target]]~
  - ~[[target][description]]~
- Store ~format = bracket~.
- Preserve ~raw~.
- Preserve ~raw_target~.
- Preserve ~raw_description~ when present.
- Use ~link_type~, not ~type~.
- Do not store normalized ~description~.
- Explicit typed targets store the prefix before the first ~:~ as ~link_type~.
- Unknown explicit types are preserved as their ASCII-lowercase prefix.
- Store ~path~ as the part after the first ~:~ for explicit typed links.
- Targets without explicit type are classified minimally:
  - ~[[#custom-id]]~ => ~link_type = custom-id~
  - ~[[*Heading]]~ => ~link_type = fuzzy~
  - ~[[dedicated]]~ => ~link_type = fuzzy~
- Implicit file bracket links are classified as file-like only when the target starts with:
  - ~./~
  - ~../~
  - ~~/~
  - ~/~ 
- ~[[notes.org]]~ remains fuzzy, not file.
- Split ~path::search_option~ only for file-like links.
- Do not resolve targets.
#+end_src

* Planning

** Problem summary
- The repository already has a project-owned raw-text scanner and a DB link schema, but bracket links are not yet exposed on parsed documents or written during indexing.
- This task needs the smallest end-to-end bracket-link path: scanner output -> parsed document -> heading/root ownership -> DB rows.

** Goals
- Expose bracket links through the parser-owned document model.
- Persist only bracket links through the existing indexer/storage pipeline.
- Keep classification, raw field preservation, and file-like search-option splitting aligned with the Phase 3 contract.

** Non-goals
- No angle-link storage.
- No plain-link storage.
- No target resolution or target lookup.
- No advanced bracket escaping or delimiter edge cases beyond the current task contract.

** Architecture
- Extend =ParsedOrgDocument= with a parser-owned =links= collection.
- Let =OrgizeAdapter= populate document links via the project scanner, filtered to =format = bracket=.
- Let the indexer map link byte positions onto already-normalized heading/root ranges and persist them via =DbWriter::insert_links= with =source_context = normal= for now.

- Update scanner bracket classification and file-like search-option splitting where required by the contract.

- Add focused scanner and indexer regression tests.
- Run formatter, focused tests, and =make ci=.

* Results

** Approach
- Extended the parser-owned document model with =links= so scanner output can travel through parsing and indexing without a parallel side channel.
- Reused the existing project-owned scanner in =OrgizeAdapter= and filtered its output to =format = bracket=, keeping link-token ownership outside Orgize link-node support.
- Refined bracket-link classification in the scanner to:
  - lowercase explicit link types
  - keep unknown explicit types
  - classify implicit file-like targets only for =./=, =../=, =~/=, and =/=

  - split =path::search_option= only for file-like bracket links
