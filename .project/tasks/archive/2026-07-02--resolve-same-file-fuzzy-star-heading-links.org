Depends on:

- [[*Resolve file links with heading-title search options][Resolve file links with heading-title search options]]

Goal:

- Resolve same-file fuzzy heading links of the form ~[[*Heading]]~.

Supported forms:

- ~[[*Heading]]~
- ~[[*Heading][Description]]~

Out of scope:

- Do not resolve non-star fuzzy links such as ~[[Heading]]~.
- Do not resolve dedicated targets.
- Do not resolve radio targets.
- Do not resolve named elements.

Resolution rules:

- Resolve only links classified as:
  - ~link_type = fuzzy~
  - ~path~ starts with exactly one leading ~*~
- Target file context is the source file.
- Strip exactly one leading ~*~ before matching.
- Unescape Org link escapes needed for heading text matching.
- Search non-root headings only in the source file.
- Match against the documented stored heading title field.
- If exactly one heading matches:
  - set ~target_file_id~ to the source file id.
  - set ~target_heading_id~
  - set ~resolution_status = resolved~
  - set ~resolution_diagnostic = NULL~
- If no heading matches:
  - set ~target_file_id~ to the source file id.
  - set ~target_heading_id = NULL~
  - set ~resolution_status = broken~
- If multiple headings match:
  - set ~target_file_id~ to the source file id.
  - set ~target_heading_id = NULL~
  - set ~resolution_status = ambiguous~
  - do not pick the first heading.

Acceptance criteria:

- ~[[*Target heading]]~ resolves to the matching heading in the same file.
- ~[[*Target heading][Description]]~ resolves and preserves the raw description.
- Missing same-file star fuzzy heading links are marked ~broken~.
- Duplicate same-file heading titles are marked ~ambiguous~.
- Lookup does not scan other files.
- Raw link source fields remain unchanged.
- Non-star fuzzy links remain unsupported.
- ~make ci~ passes.
#+end_src

* Planning

** Problem summary
- The resolver already handles explicit file heading-title search for =file:...::*Heading=, but same-file fuzzy star links still fall through to the unsupported fallback.
- This task needs same heading-title matching semantics with an implicit file target equal to the source file.

** Goals
- Resolve =link_type = fuzzy= links whose stored =path= starts with exactly one =*= against headings in the source file.
- Preserve raw link fields, including descriptions and the original fuzzy path text.
- Keep all non-star fuzzy forms unsupported.

** Non-goals
- No non-star fuzzy links such as =[[Heading]]=.
- No dedicated targets, radio targets, named elements, attachment, CUSTOM_ID, ID, regexp, or line-number resolution.
- No cross-file scan.

- Extend the resolver's link dispatch with a dedicated same-file star fuzzy branch before the unsupported fallback.
- Reuse the same normalized heading-title extraction and matching helpers used for file heading-title search.
- Keep duplicate semantics task-specific:
  - same-file star fuzzy duplicates remain =ambiguous=
  - file heading-title duplicates keep their current first-match selection behavior
