* Planning

** Problem summary

Nested ~(headings ...)~ relation queries currently use a real-heading-only SQL scope, so preamble/root nodes cannot match relation predicates.

** Goals

- Use the all-headings scope for nested heading relation queries.
- Preserve nested file query behaviour and level-0 file-shaped results.
- Cover link endpoint and heading/file relation predicates with root-focused regressions.
- Document the level-0 relation-query domain.

** Non-goals

- Do not change hierarchy or ~has-link~ compilation.
- Do not change the database schema or query syntax.

** Architecture

~compile_nested_target_exists~ is shared by structured ~source~, ~target~, ~links-to~, and ~linked-from~ predicates. Selecting ~AllHeadings~ there updates every nested heading relation consistently.

** Execution plan

1. Select an all-headings scope only for nested heading targets.
2. Seed file-root link targets with both file and heading IDs.
3. Add SQL and execution regressions covering root sources and targets.
4. Update query-model and CLI documentation, then run the full CI check.

** Risks & assumptions

The resolver represents a resolved file root as both ~target_file_id~ and ~target_heading_id~. Fixtures will mirror that invariant so target-heading relations can match roots.
