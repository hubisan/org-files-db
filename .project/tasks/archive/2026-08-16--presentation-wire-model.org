Goal: Separate original query results from presentation rows and visible cells.

The presentation response should conceptually contain:

#+begin_example
presentation_version
database_id
generation
results
rows
#+end_example

~results~ contains each original query result once.

Each row contains:

#+begin_example
result_index
row_context
cells
#+end_example

For normal one-row-per-result presentation:

#+begin_example
row_context = null
#+end_example

Each cell contains:

#+begin_example
search_text
display_text
role
#+end_example

Definitions:

- ~search_text~ contains the complete logical value.
- ~display_text~ contains the final visible value after truncation and padding.
- ~role~ contains the semantic presentation role.

Rows may be sorted independently of the order of ~results~.

Do not duplicate the complete result object inside every row.

Do not add generic rich-text ranges.

Acceptance criteria:

- Results and presentation rows are separate representations.
- Rows refer to results using ~result_index~.
- Full values survive visible truncation.
- The model permits several future rows to reference one result.
- ~database_id~ and ~generation~ identify the originating database snapshot.

* Planning

** Problem summary

The presentation module now defines the input specification, public columns, and semantic roles. It does not define the output wire types yet.

The next presentation stages need stable output types before they can extract values or build final rows.

** Goals

- Add one versioned presentation response type.
- Store each original ~QueryResultNode~ once in ~results~.
- Let rows reference original results with ~result_index~.
- Keep normal ~row_context~ values null.
- Define structured row-context shapes for later tag, property, and keyword expansion.
- Store complete ~search_text~ separately from visible ~display_text~.
- Store one optional typed ~PresentationRole~ per cell.
- Keep ~database_id~ and ~generation~ in the response snapshot metadata.

** Non-goals

- Do not connect the wire model to CLI output yet.
- Do not implement value extraction.
- Do not implement inferred includes.
- Do not sort rows.
- Do not calculate widths, truncate text, or add padding.
- Do not implement row expansion execution.
- Do not add role ranges or other rich-text metadata.

** Architecture

Add these public wire types to ~src/presentation.rs~:

#+begin_example
PresentationResponse
PresentationRow
PresentationRowContext
PresentationCell
#+end_example

~PresentationResponse~ uses ~PRESENTATION_VERSION = 1~. The constructor sets this version automatically.

~results~ stores the existing ~QueryResultNode~ values without changing the stable query JSON model.

~PresentationRowContext~ is a tagged enum. It defines the future wire shapes without executing row expansion.
