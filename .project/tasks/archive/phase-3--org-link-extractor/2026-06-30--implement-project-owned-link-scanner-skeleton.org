Goal:

- Implement a small scanner over raw Org source text that detects link tokens independently of Orgize link-node support.
- Make scanner behavior deterministic before storage and full edge-case handling are implemented.

Contract copied from Phase 3 SPEC:

- Link-token extraction is owned by the project scanner.
- Orgize link nodes are optional cross-checks, not the contract.
- Bracket links and angle links are syntax-driven.
- Plain links are protocol-list-driven.
- Scanner must not resolve link targets.
- Scanner must not execute link targets.
- Scanner must return byte ranges using zero-based half-open semantics.
- Scanner must preserve 1-based line number for token start.
- Scanner must not parse links across newlines.
- Scanner must avoid matching inside ignored regions once ignored-region ranges are available.

Scanner priority:

,#+begin_src text
1. If current position starts with [[, try parse bracket link.
2. Else if current char is <, try parse angle link.
3. Else try parse configured plain link.
4. Otherwise advance by one character.
,#+end_src

Scope:

- Scan left-to-right over raw Org source bytes/text.
- Return raw link tokens with:
  - ~format~
  - ~raw~
  - ~raw_target~
  - ~raw_description~
  - ~link_type~
  - ~path~
  - ~search_option~
  - ~byte_start~
  - ~byte_end~
  - ~line~
- Accept structural context from the outer Org parser where needed.
- Do not store links yet unless storage wiring is already available.
- Do not implement every edge case in this skeleton.
- Do not depend on Orgize link nodes in scanner core.
#+end_src

* Planning

** Problem summary
- The repository has the Phase 3 storage contract for links but no parser-owned scanner that can extract raw link tokens independently from Orgize link AST support.
- The scanner skeleton needs stable field names and byte/line semantics now, while deferring full edge-case handling and storage wiring to later tasks.

** Goals
- Add a parser-owned link token model with the Phase 3 field names.
- Implement a raw-text scanner module that handles basic bracket, angle, and configured plain-link candidates in the required priority order.
- Keep the scanner free of Orgize dependencies and make Unicode-safe byte positions explicit in tests.

** Non-goals
- No storage/indexer wiring in this task.
- No full ignored-region extractor from structural Org parsing in this task.
- No exhaustive bracket delimiter or file-like search-option handling beyond a deterministic skeleton.

** Architecture
- Keep the scanner in a dedicated =src/parser/link_scanner.rs= module and export it through =src/parser.rs=.
- Define the link row shape as a parser-owned type with DB-compatible field names.
- Accept scanner configuration and structural context as explicit inputs so later parser/indexer work can plug in ignored ranges and protocol policy without changing the scanner core API.

** Execution plan
- Create the active task file and link it from =todo.org=.
- Add the parser-owned link model and scanner module with a small config/context API.
- Add focused unit tests for successful basic candidates, failed candidate recovery, configured protocols, and Unicode-safe byte offsets.
- Run formatter, focused tests, and =make ci= if feasible.

** Risks & assumptions
- Assumption: leaving =search_option = NULL= in the skeleton is acceptable until the dedicated file-like splitting task lands, as long as the field name already exists.
- Risk: plain-link boundary behavior is intentionally conservative here and may need refinement in the later plain-link task.
