Goal:

- Make bracket-link parsing deterministic for escaped brackets, backslashes, invalid targets, permissive descriptions, same-line delimiter behavior, and zero-width delimiter breakers.

Contract:

- Bracket target parsing is stricter than description parsing.
- Reject unescaped ~[~ and ~]~ in the target.
- Allow escaped ~\[~ and ~\]~ in the target.
- Use odd/even backslash escaping for target delimiters.
- Description parsing is permissive.
- In the description part, arbitrary characters may appear, including unescaped ~[~ and ~]~.
- Nested-looking bracket sequences in descriptions are allowed.
- Close description only at the first valid same-line ~]]~ delimiter.
- Treat zero-width characters between delimiter characters as normal text, not as closing delimiters.
- Preserve raw text exactly.
- Preserve ~raw_target~ exactly, including escapes.
- Preserve ~raw_description~ exactly when present.
- Do not normalize description text.
- Do not parse bracket links across newlines.
#+end_src

* Planning

** Problem summary
- The current bracket scanner uses simple substring searches for =][= and =]]=. That is sufficient for basic links, but it does not implement the required odd/even backslash escaping semantics or strict target validation.

** Goals
- Make target delimiter handling deterministic with explicit escape logic.
- Preserve permissive description parsing and same-line close behavior.
- Keep invalid bracket candidates non-fatal so later valid links are still detected.

** Non-goals
- No storage redesign.
- No angle-link or plain-link storage work.
- No link resolution.
- No broader ignored-region work in this task.

** Architecture
- Replace the bracket parser’s substring shortcut with small helper functions that scan target text and description delimiters explicitly.
- Keep the outer scanner left-to-right and line-local.
- Add focused scanner tests rather than broad integration churn unless existing end-to-end tests fail.
