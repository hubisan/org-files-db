Goal:

- Resolve ~file:...::*Heading~ links to both the target file and, when possible, the matching heading in that file.
- Extend the existing file-link resolver only for heading-title search options.
- Do not implement CUSTOM_ID, ID, attachment, regexp, line-number, or dedicated-target search resolution in this task.

Supported forms:

- ~[[file:notes.org::*Heading]]~
- ~[[file:notes.org::*TODO Heading]]~
- ~[[file:notes.org::*\[2026-07-01 Wed\] Implement deterministic link resolution pass after rebuild]]~

Resolution rules:

- First resolve the file path using the existing file-link resolver.
- If file resolution fails, do not attempt heading-title resolution.
- Interpret ~search_option~ beginning with ~*~ as heading-title search.
- Strip exactly one leading ~*~ from the search option before matching.
- Unescape Org link escapes needed for heading text matching, including:
  - ~\[~ -> ~[~
  - ~\]~ -> ~]~
- Search headings only in the resolved target file.
- Exclude synthetic root headings from heading-title matching.
- Match against the stored normalized heading title field, not the raw line.
- Do not include TODO keyword, priority, tags, or planning metadata unless they are part of the stored heading title.
- If exactly one heading matches:
  - keep ~target_file_id~
  - set ~target_heading_id~
  - set ~resolution_status = resolved~
  - set ~resolution_diagnostic = NULL~
- If no heading matches:
  - keep ~target_file_id~
  - set ~target_heading_id = NULL~
  - set ~resolution_status = broken~
  - set ~resolution_diagnostic~ explaining that the heading title search target is missing in the resolved file.
- If multiple headings match:
  - keep ~target_file_id~
  - set ~target_heading_id = NULL~
  - set ~resolution_status = ambiguous~
  - set ~resolution_diagnostic~ explaining that multiple headings in the resolved file match the search option.
- Preserve ~search_option~ as a raw source fact.

Out of scope:

- Do not resolve ~file:...::#CUSTOM_ID~.
- Do not resolve ~file:...::/regexp/~.
- Do not resolve ~file:...::42~.
- Do not resolve dedicated targets.
- Do not resolve same-file fuzzy heading links such as ~[[*Heading]]~.
- Do not resolve ~id:~ links.
- Do not resolve ~CUSTOM_ID~ links outside this file-search-option form.
- Do not resolve ~attachment:~ links.
- Do not scan unrelated files.
- Do not execute, open, or follow link targets.

Acceptance criteria:

- ~file:...::*Heading~ resolves to the target file first.
- Matching heading-title search options resolve to ~target_heading_id~.
- Escaped bracket syntax like ~\[2026-07-01 Wed\]~ is handled correctly.
- Missing headings in a resolved target file are marked ~broken~.
- Duplicate matching headings in the target file are marked ~ambiguous~.
- Heading-title lookup does not scan unrelated files.
- File links without heading-title search options keep existing file-resolution behavior.
- File links with unsupported search options keep existing file target resolution and do not set ~target_heading_id~.
- Existing ~search_option~ values remain unchanged.
- Raw link source fields remain unchanged.
- No CUSTOM_ID, ID, attachment, regexp, line-number, dedicated-target, or fuzzy-link resolution is implemented.

* Planning

** Problem summary
- File-link resolution already resolves =path_absolute= and =target_file_id=, but it ignores heading-title search options entirely.
- This task needs a second-stage resolver that only runs after a file target is resolved and only inspects headings from that single target file.

** Goals
- Resolve =search_option= values beginning with =*= against stored normalized heading titles in the resolved target file.
- Keep existing file-only behavior unchanged for links without heading-title search options and for unsupported search-option forms.
- Preserve raw link source facts, including the original =search_option= text with escapes.

** Non-goals
- No CUSTOM_ID, ID, regexp, line-number, dedicated-target, attachment, or same-file fuzzy-link resolution.
- No scans outside the resolved target file.
- No schema change.

** Architecture
- Extend the resolver's loaded link row to include =search_option=.
- After file-path resolution finds a known target file, branch:
  - no heading-title search option: keep current resolved-file behavior
  - heading-title search option: unescape the match text, query headings in =target_file_id= excluding =level = 0=, and resolve =target_heading_id= based on exact normalized-title matches
  - unsupported search option: keep the resolved file target and leave heading target unset
- Use explicit diagnostics for missing and ambiguous heading-title matches.

** Execution plan
- Create the active task file and link it from =todo.org=.
- Implement heading-title search-option handling in =src/link_resolver.rs= with focused helper functions.
- Add resolver and rebuild coverage for resolved, broken, ambiguous, escaped-bracket, and unsupported-search-option cases.
- Update docs/changelog if behavior descriptions need to mention heading-title resolution.
- Run formatter, focused tests, and =make ci=.

** Risks & assumptions
- Assumption: heading-title matching should use the stored =headings.title= field exactly as written in the DB, because that is the normalized title contract already exposed elsewhere.
- Risk: unsupported search-option forms now coexist with a resolved file target, so tests need to pin that contract clearly to avoid regressions in later resolver tasks.
