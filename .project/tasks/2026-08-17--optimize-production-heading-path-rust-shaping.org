Optimize production heading path Rust construction and shaping.

* Planning

** Problem summary

The Rust-driven path loader is faster than the recursive loader in the isolated benchmark.

The complete production ~headings.path~ workload regresses at ~50'000~ results after the loader switch.

The current production path construction allocates temporary sets and vectors for every matched heading.

Final direct-flat shaping also clones each complete ~Vec<PathEntry>~ from ~heading_paths~.

** Goals

- Add a same-process A/B benchmark for the complete production ~headings.path~ composition.
- Keep the existing recursive loader as the benchmark reference.
- Move heading paths into final result nodes instead of cloning them.
- Reduce temporary allocations in Rust path construction.
- Preserve query output, ordering, validation errors, and public APIs.
- Measure 100, 1'000, 10'000, and 50'000 results after the change.

** Non-goals

- Do not change SQL query semantics.
- Do not change the public query JSON format.
- Do not add dependencies.
- Do not remove the recursive benchmark reference.
- Do not optimize unrelated query workloads in this task.

** Architecture

Add an internal path loader selector to the direct-flat shaping path.

Production always selects ~rust-driven-bulk-ancestors~.

The benchmark can select ~recursive-query-derived~ for a complete same-process reference run.

Consume each loaded heading path during direct-flat shaping so its result owns the path without a full vector clone.

Build each Rust heading path with one output vector. Reuse one small cycle-detection vector across origins.

** Execution plan

1. Add the benchmark-only complete production path A/B.
2. Make ~FlatMetadataContext~ consume loaded heading paths during direct-flat shaping.
3. Move ~heading_paths~ entries into result nodes with ~HashMap::remove~.
4. Replace per-heading ~BTreeSet~ cycle tracking with one reused vector.
5. Build common-case heading paths directly into the final ~Vec<PathEntry>~.
6. Keep the fallback file-root path for malformed legacy chains.
7. Add regression tests for path output and metadata move behavior.
8. Run ~make ci~ when the Rust toolchain is available.
9. Run the release benchmark at all standard result sizes.

** Risks & assumptions

Each direct-flat matched row appears once in the final result.

Removing a heading path by row ID is safe only under that invariant.

Deep cyclic parent chains can make linear cycle checks more expensive.

Typical Org heading depth is small, and the reused vector removes per-result tree allocations.
