Implement the Phase 7 backend-independent watcher input model and deterministic candidate batching without adding ~notify~, debounce, threads, channels, polling, CLI behavior, parsing, or database mutation.

* Planning

** Problem summary

Filesystem backends emit duplicate, reordered, incomplete, and backend-specific event sequences. Phase 7 needs a deterministic boundary that converts those hints into Phase 6 candidate paths or a full reconciliation request without creating a second source-universe, exclusion, canonicalization, or identity model.

** Goals

- Add a backend-independent raw watcher input model.
- Normalize eligible paths through the Phase 6 discovery universe.
- Preserve missing, renamed-away, symlinked, explicit-file, exclusion, and non-UTF-8 path semantics.
- Deduplicate and order candidates by Phase 6 native Unix identity.
- Escalate incomplete rename and backend uncertainty to full reconciliation.
- Cover all required combinations with deterministic unit tests.

** Non-goals

- No ~notify~ dependency or live filesystem watcher.
- No debounce timing, threads, channels, polling, controller, CLI, parsing, or DB writes.
- No direct create, modify, or delete decision from an event kind.

** Architecture

- Keep watcher event and batch types in a new internal ~watcher~ module.
- Expose a narrow Phase 6 candidate-path normalizer backed by the existing discovery-produced ~IndexedUniverse~.
- Retain logical-to-canonical file mappings in ~IndexedUniverse~ so deleted paths and symlink aliases resolve to the same native identity previously discovered by Phase 6.
- Represent batch output as either ordered candidate paths or a full reconciliation request.

** Execution plan

- Extend the Phase 6 indexed universe with reusable source-path normalization helpers.
- Add the watcher input, uncertainty, output, and batch-normalizer types.
- Add deterministic unit tests for all acceptance scenarios.
- Document only the implemented batching contract.

** Risks & assumptions

- The normalizer is a source-universe snapshot. Later startup and recovery work must refresh it through the documented Phase 6 reconciliation lifecycle when the configured universe changes or backend uncertainty occurs.
- Directory replacement and watch-root uncertainty remain recovery concerns for later Phase 7 tasks.
