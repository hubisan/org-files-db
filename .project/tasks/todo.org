* Phase 5: Query engine and optional full-text search

Goal of this phase:

- Build a small, safe query layer for indexed Org graph data.
- Implement the Query Model v0 contract defined in [[file:../../docs/reference/query-model-v0.org][Query Model v0 Specification]].
- Keep the query model independent from CLI and SQL.
- Support headings, links, and files as explicit query targets.
- Keep full-text search optional and separate from the core query model.
- Return stable JSON that is useful for Emacs/editor integrations.

General rules:

- Query AST/model is independent of CLI and SQL.
- SQL generation must use bound parameters.
- Query execution uses the persisted database, not parser re-analysis.
- Query target is explicit through ~(headings ...)~, ~(links ...)~, and ~(files ...)~.
- Bare predicates are shorthand for heading queries only at the top level.
- Nested relation queries must use explicit target wrappers.
- Query output mode must not change match semantics.
- Include options may enrich results but must not change which objects match.
- Direct parsed facts and effective/derived semantics must stay clearly separated.
- Query results must include enough location data for editor jumps.
- Body text search must fail clearly when body text is unavailable.
- FTS5 is optional and must only be required for FTS-specific functionality.
- Mutation and repair operations are out of scope for Query Model v0.

** REVIEW [#B] Index FTS title from ~title_raw~
:PROPERTIES:
:PRIORITY: Medium
:RISK: Medium
:DB_SCHEMA_CHANGE: No
:API_CONTRACT_CHANGE: Yes
:END:

- Task file: [[file:2026-07-23--index-fts-title-from-title-raw.org]]

Goal:

- Change the derived FTS ~title~ content from the normalized semantic heading title to the source-oriented ~title_raw~ value.
- Make quick full-text search find TODO keywords, priority cookies, and statistics cookies present in the Org headline.
- Preserve normalized ~title~ semantics everywhere outside the dedicated ~search~ command.

Current implementation:

- ~DbWriter::rebuild_heading_fts~ currently populates ~heading_fts.title~ directly from ~headings.title~.
- ~heading_fts~ is a contentless FTS5 table with the columns ~title~ and ~body~.
- Search retrieves only heading IDs and BM25 ranks from FTS; the public result fields already come from the canonical heading/root serializer.
- Real heading ~title_raw~ preserves the source title area after the headline stars, including:
  - TODO keywords
  - priority cookies such as ~[#A]~
  - statistics cookies such as ~[2/5]~ and ~[50%]~
- Trailing Org tags are deliberately excluded from ~title_raw~.
- Synthetic roots without a source ~#+TITLE~ have:
  - an effective fallback ~title~ derived from the file stem
  - ~title_raw = null~

Required FTS content:

- Populate ~heading_fts.title~ from:

#+begin_src sql
COALESCE(headings.title_raw, headings.title)
#+end_src

- Use ~title_raw~ whenever it is available.
- Fall back to the canonical ~title~ when ~title_raw~ is null.
- The fallback is required so roots without a source ~#+TITLE~ remain searchable by their effective file-stem title.
- Do not append tags, TODO fields, priority fields, properties, keywords, planning values, or other metadata separately.
- Do not change the physical ~heading_fts~ table shape.
- Keep the public FTS column name ~title~.
- Keep ~body~ population and ~search.index_body_text~ behaviour unchanged.

Public semantics:

- ~orgfdb search --json --title EXPRESSION~ must search the source-oriented title text represented by ~title_raw~, with the root fallback described above.
- Default ~orgfdb search --json EXPRESSION~ must search:
  - source-oriented title text
  - body text when body indexing is enabled
- ~orgfdb search --json --body EXPRESSION~ remains unchanged.
- TODO keywords may now match through their textual occurrence in ~title_raw~.
- Priority and statistics cookie tokens may now participate according to SQLite FTS5 tokenization.
- Trailing Org tags must not become searchable through ~heading_fts.title~ because they are not part of ~title_raw~.
- Search remains raw SQLite FTS5 matching, not structured TODO, priority, statistics, or tag matching.
- For precise structured matching, users must continue to use Query Model v0 predicates such as:
  - ~(todo "NEXT")~
  - ~(priority "A")~
  - ~(tags "project")~
  - ~(title "Searchable Heading")~

Unchanged semantics:

- Do not change the Query Model v0 ~(title ...)~ predicate.
- ~(title ...)~ must continue matching the normalized semantic ~headings.title~ value.
- Do not change ~title~ or ~title_raw~ storage.
- Do not change parsing or normalization of headline titles.
- Do not include trailing Org tags in ~title_raw~.
- Do not change link resolution by normalized heading title.
- Do not change ~has-text~.
- Do not change search JSON serialization.
- Do not add additional FTS columns or new search options.
- Do not scan source files during search.

FTS contract version:

- Treat the indexed title source as part of the persisted FTS content contract.
- Increment ~FTS_SCHEMA_CONTRACT_VERSION~ from ~"2"~ to ~"3"~.
- A database carrying trusted FTS contract version ~"2"~ must be treated as stale and must instruct the user to run:

#+begin_src shell
orgfdb rebuild
#+end_src

- Do not classify the known older version ~"2"~ as invalid trust metadata.
- Adjust trust-metadata validation so valid older contract versions are recognised as stale rather than malformed.
- Prefer parsing ~fts_schema_version~ as a non-negative integer:
  - current version → trusted
  - valid older or newer numeric version → incompatible or stale index
  - missing or non-numeric value → missing or invalid trust metadata as appropriate
- Preserve the existing clear rebuild-required error for stale FTS contracts.
- Rebuild must persist ~fts_schema_version = "3"~ only after the new index has been populated successfully.
- This requires an index rebuild but no database schema migration and no ~PRAGMA user_version~ change.

Implementation:

- Change the single ~INSERT INTO heading_fts ... SELECT ... FROM headings~ population query in ~DbWriter::rebuild_heading_fts~.
- Continue deriving every FTS row from the canonical ~headings~ and ~heading_bodies~ tables.
- Preserve one FTS row per canonical heading ID, including level-0 roots.
- Preserve contentless FTS operation.
- Preserve the current tokenizer and BM25 query implementation.
- Preserve deterministic search ordering:
  1. ~rank~ ascending
  2. canonical heading ~id~ ascending
- Do not promise identical numeric ranks or identical ordering between differently matching documents, because changing indexed title text may legitimately affect BM25 scores.
