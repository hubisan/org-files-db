* Phase 5: Query engine and optional full-text search

Goal of this phase:

- Build a small, safe query layer for indexed Org graph data.
- Implement the Query Model v0 contract defined in [[file:../../docs/reference/query-model-v0.org][Query Model v0 Specification]].
- Keep the query model independent from CLI and SQL.
- Support headings, links, and files as explicit query targets.
- Keep full-text search optional and separate from the core query model.
- Return stable JSON that is useful for Emacs/editor integrations.

General rules:

- Query AST/model is independent of CLI and SQL.
- SQL generation must use bound parameters.
- Query execution uses the persisted database, not parser re-analysis.
- Query target is explicit through ~(headings ...)~, ~(links ...)~, and ~(files ...)~.
- Bare predicates are shorthand for heading queries only at the top level.
- Nested relation queries must use explicit target wrappers.
- Query output mode must not change match semantics.
- Include options may enrich results but must not change which objects match.
- Direct parsed facts and effective/derived semantics must stay clearly separated.
- Query results must include enough location data for editor jumps.
- Body text search must fail clearly when body text is unavailable.
- FTS5 is optional and must only be required for FTS-specific functionality.
- Mutation and repair operations are out of scope for Query Model v0.

** TODO [#B] Complete date-only and datetime query-bound semantics
:PROPERTIES:
:PRIORITY: Medium
:RISK: Medium
:DB_SCHEMA_CHANGE: No
:API_CONTRACT_CHANGE: Yes
:END:

Depends on:

- Add configurable query timezone and deterministic relative-date resolution
- [[file:../../docs/reference/query-model-v0.org][Query Model v0 Specification]]

Goal:

- Define and implement consistent semantics for date-only and datetime arguments used with ~:on~, ~:from~, and ~:to~.
- Keep query bounds consistent with the timezone-naive representation of indexed Org timestamps.

Rules:

- Date-only arguments represent calendar-day boundaries.
- Date-only ~:on~ matches the complete specified calendar day.
- Date-only ~:from~ uses an inclusive start-of-day boundary.
- Date-only ~:to~ includes the complete specified day by using an exclusive next-day boundary.
- Datetime arguments use their explicit hour and minute.
- Datetime arguments are not converted between timezones.
- Datetime ~:from~ bounds are inclusive.
- Datetime ~:to~ bounds follow the query model's documented upper-bound semantics.
- Resolved dates and datetimes use the same timezone-naive representation as indexed Org timestamps.
- Stored Org timestamps must not be converted between timezones.

Acceptance criteria:

- Date-only ~:on~, ~:from~, and ~:to~ semantics are documented.
- Datetime ~:on~, ~:from~, and ~:to~ semantics are documented.
- A date-only ~:to~ value includes timestamps throughout the specified day.
- A date-only ~:to~ value excludes timestamps from the following day.
- Explicit datetime arguments preserve their stated hour and minute.
- Tests distinguish date-only bounds from datetime bounds.
- Tests cover explicit midnight datetime arguments.
- Tests cover month-end and year-end next-day boundaries.
- Tests cover daylight-saving transition dates without converting stored values.
- Query SQL continues to use bound parameters for all resolved values.
