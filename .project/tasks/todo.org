* Phase 5: Query engine and optional full-text search

Goal of this phase:

- Build a small, safe query layer for indexed Org data.
- Keep the query model independent from CLI and SQL.
- Prepare the design so it can later grow toward an org-ql-like language.
- Keep full-text search optional.

General rules:

- Query AST/model is independent of CLI and SQL.
- SQL generation must use bound parameters.
- FTS5 is optional and must only be required for FTS-specific functionality.
- FTS-dependent operators must fail clearly when FTS5 is disabled.
- Direct parsed facts and effective/derived semantics must stay clearly separated.
- Query results should include enough location data for editor jumps.

** TODO [#B] Define effective property semantics
:PROPERTIES:
:PRIORITY: Medium
:RISK: High
:API_CONTRACT_CHANGE: Yes
:END:

Goal:

- Define how direct property rows are resolved into effective property values for query/API use.

Context:

- The ~properties~ table stores direct source facts only.
- Parsing and indexing do not collapse duplicate rows.
- Parsing and indexing do not compute final effective values.
- Direct property rows remain the source of truth.

Definitions:

- Direct property :: A property row exactly as parsed from the source file and stored in the ~properties~ table.
- Effective property :: The resolved value for a heading after applying overwrite, append, source precedence, and optional inheritance.
- Direct property query :: A query against raw property rows.
- Effective property query :: A query against resolved property values.

Rules:

- Later direct definitions with the same key override earlier non-append definitions in effective mode.
- Rows with ~append = 1~ append to the current effective value, separated by a single space.
- If an append row appears before any base value, it starts the value.
- Effective inheritance is optional.
- Queries must be able to request direct-only behavior.
- Direct heading drawer properties override inherited/default values.
- Child heading append rows append to the inherited/current value.

Effective inherited precedence:

1. Level 0 ~#+PROPERTY~ defaults.
2. Level 0 ~#+CATEGORY~ as ~CATEGORY~ property.
3. Level 0 property drawer.
4. Ancestor heading property drawers from root to parent.
5. Current heading property drawer.

Acceptance criteria:

- Direct property rows remain unchanged.
- Direct and effective property queries are clearly distinguished.
- Duplicate direct definitions are resolved only in effective mode.
- Later non-append definitions override earlier effective values.
- Append rows append to the current effective value.
- Append without prior base value starts the value.
- Inheritance behavior is explicit and optional.
- Level 0 property behavior is documented.
- Tests cover overwrite, append, append without prior base value, level 0 properties, drawer-over-keyword override, and child append with inheritance.

Open questions:

- Should effective properties be computed in Rust query/API code first?
- Is a SQL view or cache table needed later for performance?
- Should v0 expose both direct and effective operators immediately?

** TODO [#C] Enable optional SQLite FTS5 for full-text search
:PROPERTIES:
:PRIORITY: Low
:RISK: Medium
:DB_SCHEMA_CHANGE: Maybe
:END:

Goal:

- Create and maintain an optional FTS5 table for heading title and optional body search.

Planned table when FTS5 is enabled:

#+begin_src sql
  CREATE VIRTUAL TABLE heading_fts
  USING fts5(
      title,
      body,
      tokenize = 'unicode61'
  );
#+end_src

Rules:

- FTS5 support is configured through ~search.fts5_enabled~.
- Body indexing is configured separately through ~search.index_body_text~.
- FTS5 must not be required unless FTS-specific functionality is enabled.

Acceptance criteria:

- If FTS5 is disabled, rebuild works without creating or writing ~heading_fts~.
- If FTS5 is enabled, ~heading_fts~ is created and maintained.
- ~heading_fts.rowid~ matches ~headings.id~.
- Heading titles are indexed when FTS5 is enabled.
- Heading body text is indexed only when both ~search.fts5_enabled~ and ~search.index_body_text~ are enabled.
- Search can match title-only, body-only, or both when enabled.
- Body indexing can be disabled even when FTS5 is enabled.
- Search/query commands handle disabled FTS5 clearly.
