#+begin_src text

** TODO Normalize `title` and preserve `title_raw` for headings

Goal:
Make heading title fields match the documented schema semantics.

Context:
The schema documents two different title fields:

- `title` is the normalized display title.
- `title_raw` preserves more of the original Org heading syntax after TODO keyword extraction.

Current behavior still returns Org markup in `title` for some headings, for example described links:

#+begin_src json
{
  "title": "[[file:natural/hausarzt-krebs-thomas.org][Thomas Krebs - Hausarzt]]",
  "title_raw": "[[file:natural/hausarzt-krebs-thomas.org][Thomas Krebs - Hausarzt]]"
}
#+end_src

For display/search/query use, `title` should contain the human-readable title.

Required behavior:

- Keep `title_raw` as the raw heading title text after TODO keyword extraction.
- Normalize `title` for display use.
- For described Org links in heading titles:
  - `[[file:natural/hausarzt-krebs-thomas.org][Thomas Krebs - Hausarzt]]`
    becomes `Thomas Krebs - Hausarzt` in `title`.
- For Org links without description:
  - use the link target/text in `title`.
  - `[[file:natural/hausarzt-krebs-thomas.org]]`
    becomes `file:natural/hausarzt-krebs-thomas.org` in `title`.
- Remove supported basic Org markup from `title`, including at least:
  - bold
  - italic
  - underline
  - verbatim/code markup if supported by the existing parser representation
- Keep non-markup plain text unchanged.
- Preserve existing TODO keyword, TODO type, priority, tag, line number, byte range, and parent/outline behavior.
- Do not change the DB schema.
- Do not change CLI JSON field names.
- Do not add broad Org rendering support beyond heading title normalization.

Level-0 behavior:

- For synthetic level-0 file headings, set `title` according to the documented rule:
  - use `#+TITLE:` when present
  - otherwise use the file name without path and normally without the `.org` extension
- `title_raw` for level-0 headings should be documented/implemented consistently:
  - either match `title`
  - or preserve the raw source used to derive it
- Do not use the full file path as `title` for level-0 headings; the full path is already available through the `files` table.

Acceptance criteria:

- A heading with a described Org link has normalized `title` and raw `title_raw`.
- A heading with an Org link without description has a normalized `title` based on the link target/text.
- A heading with basic emphasis markup has markup removed from `title` while `title_raw` preserves the source text.
- Plain headings remain unchanged.
- Level-0 headings use `#+TITLE:` when present.
- Level-0 headings fall back to the file stem when no `#+TITLE:` exists.
- Existing parser adapter tests still pass.
- Add focused parser/indexer tests for the new title behavior.
- No DB schema changes are made.

** TODO Respect file-local TODO keyword config in parser/indexer pipeline

Goal:
Ensure file-local `#+TODO:` keyword definitions are used when parsing headings.

Context:
A file with this setup:

#+begin_src org
  ,#+TODO: TODO(t) NEXT(n) PLAN(p) | DONE(d) CANCEL(c)

  ,* PLAN me
  ,* DONE me
#+end_src

currently produces headings where `PLAN` is not recognized as a TODO keyword:

#+begin_src json
{
  "title": "PLAN me",
  "todo_keyword": null,
  "todo_type": null
}
#+end_src

Expected behavior:
`PLAN` should be recognized as an open TODO keyword and removed from the display/raw title fields according to the existing title semantics.

Required behavior:

- Read file-local `#+TODO:` keyword definitions before or during parsing.
- Use file-local TODO keywords for that file when identifying heading TODO keywords.
- File-local TODO config should override or extend the configured project/default TODO keywords according to the existing project decision. If no decision exists, prefer file-local override for that file.
- Recognize open keywords before `|` and closed keywords after `|`.
- Preserve fast-selection keys such as `(p)`, `(d)` where the internal model supports them.
- Keep existing default/configured TODO keyword behavior working.
- Do not change DB schema.
- Do not change CLI JSON field names.
- Do not implement unrelated Org keyword parsing.

Acceptance criteria:

- With `#+TODO: TODO(t) NEXT(n) PLAN(p) | DONE(d) CANCEL(c)`, `* PLAN me` has `todo_keyword = "PLAN"` and an open TODO type.
- With the same config, `* DONE me` has `todo_keyword = "DONE"` and a closed TODO type.
- The displayed/raw title for those headings no longer includes the TODO keyword.
- A heading `* REVIEW Mist` is handled according to the file-local config:
  - if `REVIEW` is not in `#+TODO:`, it is not treated as a TODO keyword
  - if a project/default config includes `REVIEW`, document whether file-local config overrides or extends it
- File-local TODO parsing is covered by parser adapter or indexer tests.
- End-to-end rebuild plus `headings --json` returns TODO keyword/type values for file-local TODO keywords.

** TODO Compute inherited tags for `all_tags_json`

Goal:
Make `all_tags_json` match its documented schema semantics.

Context:
The schema documents `all_tags_json` as all tags visible on a heading, including inherited tags. Current output only contains local heading tags.

Example:

#+begin_src org
  ,* TODO me :test:
  ,** again :me:
#+end_src

Current output for `again`:

#+begin_src json
{
  "title": "again",
  "all_tags_json": "[\"me\"]"
}
#+end_src

Expected output:

#+begin_src json
{
  "title": "again",
  "all_tags_json": "[\"test\", \"me\"]"
}
#+end_src

Required behavior:

- Keep normalized local tag rows in the `tags` table.
- Compute `all_tags_json` as the visible/effective tag set for each heading.
- Include inherited tags from ancestor headings.
- Include local tags from the heading itself.
- Avoid duplicate tags in `all_tags_json`.
- Preserve a stable deterministic order:
  - ancestor tags from outermost to innermost
  - then local tags
  - or document and test another deterministic order
- Do not change the DB schema unless unavoidable.
- Do not change parser-specific public types unless needed.
- Do not implement inherited properties in this task.

Acceptance criteria:

- A child heading inherits parent tags in `all_tags_json`.
- A heading with both inherited and local tags includes both.
- Duplicate tags are not repeated.
- Local tag rows in `tags` still represent local heading tags only.
- Existing tag tests still pass.
- Add focused parser/indexer/query tests for inherited tag behavior.
