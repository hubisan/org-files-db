* Phase 5: Query engine and optional full-text search

Goal of this phase:

- Build a small, safe query layer for indexed Org graph data.
- Implement the Query Model v0 contract defined in [[file:../../docs/reference/query-model-v0.org][Query Model v0 Specification]].
- Keep the query model independent from CLI and SQL.
- Support headings, links, and files as explicit query targets.
- Keep full-text search optional and separate from the core query model.
- Return stable JSON that is useful for Emacs/editor integrations.

General rules:

- Query AST/model is independent of CLI and SQL.
- SQL generation must use bound parameters.
- Query execution uses the persisted database, not parser re-analysis.
- Query target is explicit through ~(headings ...)~, ~(links ...)~, and ~(files ...)~.
- Bare predicates are shorthand for heading queries only at the top level.
- Nested relation queries must use explicit target wrappers.
- Query output mode must not change match semantics.
- Include options may enrich results but must not change which objects match.
- Direct parsed facts and effective/derived semantics must stay clearly separated.
- Query results must include enough location data for editor jumps.
- Body text search must fail clearly when body text is unavailable.
- FTS5 is optional and must only be required for FTS-specific functionality.
- Mutation and repair operations are out of scope for Query Model v0.

** BUILD [#B] Add ~:inherit~ control to heading ~keyword~ queries
:PROPERTIES:
:PRIORITY: High
:RISK: Low
:DB_SCHEMA_CHANGE: No
:API_CONTRACT_CHANGE: Yes
:END:

Goal:

- Add ~:inherit t|nil~ to the ~keyword~ predicate for heading queries.
- Keep inherited keyword matching enabled by default.
- Allow callers to restrict matching to keywords local to the candidate heading.

Current behaviour:

- Document keywords are indexed exclusively on the synthetic level-0 heading of a file.
- Heading ~keyword~ predicates always query the synthetic file root:

#+begin_src rust
"keyword" => {
    compile_keyword_predicate(
        QueryTarget::Headings,
        predicate,
        &scope.root_col("id"),
    )
}
#+end_src

- Consequently, every heading in a matching file currently matches the document keyword.
- The query validator permits only ~:regexp~ for ~keyword~ and rejects ~:inherit~.
- There is currently no way to disable inherited keyword matching.

Required semantics:

- Heading ~keyword~ queries accept ~:inherit t|nil~.
- Omitted ~:inherit~ is equivalent to ~:inherit t~.
- With ~:inherit t~, match keywords stored on the synthetic file root.
- With ~:inherit nil~, match only keywords stored directly on the candidate heading.
- File queries continue to operate directly on the synthetic file root and do not accept an ~:inherit~ option.

The resulting behaviour is:

#+begin_src text
Heading target, :inherit t or omitted:
- synthetic file heading: match file keywords
- ordinary heading: match file keywords
- nested heading: match file keywords

Heading target, :inherit nil:
- synthetic file heading: match its local file keywords
- ordinary heading: no match unless local heading keywords are introduced in the future
- nested heading: no match unless local heading keywords are introduced in the future

File target:
- match file keywords
- :inherit is not accepted
#+end_src

Rationale:

- Keywords are currently document-level facts and are stored only on the synthetic level-0 heading.
- Treating them as inherited for ordinary headings is useful and remains the default.
- ~:inherit nil~ must nevertheless provide a consistent local-only mode, as already supported by heading ~tags~ and ~property~ predicates.
- Local-only matching must refer to the candidate heading rather than the containing file root.
- No parser, index, or schema change is required.

Implementation tasks:

- Update ~validate_keyword~ so that allowed options depend on the query target:
  - headings: ~inherit~, ~regexp~
  - files: ~regexp~
- Validate ~:inherit~ as an optional boolean for heading queries.
- Keep the default value of ~:inherit~ equal to ~t~.
- Add a heading-specific keyword compiler or select the keyword owner ID before calling ~compile_keyword_predicate~.
- For heading queries:
  - use ~scope.root_col("id")~ when ~:inherit~ is omitted or ~t~
  - use ~scope.heading_col("id")~ when ~:inherit nil~
- Keep file keyword compilation unchanged.
- Apply the same inheritance selection to:
  - key-only queries
  - key-and-value queries
  - exact value matching
  - regular-expression value matching
- Do not copy document keywords onto every heading.
- Do not change keyword persistence or the database schema.

Expected examples:

Given:

#+begin_src org
#+TITLE: keyword-fixture-kwd7

,* keyword: First Heading kwd7-a

,* keyword: Second Heading kwd7-b

,** keyword: Nested Heading kwd7-c
#+end_src

The default query:

#+begin_src lisp

  (keyword "AUTHOR" "Author-kwd7-unique"))
#+end_src

is equivalent to:

#+begin_src lisp
(headings
  (keyword "AUTHOR" "Author-kwd7-unique" :inherit t))
#+end_src

Both match:

#+begin_src text
keyword-fixture-kwd7
keyword: First Heading kwd7-a
keyword: Second Heading kwd7-b
keyword: Nested Heading kwd7-c
#+end_src

The local-only query:

#+begin_src lisp
(headings
  (keyword "AUTHOR" "Author-kwd7-unique" :inherit nil))
#+end_src

matches only:

#+begin_src text
keyword-fixture-kwd7
#+end_src

The file query remains:

#+begin_src lisp
(files
  (keyword "AUTHOR" "Author-kwd7-unique"))
#+end_src

and matches the containing file.

The following remains invalid:

#+begin_src lisp
(files
  (keyword "AUTHOR" "Author-kwd7-unique" :inherit nil))
#+end_src

Tests:

- Add validator tests proving that heading ~keyword~ accepts:
  - omitted ~:inherit~
  - ~:inherit t~
  - ~:inherit nil~
  - combinations with ~:regexp t~
- Add validator tests proving that file ~keyword~ rejects ~:inherit~.
- Add SQLite execution tests for a file keyword and multiple heading levels.
- Verify that omitted ~:inherit~ and explicit ~:inherit t~ return identical results.
- Verify that ~:inherit nil~ returns only the synthetic level-0 heading.
- Verify key-only matching:

- Verify exact key-and-value matching:

#+end_src

- Verify regular-expression matching:

#+begin_src lisp

#+end_src

- Verify that a non-matching value returns no results in either inheritance mode.
- Verify that the query result still reports the file result as ~kind = "file"~ for the synthetic root.

Documentation:

#+end_src

- Explain that inherited mode uses document keywords from the containing file.
- Explain that ~:inherit nil~ checks only the candidate heading.
- Explain that document keywords are currently stored on the synthetic file heading, so ordinary headings normally do not match in local-only mode.
- State that ~:inherit~ is unavailable for the ~files~ target because file queries already operate at document scope.

- Add one example contrasting inherited and local-only keyword matching.
