* Phase 4: Link resolution

Goal of this phase: Resolve stored raw link source facts to known files, file-scoped CUSTOM_ID targets, and indexed Org ID targets.

General rules:

- Resolution never destroys raw link facts.
- Resolution fields stay clearly separated from raw source fields.
- Broken, ambiguous, unresolved, and unsupported targets are represented explicitly.
- Target deletion must not delete source link rows.
- Resolution must not execute link targets.
- Resolution must be deterministic and repeatable.
- Resolution runs after all files, headings, properties, outline paths, and raw links for the rebuild are stored.
- Do not resolve links on demand in read-only CLI commands.
- Do not introduce parallel ~resolved_file_id~ / ~resolved_heading_id~ columns unless the schema contract is deliberately renamed first.

Existing target-ish fields:

- ~path_absolute~
- ~target_file_id~
- ~target_heading_id~
- ~target_custom_id~
- ~target_id~

Recommended resolution state fields:

- ~resolution_status~
- ~resolution_diagnostic~

Recommended ~resolution_status~ values:

- ~unresolved~
- ~resolved~
- ~broken~
- ~ambiguous~
- ~unsupported~

Status semantics:

- is ~NULL~ means not attempted
- ~unresolved~ means resolution was attempted but the available universe is not known to be complete.
- ~broken~ means the target is missing inside a known complete context.
- ~ambiguous~ means more than one valid target exists in the applicable context.
- ~unsupported~ means the link form is intentionally not resolved yet.
- ~resolved~ means target fields point to the selected target.

Important distinction:

- ~CUSTOM_ID~ resolution is file-scoped.
- ~id:~ resolution is global in Org semantics and should not be marked broken merely because the ID is absent from the indexed files.
- A missing ~CUSTOM_ID~ can be broken when the target file context is known.
- A missing ~id:~ should be ~unresolved~ unless a complete Org ID location universe is available.

** BUILD [#B] Resolve file links with heading-title search options
:PROPERTIES:
:PRIORITY: Medium
:RISK: Medium
:DB_SCHEMA_CHANGE: No
:API_CONTRACT_CHANGE: Maybe
:END:

Depends on:

- [[*Resolve file links to known indexed files][Resolve file links to known indexed files]]

Goal:

- Resolve ~file:...::*Heading~ links to both the target file and, when possible, the matching heading in that file.
- Extend the existing file-link resolver only for heading-title search options.
- Do not implement CUSTOM_ID, ID, attachment, regexp, line-number, or dedicated-target search resolution in this task.

Supported forms:

- ~[[file:notes.org::*Heading]]~
- ~[[file:notes.org::*TODO Heading]]~
- ~[[file:notes.org::*\[2026-07-01 Wed\] Implement deterministic link resolution pass after rebuild]]~

Resolution rules:

- First resolve the file path using the existing file-link resolver.
- If file resolution fails, do not attempt heading-title resolution.
- Interpret ~search_option~ beginning with ~*~ as heading-title search.
- Strip exactly one leading ~*~ from the search option before matching.
- Unescape Org link escapes needed for heading text matching, including:
  - ~\[~ -> ~[~
  - ~\]~ -> ~]~
- Search headings only in the resolved target file.
- Exclude synthetic root headings from heading-title matching.
- Match against the stored normalized heading title field, not the raw line.
- Do not include TODO keyword, priority, tags, or planning metadata unless they are part of the stored heading title.
- If exactly one heading matches:
  - keep ~target_file_id~
  - set ~target_heading_id~
  - set ~resolution_status = resolved~
  - set ~resolution_diagnostic = NULL~
- If no heading matches:
  - keep ~target_file_id~
  - set ~target_heading_id = NULL~
  - set ~resolution_status = broken~
  - set ~resolution_diagnostic~ explaining that the heading title search target is missing in the resolved file.
- If multiple headings match:
  - keep ~target_file_id~
  - set ~target_heading_id = NULL~
  - set ~resolution_status = ambiguous~
  - set ~resolution_diagnostic~ explaining that multiple headings in the resolved file match the search option.
- Preserve ~search_option~ as a raw source fact.

Out of scope:

- Do not resolve ~file:...::#CUSTOM_ID~.
- Do not resolve ~file:...::/regexp/~.
- Do not resolve ~file:...::42~.
- Do not resolve dedicated targets.
- Do not resolve same-file fuzzy heading links such as ~[[*Heading]]~.
- Do not resolve ~id:~ links.
- Do not resolve ~CUSTOM_ID~ links outside this file-search-option form.
- Do not resolve ~attachment:~ links.
- Do not scan unrelated files.
- Do not execute, open, or follow link targets.

Acceptance criteria:

- ~file:...::*Heading~ resolves to the target file first.
- Matching heading-title search options resolve to ~target_heading_id~.
- Escaped bracket syntax like ~\[2026-07-01 Wed\]~ is handled correctly.
- Missing headings in a resolved target file are marked ~broken~.
- Duplicate matching headings in the target file are marked ~ambiguous~.
- Heading-title lookup does not scan unrelated files.
- File links without heading-title search options keep existing file-resolution behavior.
- File links with unsupported search options keep existing file target resolution and do not set ~target_heading_id~.
- Existing ~search_option~ values remain unchanged.
- Raw link source fields remain unchanged.
- No CUSTOM_ID, ID, attachment, regexp, line-number, dedicated-target, or fuzzy-link resolution is implemented.
- ~make ci~ passes.

** TODO Resolve property-based heading links

:PRIORITY: High
:RISK: High
:DB_SCHEMA_CHANGE: No

:END:

Depends on:

- [[*Implement deterministic link resolution pass after rebuild][Implement deterministic link resolution pass after rebuild]]

Goal:

- Resolve heading links that target Org properties such as ~ID~ and ~CUSTOM_ID~.
- Use one shared property-target lookup mechanism with different search scopes and missing-target semantics.

General property lookup model:

- Each resolver case defines:
  - property key
  - property value
  - search scope
  - status for no match
- Exactly one match resolves to a heading.
- Multiple matches are ambiguous.
- No match is either ~broken~ or ~unresolved~, depending on whether the search scope is known to be complete.

Shared matching rules:

- Match against heading properties:
  - ~properties.key~
  - ~properties.value~
- If exactly one matching heading exists:
  - set ~target_heading_id~
  - set ~resolution_status = resolved~
- If multiple matching headings exist:
  - set ~target_heading_id = NULL~
  - set ~resolution_status = ambiguous~
  - set ~resolution_diagnostic~ explaining that multiple headings match the property target.
  - do not choose an arbitrary target.
- Raw link source fields must remain unchanged.

*** TODO Resolve Org ID links within indexed ID universe

Supported forms:

- ~id:foo~
- bracket or angle links classified by Phase 3 as ~link_type = id~

Rules:

- Property key:
  - ~ID~
- Property value:
  - raw ID target
- Search scope:
  - all indexed files
- No-match status:
  - ~unresolved~

Background:

- Org ID links are global ID links.
- Org normally resolves them through its ID location mechanism.
- The indexed DB may not be the complete Org ID universe.
- Therefore, absence from indexed files does not necessarily mean the link is broken.

Target fields:

- On match, set:
  - ~target_heading_id~
  - ~target_id~
  - ~resolution_status = resolved~
- On no match, set:
  - ~target_heading_id = NULL~
  - ~target_id~ to the raw ID target if useful for diagnostics.
  - ~resolution_status = unresolved~
  - ~resolution_diagnostic~ explaining that the ID was not found in indexed files, but the complete Org ID universe is not known.
- On multiple matches:
  - ~target_heading_id = NULL~
  - ~target_id~ to the raw ID target if useful for diagnostics.
  - ~resolution_status = ambiguous~

Acceptance criteria:

- ~id:foo~ resolves when exactly one indexed heading has ~:ID: foo~.
- Duplicate indexed IDs are marked ~ambiguous~.
- Missing IDs are marked ~unresolved~, not ~broken~.
- Tests document that absence from indexed files is not enough to classify an ID link as broken.
- ID resolution uses or preserves the existing ID property index.
