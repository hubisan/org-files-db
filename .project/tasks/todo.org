* Phase 4: Link resolution

Goal of this phase: Resolve stored raw link source facts to known files, file-scoped CUSTOM_ID targets, and indexed Org ID targets.

General rules:

- Resolution never destroys raw link facts.
- Resolution fields stay clearly separated from raw source fields.
- Broken, ambiguous, unresolved, and unsupported targets are represented explicitly.
- Target deletion must not delete source link rows.
- Resolution must not execute link targets.
- Resolution must be deterministic and repeatable.
- Resolution runs after all files, headings, properties, outline paths, and raw links for the rebuild are stored.
- Do not resolve links on demand in read-only CLI commands.
- Do not introduce parallel ~resolved_file_id~ / ~resolved_heading_id~ columns unless the schema contract is deliberately renamed first.

Existing target-ish fields:

- ~path_absolute~
- ~target_file_id~
- ~target_heading_id~
- ~target_custom_id~
- ~target_id~

Recommended resolution state fields:

- ~resolution_status~
- ~resolution_diagnostic~

Recommended ~resolution_status~ values:

- ~unresolved~
- ~resolved~
- ~broken~
- ~ambiguous~
- ~unsupported~

Status semantics:

- is ~NULL~ means not attempted
- ~unresolved~ means resolution was attempted but the available universe is not known to be complete.
- ~broken~ means the target is missing inside a known complete context.
- ~ambiguous~ means more than one valid target exists in the applicable context.
- ~unsupported~ means the link form is intentionally not resolved yet.
- ~resolved~ means target fields point to the selected target.

Important distinction:

- ~CUSTOM_ID~ resolution is file-scoped.
- ~id:~ resolution is global in Org semantics and should not be marked broken merely because the ID is absent from the indexed files.
- A missing ~CUSTOM_ID~ can be broken when the target file context is known.
- A missing ~id:~ should be ~unresolved~ unless a complete Org ID location universe is available.

Depends on:

- [[*\[2026-07-01 Wed\] Implement deterministic link resolution pass after rebuild][Implement deterministic link resolution pass after rebuild]]

Goal:

- Resolve file-like links to known indexed files.
- Populate file target fields in the existing Phase 4 resolver pass.
- Keep search options as raw source facts.
- Do not resolve headings, CUSTOM_IDs, IDs, attachments, or file search options in this task.

Supported source facts:

- Explicit file links:
  - ~[[file:notes/a.org]]~
  - ~<file:notes/a.org>~
  - plain ~file:notes/a.org~ when extracted by the configured plain-link protocols
- Implicit file bracket links classified by Phase 3 as file-like links:
  - ~[[./a.org]]~
  - ~[[../a.org]]~
  - ~[[~/notes/a.org]]~
  - ~[[/absolute/path/a.org]]~

Resolution rules:

- Resolve only links classified as file-like by Phase 3.
- Relative paths are interpreted relative to the source file's parent directory.
- Home-relative paths using ~~~ are expanded consistently with existing config path handling.
- Absolute paths are normalized syntactically in the same style as indexed file paths.
- Store the normalized absolute target path in ~path_absolute~ when path normalization succeeds.
- If the normalized target path matches a known row in ~files.path~, set:
  - ~target_file_id~
  - ~resolution_status = resolved~
  - ~resolution_diagnostic = NULL~
- If the normalized target path does not match an indexed file but is inside the configured indexed/discovery universe and is known to be absent, set:
  - ~target_file_id = NULL~
  - ~resolution_status = broken~
  - ~resolution_diagnostic~ explaining that the target file is missing from the indexed universe.
- If the normalized target path is outside the configured indexed/discovery universe, set:
  - ~target_file_id = NULL~
  - ~resolution_status = unresolved~
  - ~resolution_diagnostic~ explaining that the file target is outside the indexed universe.
- If the path cannot be normalized safely, set:
  - ~target_file_id = NULL~
  - ~path_absolute = NULL~
  - ~resolution_status = unsupported~
  - ~resolution_diagnostic~ explaining that the path form is unsupported.
- Preserve ~search_option~ as a raw source fact.
- Do not use ~search_option~ to resolve headings in this task.

Indexed/discovery universe rules:

- The indexed universe consists of configured file roots and directory roots after applying the current discovery settings.
- A target path is inside the indexed universe if it is under a configured recursive directory root, exactly equal to a configured non-recursive file root, or exactly equal to a discovered file in a configured non-recursive directory root.
- A target path outside this universe must not be marked ~broken~ merely because it has no matching ~files~ row.
- Do not scan arbitrary directories from link targets to decide whether external files exist.
- Do not add non-indexed files to the DB.

Resolver integration rules:

- Integrate this into the existing ~LinkResolver::resolve_all~ framework.
- Continue resetting resolver-owned fields before resolving.
- Visit links in deterministic order.
- File-like resolver logic should run before the generic unsupported fallback.
- Non-file-like links continue to be marked ~unsupported~ by the fallback.
- Do not modify raw source-fact fields:
  - ~raw~
  - ~raw_target~
  - ~raw_description~
  - ~link_type~
  - ~path~
  - ~search_option~
  - ~byte_start~
  - ~byte_end~
  - ~line~
  - ~source_context~

Out of scope:

- Do not resolve ~search_option~ to headings.
- Do not resolve ~file:...::#CUSTOM_ID~ in this task.
- Do not resolve ~file:...::*Heading~ in this task.
- Do not resolve ~id:~ links.
- Do not resolve ~CUSTOM_ID~ links.
- Do not resolve ~attachment:~ links.
- Do not add non-indexed files to the DB.
- Do not perform filesystem discovery from link targets.
- Do not execute, open, or follow link targets.

Acceptance criteria:

- Relative ~file:~ links resolve relative to the source file.
- Absolute ~file:~ links resolve to known indexed files.
- Home-relative ~file:~/...~ links resolve consistently with config path handling.
- Implicit file bracket links resolve to known indexed files.
- Resolved file links set ~path_absolute~, ~target_file_id~, and ~resolution_status = resolved~.
- File links inside the indexed universe but missing from indexed files are marked ~broken~.
- File links outside the indexed universe are marked ~unresolved~, not ~broken~.
- Unsupported path forms are marked ~unsupported~ without inventing a target.
- Existing ~search_option~ values remain unchanged.
- Non-file-like links continue to use the unsupported fallback.
- Link rows are not deleted when a target file disappears from the indexed set.
- Tests cover a rebuild where the source file remains indexed and the target file is removed.
- Tests cover deterministic ordering-independent resolution across multiple indexed files.
- Tests cover an external file target outside the indexed universe being marked ~unresolved~.
- Tests verify raw link fields are unchanged after file-link resolution.
- No heading, CUSTOM_ID, ID, attachment, or search-option resolution is implemented in this task.
- ~make ci~ passes.

Background:

- Org attachment resolution depends on Org attachment settings and heading context.
- Attachments may be based on heading ~ID~.
- Attachment behavior may also depend on configured attachment directories.

- Do not scan arbitrary attachment directories in this task.

- If the attachment base is known but the target is not an indexed file, mark it as ~broken~.

Resolution rules:

- If the normalized path matches an indexed row in ~files.path~:

- If the attachment base cannot be derived:
  - set ~target_file_id = NULL~
  - set ~resolution_status = unsupported~
  - set ~resolution_diagnostic~ explaining that this attachment form is not supported yet.

Acceptance criteria:

- Supported attachment-base rules are documented before implementation.
- Attachment links with known base and indexed target resolve to ~target_file_id~.
- Attachment links with known base and missing target are marked ~broken~.
- Attachment links without derivable base are marked ~unsupported~.
- Attachment resolution does not scan arbitrary directories.

  - set ~resolution_status = ambiguous~

- Raw link source fields must remain unchanged.
