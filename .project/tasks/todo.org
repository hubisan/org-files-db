Goal: Ensure that normalized property rows created from ~#+PROPERTY~ and ~#+CATEGORY~ are based on keyword lines from the whole Org document, not only on keywords before the first regular heading.

Context: Org keyword lines can appear later in the buffer and still be recognized by Org-mode. The raw keyword parser/indexer stores keyword rows on the synthetic level 0 heading. Property normalization for ~#+PROPERTY~ and ~#+CATEGORY~ must use the same parsed keyword source, but this task must not change TODO keyword semantics.

Important regression context: A previous attempt changed the central keyword collection path too broadly and caused ~todo_keywords~ insertion to fail with a uniqueness error. This task must avoid that regression.

Do not change:

- Do not change normalized ~TODO~, ~SEQ_TODO~, or ~TYP_TODO~ behavior.
- Do not remove existing TODO keyword deduplication or merge logic.
- Do not change the ~todo_keywords~ schema.
- Do not change the uniqueness behavior of ~todo_keywords~.
- Do not modify manual SQLite database files.
- Do not modify task tracking files such as ~.project/tasks/todo.org~, except for moving this task through the workflow if explicitly required by the project process.
- Do not implement a second independent raw-text scanner if a parsed keyword list already exists.
- Do not compute effective or inherited property values in this task.

Problem:

#+begin_src org
  ,#+PROPERTY: var before

  ,* First heading

  ,#+PROPERTY: var after
  ,#+CATEGORY: later-category

  ,* Second heading
#+end_src

Expected parser/indexer behavior:

- Both ~#+PROPERTY~ rows are stored as raw keyword rows.
- The later ~#+CATEGORY~ row is stored as a raw keyword row.
- Both ~#+PROPERTY~ rows also create normalized rows in ~properties~ with ~source = property_keyword~.
- The ~#+CATEGORY~ row also creates a normalized row in ~properties~ with ~source = category_keyword~.
- All normalized rows are attached to the synthetic level 0 heading.
- No normalized row is attached directly to ~First heading~ or ~Second heading~.

Scope:

- Reuse the existing parsed keyword collection used for raw keyword insertion, if available.
- If the existing parser has special whole-buffer keyword logic for ~TODO~, ~SEQ_TODO~, ~TYP_TODO~, ~PROPERTY~, or ~CATEGORY~, preserve it unless a test proves it is wrong.
- Do not replace the central keyword collector with a broad ~syntax().descendants().filter_map(Keyword::cast)~ implementation unless all existing keyword/TODO tests still pass and no duplicate ~todo_keywords~ rows are produced.
- Do not limit ~#+PROPERTY~ or ~#+CATEGORY~ normalization to the preamble before the first regular heading.
- Preserve duplicate raw keyword rows.
- Preserve duplicate normalized property rows.
- Preserve source order through ~line_number~ and/or insertion order.
- Keep keyword rows and property rows separate.
- Store ~#+PROPERTY~ and ~#+CATEGORY~ twice: once as raw ~keywords~ rows and once as normalized ~properties~ rows.
- Attach normalized ~property_keyword~ and ~category_keyword~ rows only to the synthetic level 0 heading.
- Do not attach normalized keyword-derived property rows to surrounding regular headings.

Normalization rules:

- ~#+PROPERTY: key value~ creates a row in ~properties~ with key ~KEY~, value ~value~, source ~property_keyword~, append = 0, and heading_id = synthetic level 0 heading.
- ~#+PROPERTY: key+ value~ creates a row in ~properties~ with key ~KEY~, value ~value~, source ~property_keyword~, append = 1, and heading_id = synthetic level 0 heading.
- ~#+CATEGORY: value~ creates a row in ~properties~ with key ~CATEGORY~, value ~value~, source ~category_keyword~, append = 0, and heading_id = synthetic level 0 heading.
- The trailing ~+~ append marker is not part of the stored key.
- Property keys are normalized consistently with the existing property implementation.

** BUILD Refine heading body extraction to exclude structured metadata

Goal:
Refine optional heading body extraction so ~heading_bodies.body_text~ contains free Org content only, not structured metadata that is already stored in dedicated tables.

Context:
A previous body-text implementation exists and the current version has been committed. This task should be a focused follow-up that adjusts body extraction semantics without mixing in unrelated parser/indexer changes.

The project uses this architecture:

- Orgize is the syntax authority.
- Parser adapter translates Orgize syntax nodes into the internal model.
- Indexer/DB writer stores direct facts and derived/cache data.
- Structured metadata belongs in dedicated tables.
- ~heading_bodies~ is for optional free body content that may later be indexed through FTS.

Existing config behavior must remain:

#+begin_src toml
  [search]
  fts5_enabled = false
  index_body_text = false
#+end_src

~heading_bodies~ rows are written only when ~search.index_body_text = true~. Body text is inserted into FTS only when both ~search.fts5_enabled = true~ and ~search.index_body_text = true~.

Design decision:
~heading_bodies.body_text~ should contain normal content from a heading's own section, not structured metadata.

Use Orgize as the boundary authority:

- If Orgize exposes a line/block as structured metadata, exclude it from ~body_text~.
- If Orgize exposes a metadata-looking line as normal section text, keep it in ~body_text~.

Body extraction rules:
- Exclude the heading line itself.
- Exclude child heading subtrees.
- Exclude Orgize ~PLANNING~ nodes.
- Exclude Orgize ~PROPERTY_DRAWER~ nodes.
- Exclude Orgize ~KEYWORD~ nodes from level 0 body text.
- Include normal section content such as paragraphs, lists, source blocks, example blocks, and normal text.
- Include planning/property/keyword-looking text if Orgize exposes it as normal paragraph/section text rather than a structured node.
- File-level free text before the first regular heading belongs to the synthetic level 0 heading.
- File-level structured metadata before the first regular heading, such as property drawers and keywords, does not belong to level 0 ~body_text~.

Examples:

#+begin_src org
  ,#+TITLE: Example
  ,#+PROPERTY: owner Alice

  ,* Task
  SCHEDULED: <2026-06-23 Tue>
  :PROPERTIES:
  :Owner: Bob
  :END:
  Real body text.

  ,** Child
  Child body.
#+end_src

Expected:
- Level 0 body does not include ~#+TITLE~ or ~#+PROPERTY~.
- ~Task~ body does not include the heading line.
- ~Task~ body does not include the ~SCHEDULED~ planning line if Orgize exposes it as ~PLANNING~.
- ~Task~ body does not include the property drawer.
- ~Task~ body includes ~Real body text.~.
- ~Task~ body does not include ~Child body.~.
- ~Child~ body includes ~Child body.~.

Metadata-looking body example:

#+begin_src org
  ,* Not valid planning
  SCHEDULED: <%%(diary-float t 42)>

  ,* Multiple planning-like lines
  SCHEDULED: <2024-11-20 Wed>
  DEADLINE: <2024-12-01 Sun>
  CLOSED: [2024-11-21 Thu]
#+end_src

Expected:
- If Orgize exposes a line as ~PLANNING~, exclude it from ~body_text~.
- If Orgize exposes later planning-looking lines as normal paragraph text, keep them in ~body_text~.
- Do not implement independent planning recognition to remove text that Orgize treated as normal body.

Property example:

#+begin_src org
  ,:PROPERTIES:
  ,:CATEGORY: Level 0 Category Property
  ,:WHATEVER: level 0 drawer property
  ,:END:
  ,#+TITLE: Org Property and Keyword Test
  ,#+PROPERTY: keyword_property valid

  ,* Task with drawer
  ,:PROPERTIES:
  ,:ID: abc
  ,:Owner: Alice
  ,:END:
  Body text for the task.
#+end_src

Expected:
- Level 0 body does not include the level 0 property drawer.
- Level 0 body does not include recognized keyword nodes.
- ~Task with drawer~ body does not include the property drawer.
- ~Task with drawer~ body includes only ~Body text for the task.~.

Scope:
- Inspect the current committed body extraction implementation.
- Adjust parser/indexer body extraction to follow the rules above.
- Preserve existing ~search.index_body_text~ gating.
- Preserve existing FTS gating.
- Preserve existing heading/title/tag/property/keyword/planning extraction.
- Update fixtures and tests for body extraction around planning lines, property drawers, keywords, child subtrees, and level 0 text.
- Keep the change narrow.

Out of scope:
- Do not reimplement planning parsing.
- Do not reimplement property parsing.
- Do not reimplement keyword parsing.
- Do not change ~heading_bodies~ schema unless the current schema is broken.
- Do not implement query/search commands.
- Do not add body text when ~search.index_body_text = false~.
- Do not insert body text into FTS unless both required search flags are enabled.
- Do not treat metadata-looking paragraph text as metadata unless Orgize exposes it structurally.

Acceptance criteria:
- Body extraction uses Orgize structure as the authority.
- ~PLANNING~ nodes are excluded from ~body_text~.
- ~PROPERTY_DRAWER~ nodes are excluded from ~body_text~.
- Recognized level 0 ~KEYWORD~ nodes are excluded from level 0 ~body_text~.
- Normal section text remains in ~body_text~.
- Metadata-looking paragraph text remains in ~body_text~ if Orgize does not expose it structurally.
- Child heading subtrees are excluded from parent ~body_text~.
- File-level free text before the first regular heading is assigned to level 0.
- File-level structured property drawers and keywords are excluded from level 0 body.
- Existing config-disabled behavior still works.
- Existing FTS gating still works.
- Existing parser/indexer tests still pass.
- Focused tests cover:
  - planning line excluded,

  - property drawer excluded,
  - level 0 property drawer and keywords excluded,
  - child subtree excluded.
