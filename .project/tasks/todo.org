** DONE [2026-06-23 Tue 20:17] Fix PROPERTY and CATEGORY normalization to use whole-file keyword scan

[[./archive/2026-06-23--fix-property-and-category-normalization-to-use-whole-file-keyword-scan.org]]

Goal: Ensure that normalized property rows created from ~#+PROPERTY~ and ~#+CATEGORY~ are based on keyword lines from the whole Org document, not only on keywords before the first regular heading.

Context: Org keyword lines can appear later in the buffer and still be recognized by Org-mode. The raw keyword parser/indexer stores keyword rows on the synthetic level 0 heading. Property normalization for ~#+PROPERTY~ and ~#+CATEGORY~ must use the same parsed keyword source, but this task must not change TODO keyword semantics.

Important regression context: A previous attempt changed the central keyword collection path too broadly and caused ~todo_keywords~ insertion to fail with a uniqueness error. This task must avoid that regression.

Do not change:

- Do not change normalized ~TODO~, ~SEQ_TODO~, or ~TYP_TODO~ behavior.
- Do not remove existing TODO keyword deduplication or merge logic.
- Do not change the ~todo_keywords~ schema.
- Do not change the uniqueness behavior of ~todo_keywords~.
- Do not modify manual SQLite database files.
- Do not modify task tracking files such as ~.project/tasks/todo.org~, except for moving this task through the workflow if explicitly required by the project process.
- Do not implement a second independent raw-text scanner if a parsed keyword list already exists.
- Do not compute effective or inherited property values in this task.

Problem:

#+begin_src org
  ,#+PROPERTY: var before

  ,* First heading

  ,#+PROPERTY: var after
  ,#+CATEGORY: later-category

  ,* Second heading
#+end_src

Expected parser/indexer behavior:

- Both ~#+PROPERTY~ rows are stored as raw keyword rows.
- The later ~#+CATEGORY~ row is stored as a raw keyword row.
- Both ~#+PROPERTY~ rows also create normalized rows in ~properties~ with ~source = property_keyword~.
- The ~#+CATEGORY~ row also creates a normalized row in ~properties~ with ~source = category_keyword~.
- All normalized rows are attached to the synthetic level 0 heading.
- No normalized row is attached directly to ~First heading~ or ~Second heading~.

Scope:

- Reuse the existing parsed keyword collection used for raw keyword insertion, if available.
- If the existing parser has special whole-buffer keyword logic for ~TODO~, ~SEQ_TODO~, ~TYP_TODO~, ~PROPERTY~, or ~CATEGORY~, preserve it unless a test proves it is wrong.
- Do not replace the central keyword collector with a broad ~syntax().descendants().filter_map(Keyword::cast)~ implementation unless all existing keyword/TODO tests still pass and no duplicate ~todo_keywords~ rows are produced.
- Do not limit ~#+PROPERTY~ or ~#+CATEGORY~ normalization to the preamble before the first regular heading.
- Preserve duplicate raw keyword rows.
- Preserve duplicate normalized property rows.
- Preserve source order through ~line_number~ and/or insertion order.
- Keep keyword rows and property rows separate.
- Store ~#+PROPERTY~ and ~#+CATEGORY~ twice: once as raw ~keywords~ rows and once as normalized ~properties~ rows.
- Attach normalized ~property_keyword~ and ~category_keyword~ rows only to the synthetic level 0 heading.
- Do not attach normalized keyword-derived property rows to surrounding regular headings.

Normalization rules:

- ~#+PROPERTY: key value~ creates a row in ~properties~ with key ~KEY~, value ~value~, source ~property_keyword~, append = 0, and heading_id = synthetic level 0 heading.
- ~#+PROPERTY: key+ value~ creates a row in ~properties~ with key ~KEY~, value ~value~, source ~property_keyword~, append = 1, and heading_id = synthetic level 0 heading.
- ~#+CATEGORY: value~ creates a row in ~properties~ with key ~CATEGORY~, value ~value~, source ~category_keyword~, append = 0, and heading_id = synthetic level 0 heading.
- The trailing ~+~ append marker is not part of the stored key.
- Property keys are normalized consistently with the existing property implementation.
