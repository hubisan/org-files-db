[[https://www.gnu.org/licenses/gpl-3.0][https://img.shields.io/badge/License-GPL%20v3-blue.svg]] [[https://github.com/hubisan/org-files-db][GitHub repository]]

~org-files-db~ indexes Org files in SQLite. The ~orgfdb~ command can rebuild the index, keep it current, and query stored Org data.

The index stores headings, file metadata, tags, properties, keywords, timestamps, and Org links. Structural queries read this indexed data without reparsing source files.

The project supports Linux and other Unix-like systems, including macOS. Windows is not supported. See [[*Current status and known limitations][Current status and known limitations]].

* Quick start

Download this repo and run the following in the root to install ~orgfdb~:

#+begin_src shell
make install
#+end_src

Create a ~org-files-db.toml~:

#+begin_src toml
db_path = "org-files-db.sqlite"

[[dirs]]
path = "notes"
recursive = true
#+end_src

Build the index:

#+begin_src shell
orgfdb rebuild --config ./org-files-db.toml
#+end_src

Run a structural query:

#+begin_src shell
orgfdb query \
  --config ./org-files-db.toml \
  '(headings (not (done)))'
#+end_src

Query output is JSON by default.

The explicit JSON form is:

#+begin_src shell
orgfdb query \
  --config ./org-files-db.toml \
  --format json \
  '(headings)'
#+end_src

Use ~watch~ after the initial rebuild to update the database upon changes:

#+begin_src shell
orgfdb watch --config ./org-files-db.toml
#+end_src

The watcher runs in the foreground. Press ~Ctrl-C~ to stop it.

* Common commands

- ~orgfdb rebuild~ creates or refreshes the complete configured index.
- ~orgfdb watch~ monitors configured inputs and applies incremental updates.
- ~orgfdb query~ runs structural queries against the existing database.
- ~orgfdb search~ runs SQLite FTS5 search against the trusted search index.
- ~orgfdb headings~ prints stored heading rows for inspection.
- ~orgfdb links~ prints stored link rows for inspection.
- ~orgfdb status~ prints the database identity, generation, and canonical database path.
- ~orgfdb changes~ reports affected files after a committed generation.

Read [[./docs/cli.org][docs/cli.org]] for command syntax and options.

* Query examples

Open TODO items:

#+begin_src shell
orgfdb query --config ./org-files-db.toml '(headings (not (done)))'
#+end_src

Resolved links:

#+begin_src shell
orgfdb query --config ./org-files-db.toml '(links (status "resolved"))'
#+end_src

Files with a project tag:

#+begin_src shell
orgfdb query --config ./org-files-db.toml '(files (tags "project"))'
#+end_src

Include structured path data:

#+begin_src shell
orgfdb query \
  --config ./org-files-db.toml \
  --include path \
  '(headings (todo "NEXT"))'
#+end_src

Read [[./docs/reference/query-language.org][Structural Query Language]] for the complete query syntax.

* Full-text search

~orgfdb search~ takes a raw SQLite FTS5 ~MATCH~ expression. It is separate from the structural query language.

#+begin_src shell
orgfdb search --config ./org-files-db.toml 'sqlite AND database'
orgfdb search --config ./org-files-db.toml --title 'sql*'
#+end_src

~--title~ and ~--body~ restrict the search to one indexed column. Output is JSON.

Search is optional and needs SQLite FTS5 support. The ~[search]~ section of the configuration controls it:

- ~fts5_enabled~ (default ~true~) builds the FTS index during ~rebuild~ and ~watch~.
- ~index_body_text~ (default ~false~) also stores and indexes heading body text. ~--body~ needs it.

If ~fts5_enabled~ is ~false~, indexing does not create the FTS index and ~orgfdb search~ is rejected. Run ~orgfdb rebuild~ after changing these keys. All other commands work without FTS5.

Read [[./docs/cli.org][docs/cli.org]] and [[./docs/config.org][docs/config.org]] for the full search requirements.

* Current status and known limitations

- Windows is not supported. Linux and other Unix-like systems, including macOS, are supported.
- ~attachment:~ links are indexed but not resolved. Their ~resolution_status~ is ~unsupported~.
- The parser is project code: its own line scanner builds the document structure and its own inline scanner reads timestamps, inline code and title markup (the Orgize dependency is gone, #41). It follows Emacs Org 9.6 for the facts it stores and does not read citations, inline babel calls or line breaks. Read [[./docs/design/parser-risks.org][Parser Risks]].
- Link resolution covers a limited set of link forms. Other file search forms are not resolved. Read [[./docs/cli.org][docs/cli.org]].
- After an upgrade, the next indexing run reparses all files when the parser or indexer contract changed. No manual step is needed.
- Read-only commands reject a database with an outdated schema version. Run an indexing command first.

* Configuration

A configuration file selects the SQLite database and the Org source set. It also controls link parsing, TODO defaults, search indexing, and query timezone handling.

Relative paths in a configuration file use the configuration file directory as their base.

Read [[./docs/config.org][docs/config.org]] for all supported keys and defaults.

* JSON compatibility

~headings~, ~links~, ~status~, ~changes~, ~query~, and ~search~ use JSON output. Use ~--format json~ when a client depends on the machine-readable contract.

The existing ~orgfdb query --format json~ contract is stable. The query-specific ~presentation-json~ format provides opt-in prepared rows and does not replace this contract.

Read [[./docs/reference/query-json.org][Query JSON Contract]] for normal query JSON. Read [[./docs/reference/presentation.org][Presentation Output Reference]] for the opt-in presentation interface.
