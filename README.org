* Org-files-db                                                   :noexport_2:

[[https://www.gnu.org/licenses/gpl-3.0][https://img.shields.io/badge/License-GPL%20v3-blue.svg]]

=Org-files-db= stores data from Org-mode files — headings, tags, properties, links, timestamps (scheduled, deadline, closed), and keywords — in a SQLite database.

The package parses the files asynchronously (non-blocking) and automatically detects changes to keep the database up to date. You can track individual files or directories (recursively).

*** Notes on File Change Detection

File modification times (*mtime*) are used to efficiently detect changed Org files. Only when the recorded *mtime* differs from the stored value, the file's MD5 hash is recalculated.

Since Git may alter file modification times when switching branches or performing checkouts, this can temporarily cause a large number of files to be rechecked. In such cases, many MD5 hashes need to be computed, which can take noticeable time depending on the number and size of files.

** Files Structure

The package is split into the following files:

- ~org-files-db.el~ — Entry point and main API; loads and coordinates all submodules.  
- ~org-files-db-core.el~ — Core utilities, shared functions, and customization.  
- ~org-files-db-watch.el~ — Watches for added, changed, or deleted Org files.  
- ~org-files-db-async.el~ — Runs time-consuming operations (such as scans or database updates) asynchronously in separate Emacs processes.  
- ~org-files-db-indexer.el~ — Handles changes: calls the parser and updates the database accordingly.  
- ~org-files-db-parse.el~ — Parses Org files (titles, tags, TODOs, timestamps, etc.) using org-element.  
- ~org-files-db-database.el~ — Manages persistent storage of metadata in SQLite.  

** Path Components Terminology

To avoid confusion between Emacs and general file-system terminology, this
project uses the following conventions for file-related terms:

- =filename=  
  The full path of a file, absolute or relative.  
  In Emacs Lisp, "filename" typically refers to the *entire path*, not just the
  name part. Examples: =~/org/notes.org=, =./todo.org=, =~/org/persons/=, =~/org/notes=.
- =directory=  
  Path of a directory. It may, but does not have to, end with a "/". Examples: =~/org/=, =/home/user/notes/=, =~/org=.
- =basename=  
  The filename without its directory part. Examples: =notes.org=, =index.org=.
- =extension=  
  The file extension, without the leading dot. Examples: =org=, =txt=.  
- =path=  
  The full path for either a file or a directory path, absolute or relative. Examples: =~/org/notes.org=, =/var/tmp/=, =/home/user/org/notes.org=, =../org=.
- =absolute path=  
  The absolute path of a file or directory. The home directory may be abbreviated as "~". Examples: =/home/user/org/notes.org=, =~/org/notes.org=
- =relative path=  
  A path of a file or directory relative to a base directory. Examples: =../archive/todo.org=, =./notes.org=, =../../archive=
- =truename=  
  The canonical absolute path of a file or directory, with all symbolic links
  resolved. Examples: =/home/user/org/notes.org= and =/mnt/data/shared.org=.
